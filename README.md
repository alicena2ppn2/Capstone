# 생활 리듬 기반 사회적 고립 조기 개입 AI 에이전트

> **측정은 조용하게, 변화는 정확하게, 개입은 부드럽게.**

사용자가 스스로 인지하기 어려운 **활동량·생활 리듬·수면·이동성의 변화**를 지속적으로 감지하고, 위험 등급을 직접 통보하는 대신 **작은 외출과 활동을 제안하는 예방형 AI 에이전트**를 만드는 프로젝트입니다.

이 프로젝트의 목표는 특정 사람을 "고위험군"으로 진단하는 것이 아니라, 사회적 고립이 장기화되기 전에 **생활 패턴의 변화를 먼저 발견하고 조기 개입의 기회를 만드는 것**입니다.

## 1. 문제 정의

사회적 고립이나 은둔이 심해지는 과정에서 사람은 자신의 생활 변화 자체를 명확하게 인지하지 못할 수 있습니다.

예를 들어 다음과 같은 변화가 서서히 이어질 수 있습니다.

- 평소보다 걸음수가 지속적으로 감소
- 외출과 이동 범위가 감소
- 하루 생활 리듬의 규칙성(IS)이 낮아짐
- 수면·기상 시간이 불규칙해짐
- 집에 머무는 시간이 길어짐
- 장기간 생활 패턴이 비슷한 수준에서 저활동 상태로 유지됨

따라서 단순히 "오늘 몇 보 걸었는가"를 보는 것이 아니라,

> **얼마나 움직였는가 + 언제 움직였는가 + 얼마나 규칙적으로 생활하는가 + 생활 반경이 어떻게 변했는가**

를 함께 보는 것이 핵심입니다.

## 2. 프로젝트 핵심 질문

기존의 위험 탐지 시스템이

> **측정 → 분류 → 경고**

에 가까웠다면, 이 프로젝트는 다음 질문에 집중합니다.

> **"위험으로 이어질 수 있는 생활 변화가 생겼을 때, 그 사람보다 먼저 알아차리고 무엇을 해줄 수 있는가?"**

따라서 최종 구조는 다음과 같습니다.

```text
측정
  ↓
생활 패턴 분석
  ↓
개인 baseline 대비 변화 감지
  ↓
절대적 저활동 + 지속성 확인
  ↓
AI 에이전트 대화
  ↓
작은 행동 제안
  ↓
필요 시 지역사회 지원 정보 연결
```

## 3. 선행연구 — 왜 생활 리듬을 보는가?

### 3.1 UK Biobank / Lyall 2018 — "얼마나 움직였나"와 "언제 움직였나"는 다르다

손목 가속도계를 이용해 7일간 분 단위 활동을 측정하고, 가장 활동적인 연속 10시간(M10)과 가장 조용한 연속 5시간(L5)을 이용해 **Relative Amplitude (RA)**를 계산했습니다.

```text
RA = (M10 - L5) / (M10 + L5)
```

RA가 높을수록 낮과 밤의 활동 대비가 크고, 낮과 밤이 뚜렷하게 구분됩니다.

이 연구의 핵심은 **전체 활동량을 보정한 뒤에도 RA가 유의하게 남았다는 점**입니다. 오즈비는 보정 전 1.16에서 보정 후 1.06으로 줄었지만 유의성은 유지됐습니다. 즉 단순한 총 활동량과 별개로 **활동의 시간적 리듬 자체가 추가 정보를 가질 수 있음**을 보여줍니다.

또한 기분장애가 있는 약 1만 6천 명을 제외하고 다시 분석했을 때 외로움과의 연관은 오히려 강해졌습니다(1.09 → 1.11). 임상적 우울이 없는 일반인에게도 리듬–외로움 관계가 남는다는 뜻입니다.

> 핵심 통찰: **"얼마나 움직였나"와 "언제 움직였나"는 다른 정보다.**

따라서 우리 서비스도 걸음수 총량만 보지 않고 생활 리듬 지표를 별도로 계산합니다.

## 4. 선행연구 — 왜 IS를 핵심 지표로 보는가?

### 4.1 대만 Rhythm 앱 연구 (2025)

이 연구에서는 다음 세 지표를 서로 다른 축으로 사용합니다.

| 지표 | 무엇을 보는가 | 핵심 질문 |
|---|---|---|
| **RA** | 낮·밤 활동량의 대비 | 낮과 밤이 구분되는가? |
| **IS** | 날짜 사이의 24시간 패턴 유사도 | 매일 비슷한 시간에 비슷한 생활을 하는가? |
| **IV** | 하루 안의 활동·휴식 파편화 | 활동과 휴식이 토막나 있는가? |

특히 이 연구에서는 IS가 세 유형에서 **0.47 / 0.36 / 0.27**로 구분되었고, 가장 낮은 IS의 불규칙형에서 우울 점수가 가장 높았습니다. 반면 IV는 통계적으로 유의하지 않았습니다(p=0.073).

따라서 우리 설계에서는:

> **IS = 핵심 리듬 지표**  
> **RA = 보조 지표**

로 사용합니다.

스마트폰 사용량을 이용하는 환경에서는 수면 중 스마트폰 사용량이 거의 0이 되어 RA가 1에 가까워지는 문제가 있을 수 있기 때문에, 스마트폰 기반 서비스에서는 IS가 더 실용적인 핵심 지표가 될 수 있습니다. 걸음수는 폰 사용량보다 액티그래피에 가깝지만, 밤에 폰을 책상에 두면 같은 문제가 부분적으로 생길 수 있습니다.

같은 연구의 비동기 지표(신체활동 정점과 폰 사용 정점의 시각 차이, 불규칙형에서 2.82시간으로 가장 큼)는 iOS에서 스크린타임을 읽을 수 없어 이번 서비스에서는 사용하지 않습니다.

## 5. 연구를 서비스로 가져올 때의 원칙

선행연구는 생활 리듬과 외로움·우울 관련 지표 사이의 연관성을 보여주지만, 단면 연구만으로 인과관계를 확정할 수는 없습니다.

따라서 우리 서비스는 다음을 하지 않습니다.

```text
생활 데이터
    ↓
질환 진단
```

대신 다음에 집중합니다.

```text
생활 데이터
    ↓
생활 패턴 변화 탐지
    ↓
생활 속 행동 개입
```

즉,

> **"리듬이 흐트러졌으니 우울하다"**

가 아니라,

> **"최근 생활 리듬이 평소와 달라졌으니 한 번 확인하고 작은 행동을 제안한다."**

는 방향입니다.

## 6. 왜 위험 점수를 사용자에게 직접 보여주지 않는가?

앱 내부에서는 여러 지표를 계산할 수 있지만, 사용자 화면에 다음과 같은 결과를 직접 보여주지는 않습니다.

```text
IS = 0.27
위험도 = 82
은둔 위험군
```

이유는 두 가지입니다.

### 6.1 숫자와 라벨이 불필요한 낙인을 만들 수 있음

리듬 지표 자체는 생활 패턴의 특성을 보여주는 것이지, 특정 질환이나 고독사 여부를 진단하는 값이 아닙니다. 점수화는 리듬을 회복하는 대신 숫자를 올리는 데 집착하게 만들 수도 있습니다.

### 6.2 "몰래 판단"하는 구조도 피해야 함

사용자가 아무 설명도 듣지 못한 채 갑자기 산책 알림이나 상담 안내를 받으면,

> "앱이 나를 몰래 진단하고 있었네."

라는 신뢰 문제를 만들 수 있습니다.

따라서 원점수와 위험 라벨은 내부 판단에만 사용하고, **측정 사실과 대응의 존재는 투명하게 고지**합니다.

### 설계 원칙

> **원점수와 라벨은 감추고, 대응의 존재는 감추지 않는다.**

온보딩에서는 다음 정도를 안내합니다.

> "생활 패턴 변화를 감지해서 필요한 경우 생활 속 제안을 드립니다."

## 7. 서비스의 핵심 가치

이 서비스는 사용자를 "고위험군"으로 분류하는 앱이 아닙니다.

핵심은:

> **사용자가 스스로도 알아채지 못한 생활의 작은 변화를 먼저 발견하고, 장기적인 고립으로 이어지기 전에 작은 행동을 제안하는 것**

입니다.

따라서 에이전트는 **판정자**가 아니라 **조기 개입을 시작하는 생활 동반자**에 가깝습니다.

## 8. 측정 데이터

### 8.1 기본 데이터

- 일별 걸음수
- 활동 시간
- 수면 시간
- 수면 효율
- WASO (Wake After Sleep Onset)
- 기상 시각
- 활동 리듬

### 8.2 리듬 지표

#### RA (Relative Amplitude)

```text
RA = (M10 - L5) / (M10 + L5)
```

낮·밤의 활동 대비를 측정합니다.

- M10: 하루 중 가장 활동적인 연속 10시간의 평균 활동량
- L5: 하루 중 가장 조용한 연속 5시간의 평균 활동량

#### IS (Interdaily Stability)

여러 날의 24시간 활동 패턴이 얼마나 일정한지 측정합니다.

```text
IS = (n · Σ_h (x̄_h − x̄)²) / (p · Σ_i (x_i − x̄)²)

n   : 전체 관측 개수 (시간 단위)
p   : 하루당 관측 개수 (24)
x̄_h : 시각 h의 여러 날 평균 활동량
x̄   : 전체 평균 활동량
x_i : 각 시점의 활동량
```

- 1에 가까울수록 매일 비슷한 패턴
- 낮을수록 생활 시간이 들쭉날쭉

#### IV (Intradaily Variability)

하루 안에서 활동과 휴식이 얼마나 자주 끊기고 반복되는지 측정합니다.

이번 서비스에서는 선행연구 결과와 구현 현실성을 고려해 **IS를 핵심으로 사용하고 IV는 보조적 분석 지표로 유지**합니다.

## 9. 활동량 탐지 전략 — E안(복합 조건)

단일 지표만 사용하면 오탐이 많을 수 있기 때문에, **활동량 감소 + 생활 패턴 악화**가 동시에 나타날 때 개입하는 구조를 채택합니다.

검토했던 후보는 다음과 같습니다.

| 후보 | 방식 | 필요 데이터 | 반응 속도 | 오탐 위험 | 논문 근거 |
|---|---|---|---|---|---|
| A | baseline 대비 주간 감소율 | 3–4주 | 중간 | 중간 | 약함 |
| B | 연속 저활동일 카운트 | 즉시 | 빠름 | 높음 | 없음 |
| C | IS 기반 규칙성 감소 | 7일 | 중간 | 낮음 | 강함 |
| D | 단기/장기 이동평균 교차 | 28일 | 느림 | 낮음 | 없음 |
| **E** | **복합 조건 (채택)** | 3–4주 | 중간 | 매우 낮음 | 중간 |

### 조건 1. 활동량 감소

앱 사용 초반 **3~4주를 개인 baseline**으로 설정합니다.

```text
감소율 = (baseline_steps - this_week_avg_steps) / baseline_steps
```

초기 트리거 기준:

```text
감소율 ≥ 30%
```

그리고 이 상태가 **2주 연속** 유지되는지를 확인합니다.

### 조건 2. 생활 패턴 악화

다음 중 하나:

```text
IS가 개인 baseline 대비 0.08 이상 하락
OR
개인 평균의 50% 미만인 저활동일이 4일 이상
```

### 최종 핵심 트리거

```text
[활동량]
baseline 대비 주간 걸음수 30% 이상 감소

             AND

[패턴]
IS 0.08 이상 하락
         OR
저활동일 4일 이상

             ↓

        행동 제안
```

> **30%, 0.08, 4일은 현재 단계의 프로토타입 임계값이다.**
>
> 선행연구에서 고독사 위험을 직접 예측하도록 검증된 컷오프가 아니며, 실제 데이터 확보 후 검증·조정해야 합니다.

E안의 "활동량 AND 패턴" 조건은 12장에서 **상위 개입 단계로 올라가기 위한 동시 조건(게이트)**으로 그대로 사용됩니다.

## 10. 변화만 보는 것이 아니라 "원래부터 낮은 사람"도 잡는다

개인 baseline만 사용하면 한 가지 문제가 생깁니다.

예:

```text
A: 평소 7,000보 → 최근 3,500보
B: 평소 2,000보 → 최근 1,900보
```

A는 큰 폭의 감소가 있지만 B는 변화가 거의 없습니다.

그러나 B가 원래부터 매우 낮은 활동 상태에 장기간 머물고 있는 사람이라면, 변화가 없다는 이유로 계속 정상으로 보면 놓칠 수 있습니다.

따라서 다음 두 축을 동시에 봅니다.

### 10.1 개인 변화

> 평소의 나에 비해 얼마나 달라졌는가?

### 10.2 절대적 저활동

> 변화가 없어도 현재 활동 수준이 매우 낮고, 그 상태가 장기간 지속되는가?

이를 2×2로 보면:

| 현재 활동 수준 | baseline 변화 적음 | baseline 대비 급락 |
|---|---|---|
| **정상 수준** | 낮은 개입 필요 | 변화 감시 |
| **낮은 수준** | **지속적 저활동 감시** | **복합 변화 감지** |

따라서 프로젝트는 **"최근 급락형"과 "원래부터 저활동형"을 모두 테스트**합니다. 절대 저활동을 판단하는 구체적인 규칙은 12.4에 있습니다.

## 11. 내부 위험 점수 — 프로토타입 v0.2

코드 구현을 위한 Rule-based 구조는 다음처럼 설계합니다.

```text
Risk Score
= Activity
+ Rhythm
+ Sleep
+ Mobility
+ Missingness
```

총 100점입니다.

| 영역 | 점수 | 주요 입력 |
|---|---:|---|
| Activity | 0~25 | baseline 대비 걸음수 감소율 |
| Rhythm | 0~25 | baseline 대비 IS 하락폭 |
| Sleep | 0~20 | 수면 시점 이동·기상시각 변동·WASO 변화 |
| Mobility | 0~20 | 이동반경·장소 다양성 변화 (GPS 허용 시) |
| Missingness | 0~10 | 데이터 미수집 지속성 |

### Activity (0~25)

| baseline 대비 감소율 | 점수 |
|---|---:|
| <10% | 0 |
| 10~20% | 5 |
| 20~30% | 15 |
| ≥30% | 25 |

### Rhythm (0~25)

| baseline 대비 IS 하락폭 | 점수 |
|---|---:|
| <0.02 | 0 |
| 0.02~0.05 | 5 |
| 0.05~0.08 | 15 |
| ≥0.08 | 25 |

### Sleep (0~20) — 초안

수면 중간점(잠든 시각과 깬 시각의 가운데)이 baseline 대비 얼마나 늦어졌는지를 1차 기준으로 사용합니다. 밤낮이 바뀌는 현상을 가장 직접적으로 잡을 수 있기 때문입니다.

| 수면 중간점 이동 (baseline 대비) | 점수 |
|---|---:|
| <0.5시간 | 0 |
| 0.5~1.5시간 | 5 |
| 1.5~3시간 | 12 |
| ≥3시간 (밤낮 역전) | 20 |

> 기상 시각 변동폭, WASO 증가는 합성 데이터 분포를 확인한 뒤 보조 조건으로 추가합니다.

### Mobility (0~20)

이동반경(Radius of Gyration), Location Entropy, 집 체류 비율의 baseline 대비 변화로 계산합니다. 세부 구간은 실제 데이터 분포를 확인한 뒤 확정합니다.

GPS를 허용하지 않은 사용자는 Mobility를 제외한 **80점 만점으로 계산한 뒤 100점 기준으로 환산**합니다.

```text
GPS 미허용 점수 = (Activity + Rhythm + Sleep + Missingness) × 100 / 80
```

### Missingness (0~10)

| 연속 미수집 | 점수 |
|---|---:|
| <3일 | 0 |
| 3일 | 3 |
| 5일 | 5 |
| ≥7일 | 10 |

### 내부 개입 수준

```text
0–29   : 관찰
30–49  : 주의
50–69  : 적극적 넛지
70–100 : 지원 연결 고려
```

이 단계는 사용자에게 직접 노출되는 위험 등급이 아니라 **에이전트의 개입 강도를 결정하는 내부 상태**입니다.

## 12. 판단 규칙 — 점수를 개입 단계로 바꾸는 방법

11장의 점수만으로 바로 단계를 정하면, 한 주만 튀어도 알림이 오락가락하거나, 다리를 다쳐 걸음수만 줄어든 사람이 높은 단계로 올라가는 문제가 생깁니다. 그래서 점수 위에 다음 규칙을 순서대로 적용합니다.

### 12.1 Baseline과 평가 주기

```text
Baseline 기간 : 가입 후 첫 28일 (유효 데이터 21일 이상)
평가 주기     : 매주 1회
비교 대상     : 최근 7일 vs baseline
기준값        : 평균 대신 중앙값 사용
```

- baseline 기간에는 12.5의 안전장치를 제외하고 단계를 판정하지 않습니다.
- 중앙값을 쓰는 이유는 하루 등산처럼 튀는 날에 기준이 흔들리지 않게 하기 위해서입니다.
- baseline은 3개월마다 다시 계산하되, 이미 "주의" 이상인 기간은 새 baseline 계산에서 제외합니다. 나빠진 상태가 새 기준이 되는 것을 막기 위해서입니다.

### 12.2 동시 조건 (게이트)

**"적극적 넛지"(50점) 이상으로 올라가려면 양과 리듬이 동시에 나빠져야 합니다.** 9장 E안의 조건을 그대로 게이트로 씁니다.

```text
[양]   Activity > 0  또는  12.4 절대 저활동 조건 충족
                 AND
[리듬] Rhythm > 0   또는  Sleep > 0
```

이 조건을 만족하지 않으면 점수가 50 이상이어도 **"주의"에서 멈춥니다.**

예: 부상으로 걸음수만 크게 줄고 생활 리듬·수면은 그대로인 사람 → 주의 단계에서 에이전트가 맥락을 확인하고, 더 올라가지 않음.

### 12.3 지속성 규칙 (히스테리시스)

```text
단계 상승 : 2회 연속 평가(2주)에서 조건 충족 시 확정
단계 하강 : 2회 연속 평가(2주)에서 낮은 단계 조건 충족 시 확정
```

- 한 주 튀었다고 단계가 오르내리지 않게 하는 장치입니다.
- 2주는 DSM-5 우울 삽화의 "최소 2주 이상" 기준과 맞춘 기간입니다.

### 12.4 절대 저활동 규칙 (C형 대응)

baseline 대비 변화가 없어도 다음 조건이 지속되면 단계를 끌어올립니다.

```text
최근 7일 걸음 중앙값 < 1,000보  →  4주 지속 시 최소 "주의"
                                   + 12.2의 [양] 조건 충족으로 간주
```

> 1,000보는 팀 초안의 "주중 일평균 1,000보 미만" 기준을 가져온 프로토타입 값입니다. 원래 활동량이 적은 고령층이 과도하게 잡히는지 합성 데이터로 확인해야 합니다.

### 12.5 안전장치 (baseline과 무관, 즉시 적용)

```text
7일 연속 일 100보 미만  →  즉시 "적극적 넛지" 이상
```

- baseline 수집 기간(첫 28일)에도 작동합니다.
- 12.3의 2주 지속 규칙을 거치지 않습니다.
- 팀 초안의 절대 기준(5,000 / 1,000 / 100보) 중 5,000·1,000보를 즉시 판정에 쓰면 원래 적게 걷는 사람을 전부 위험군으로 잡게 되므로, 즉시 판정에는 100보만 남깁니다.

### 12.6 유형 태그 — 어떤 말을 할지 고르는 용도

우울이 주된 경우에는 수면·리듬이 먼저 무너지고 겉으로는 출근·통학을 유지할 수 있으며, 은둔이 주된 경우에는 걸음수·이동이 훨씬 극단적으로 떨어집니다. 이 차이를 에이전트의 메시지 선택에만 사용합니다.

```text
리듬형 : (Rhythm + Sleep) 비율 > (Activity + Mobility) 비율
         → 수면·생활 시간 회복 중심 메시지

고립형 : (Activity + Mobility) 비율 ≥ (Rhythm + Sleep) 비율
         → 외출·이동 유도 중심 메시지
```

유형 태그는 진단명이 아니며 사용자에게 노출하지 않습니다.

### 12.7 임상 기준과의 연결

| 임상 기준 | 서비스 규칙 |
|---|---|
| 우울 삽화: 증상 2주 이상 지속 (DSM-5) | 단계 확정에 2회 연속(2주) 평가 요구 |
| 은둔: 3개월 이상 준은둔, 6개월 이상 은둔 | "지원 연결 고려" 4주 지속 시 기관 안내 — 준은둔 기간에 이르기 전에 연결 기회를 만듦 |
| 은둔 심각도 1단계(근처 상점 외출 가능) / 2단계(거의 집 밖으로 나오지 않음) | Mobility·절대 저활동 규칙으로 간접 반영 |

서비스는 이 기준으로 진단하지 않으며, 개입 시점을 정하는 참고로만 사용합니다.

### 12.8 임계값의 근거 수준

| 값 | 근거 |
|---|---|
| 2주 지속 | DSM-5 우울 삽화 기준 |
| IS 하락 0.08 | 대만 연구의 유형 간 IS 차이(약 0.1)를 참고한 값 |
| 감소율 30%, 저활동일 4일 | 프로토타입 초기값 |
| 수면 중간점 1.5 / 3시간 | 프로토타입 초기값 |
| 1,000보 / 100보 | 팀 초안 절대 기준에서 가져온 초기값 |
| baseline 28일 | 구현 편의를 위한 초기값 |

> 근거가 있는 값은 2주 지속과 IS 하락폭 정도이며, 나머지는 **합성 데이터 검증과 PHQ-9 응답을 이용한 보정 대상**입니다.

### 12.9 개인 판단과 지역 판단은 분리한다

빅콘테스트 제공 데이터(신한카드 결제, 통신사 유동인구)는 **지역 블록 단위 집계**이므로 개인 한 명의 결제나 이동을 볼 수 없습니다.

```text
개인 판단 : 앱 데이터 (걸음수 · 수면 · 결측 · 선택적 GPS)
지역 판단 : 빅콘 데이터 (블록 × 연령 × 시간대 × 업종)
```

- "대중교통 결제 0건", "거주지 격자 이탈 0건" 같은 개인 단위 카드·통신 조건은 실제 제공 데이터로 계산할 수 없고, 합성 데이터 시나리오에서만 사용합니다.
- 카드 데이터는 **오프라인 결제 한정**이므로 "배달 앱 결제 비율"은 실제 데이터로 계산할 수 없습니다.

## 13. GPS 기반 이동성 보강

걸음수만으로는 "동네는 나가지만 덜 걷는 사람"과 "집 밖으로 거의 나오지 않는 사람"을 구분하기 어렵습니다.

따라서 GPS 권한이 있는 경우 다음 지표를 선택적으로 추가합니다.

### 13.1 Radius of Gyration

생활 중심에서 얼마나 넓게 이동하는지 나타내는 이동성 지표입니다.

- 높음 → 생활 반경이 넓음
- 낮음 → 좁은 범위에 머무름

### 13.2 Location Entropy

방문 장소의 다양성을 Shannon entropy로 계산합니다.

```text
장소 다양성 ↑ → entropy ↑
한두 곳에만 머묾 → entropy ↓
```

### 13.3 Home Stay Ratio

하루 중 집 주변(반경 약 100m)에 머문 시간의 비율입니다.

### 13.4 고유 장소 수

일주일 동안 방문한 서로 다른 장소의 수입니다.

### 해석 예시

| 신호 조합 | 의미 |
|---|---|
| 걸음수 감소 + 반경 유지 | 밖에는 나가지만 활동량이 줄어든 상태 → 약한 신호 |
| 걸음수 감소 + 반경 감소 | 물리적 활동 범위가 함께 축소 → 강한 신호 |
| IS 하락 + entropy 감소 | 생활 규칙성과 장소 다양성이 동시에 악화 → 지속적 변화 감시 |

## 14. GPS는 필수가 아니라 선택적 보강 데이터

GPS를 항상 켜는 방식은 배터리, 권한, 실내 오차 문제를 만들 수 있습니다.

따라서:

```text
[기본 탐지]
걸음수 + 수면 + IS
        ↓
생활 변화 감지

[선택적 보강]
GPS
├─ 이동반경
├─ 장소 다양성
├─ 집 체류 비율
└─ 외출 횟수
```

구조로 설계합니다.

GPS를 허용하지 않은 사용자도 기본적인 리듬·활동 분석은 가능하도록 하는 것이 목표입니다. 대안으로 **집 Wi-Fi 연결 시간 비율**로 집 체류율을 추정하는 방법도 검토합니다. GPS보다 배터리 영향과 권한 부담이 적습니다.

## 15. 결측치도 하나의 신호로 본다 — 실험 가설

데이터가 없는 것을 단순한 분석 실패로만 처리하지 않고, **데이터 수집 행동 자체가 변화했는지**를 살펴봅니다.

예:

```text
평소 매일 데이터 수집
        ↓
갑자기 3일 미수집
        ↓
5일 미수집
        ↓
7일 미수집
```

웨어러블 충전이나 사용을 포기한 상황 등이 실제 행동 변화와 함께 나타날 가능성을 탐색합니다.

다만 **결측 = 위험**으로 직접 해석해서는 안 됩니다.

- 기기 배터리 부족
- 기기 고장
- 권한 변경
- 사용자의 여행
- 앱 오류

등 다양한 원인이 있기 때문입니다.

따라서 결측 신호는 본 점수에서 낮은 가중치(최대 10점)를 사용하고, 에이전트가 원인을 확인하는 보조 신호로 다룹니다.

## 16. 5개 합성 데이터 유형

모델이 특정 유형 하나에만 맞춰지는 것을 방지하기 위해 **5개 유형 × 10명 = 총 50명**의 합성 데이터를 생성합니다.

각 사람은 **90일치 일별 데이터**를 가집니다.

| 유형 | 설명 | 주요 변화 | 검증 목적 |
|---|---|---|---|
| **A 정상형** | 활동량·외출·수면·리듬이 안정적 | 큰 변화 없음, 낮은 결측 | 대조군 |
| **B 급락형** | 처음에는 정상이나 이후 활동이 빠르게 감소 | steps↓ + IS↓ + home stay↑ | 최근 생활 붕괴 |
| **C 지속적 저활동형** | 시작부터 활동량이 낮고 이동반경이 좁음 | 절대 활동량 낮음 + 장기 지속 | baseline 모델의 사각지대 (12.4 검증) |
| **D 리듬붕괴형** | 걸음수는 크게 변하지 않지만 생활 리듬·수면이 무너짐 | IS↓ + 기상 변동 + WASO↑ | 리듬 지표 필요성 검증 |
| **E 복합위험형** | 활동·리듬·이동성 악화와 결측이 동시에 발생 | steps↓ + IS↓ + radius↓ + entropy↓ + missing↑ | 다중 신호 동시 탐지 |

특히 C형과 B형을 함께 두는 이유는:

> **"최근 변화가 없어도 원래부터 저활동인 사람"**

과

> **"평소에는 정상인데 최근 급격히 무너지는 사람"**

을 동시에 검증하기 위해서입니다.

각 유형에서 기대하는 판정 결과는 다음과 같습니다.

|---|---|---|
| A | 관찰 유지 | — |
| B | 주의 → 적극적 넛지 | 고립형 |
| C | 4주 후 주의 (12.4) | 고립형 |
| D | 주의 (게이트에 걸려 상승 제한되는지 확인) | 리듬형 |
| E | 적극적 넛지 → 지원 연결 고려 | 고립형 |

## 18. AI 에이전트 — 규칙 엔진과의 역할 분담

규칙 엔진은 **"지금 어떤 상태인가"**까지만 정하고, 에이전트는 **"그래서 무엇을 할 것인가"**를 정합니다.

| | 규칙 엔진 | AI 에이전트 |
|---|---|---|
| 하는 일 | 점수 계산, 개입 단계·유형 태그 판정 | 맥락 확인, 대응 선택, 대화, 자원 연결, 후속 관리 |
| 방식 | 고정 수식 (11~12장) | LLM + 도구 호출 |
| 이유 | 왜 그 단계인지 설명 가능하고 일관돼야 함 | 사람마다 상황과 반응이 다름 |

위험 판정 자체를 LLM에 맡기지 않는 것은 의도적인 설계입니다. 단계를 정한 근거를 항상 수식으로 설명할 수 있어야 하기 때문입니다.

> **위험도는 규칙이 판단하고, 에이전트는 그 사람에게 무엇을 어떻게 할지를 판단한다.**

단계별로 정해진 문구만 보내는 구조는 에이전트가 아니라 알림 시스템에 가깝습니다. 이 프로젝트의 에이전트는 아래 19장의 판단을 스스로 합니다.

---

## 19. 에이전트가 하는 일

### 19.1 "눈치채고 먼저 말 거는 친구"

에이전트는 직접 진단하지 않습니다. 생활 패턴을 계속 관찰하다가 의미 있는 변화가 감지되면 먼저 말을 걸고, 사용자가 지금 할 수 있는 작은 행동을 제안합니다.

```text
걸음수 + 수면 + 활동 리듬 + 필요 시 GPS
        ↓
지표 계산 → baseline 비교 → 지속성 확인   (규칙 엔진)
        ↓
개입 단계 + 유형 태그
        ↓
맥락 확인 → 대응 선택 → 대화 → 후속        (에이전트)
```

### 19.2 맥락 확인 — 오탐 걸러내기

규칙은 "걸음수 60% 감소"는 알지만 이유는 모릅니다. 에이전트가 먼저 가볍게 묻습니다.

> "요즘 좀 바쁘셨어요?"

- "다리를 다쳐서 깁스했어요" → 해당 지표를 일정 기간 판정에서 보류
- "여행 중이에요" → 여행 기간을 baseline 비교에서 제외
- "그냥 나가기 싫어서요" → 오탐 아님, 그대로 진행

수식으로는 할 수 없는 일입니다.

### 19.3 대응 선택

같은 단계라도 사람마다 다르게 대응합니다. 다음을 함께 봅니다.

- 개입 단계
- 유형 태그 (리듬형 / 고립형)
- **이전에 어떤 제안에 반응했는지**
- 최근 알림 빈도

예: 산책 제안을 세 번 무시한 사람에게는 또 산책을 권하지 않고, "오늘은 정해진 시간에 일어나기만 해볼까요?"처럼 집 안에서 할 수 있는 제안으로 바꿉니다. 외부로 나가는 것보다 집 안에서의 일상 리듬(정해진 시간에 씻고, 먹고, 자기)을 먼저 회복하는 것이 은둔 회복의 첫 단계라는 대응 원칙과도 맞습니다.

### 19.4 자연어 요약

사용자 화면에는 숫자보다 변화 중심의 문장을 보여줍니다.

> "최근 2주 동안 평소보다 활동 시간이 줄었어요."

> "요즘 평소보다 같은 시간대의 생활 패턴이 조금 불규칙해졌어요."

> "이번 주는 집에 머문 시간이 지난주보다 길었어요."

금지 표현(위험군, 점수, 진단명)은 프롬프트 가드레일로 막습니다.

### 19.5 행동 제안

> "오늘 잠깐 밖에 나가볼까요?"

> "15분만 걸어보는 건 어때요?"

> "편의점이나 카페까지 천천히 다녀와도 좋아요."

변화를 지적하는 것("줄었어요")보다 제안("나가볼까요?")을 앞에 두는 것을 기본으로 합니다. 지적은 사람에 따라 방어적인 반응을 만들 수 있습니다.

### 19.6 지원 자원 연결

"지원 연결 고려" 단계이거나 대화에서 필요가 드러나면, 나이·지역·가구 형태에 맞는 사업을 찾아 안내합니다.

- 일상돌봄서비스
- 청년 은둔 지원 사업
- 정신건강복지센터
- 노인맞춤돌봄서비스

복지 사업 목록을 검색하는 RAG 도구로 구현합니다. 신청까지 돕는 기능은 **사용자 동의가 있을 때만** 동작합니다.

### 19.7 후속 관리

- 단계가 내려가면 개입 강도도 줄입니다.
- 다시 떨어지면 알아채고 먼저 연락합니다.
- 은둔 회복 후 재은둔을 막기 위한 사후 모니터링에 해당합니다.

### 19.8 에이전트 도구

| 도구 | 역할 |
|---|---|
| `get_user_state` | 현재 개입 단계, 유형 태그, 지표 변화의 서술형 요약 조회 (원점수는 전달하지 않음) |
| `get_history` | 이전 제안 내용과 사용자 반응 조회 |
| `pause_indicator` | 맥락 확인 결과에 따라 특정 지표를 일정 기간 판정에서 보류 |
| `search_welfare` | 지역·연령·가구 형태 기반 복지 사업 검색 (RAG) |
| `send_nudge` | 행동 제안 메시지 발송 (빈도 제한 포함) |
| `schedule_followup` | 후속 체크인 예약 |
| `crisis_handoff` | 위기 신호 감지 시 위기 상담 연결 안내 |

### 19.9 규칙보다 에이전트가 우선하는 경우

대화 중 **자해나 극단적 선택을 암시하는 표현**이 나오면, 점수와 단계와 상관없이 즉시 `crisis_handoff`로 넘어갑니다.

대화는 센서 데이터가 보지 못하는 신호이므로, 이 경우는 에이전트만 잡을 수 있습니다.

### 19.10 한 사람 기준 흐름 예시

```text
3주차 평가: 58점, 게이트 충족, 2주 연속 → 규칙 엔진이 "적극적 넛지" 확정, 고립형
  ↓
에이전트: "요즘 집에 계신 시간이 좀 길었던 것 같아요. 별일 없으셨어요?"
사용자  : "그냥 귀찮아서요"
  ↓
에이전트: 오탐 아님 확인 → get_history 조회 (산책 제안에는 반응 없었음)
  → "집 앞 편의점에서 좋아하는 음료 하나 사오기" 같은 작은 목표 제안
  ↓
2주 뒤 72점, 2주 연속 → "지원 연결 고려"
  ↓
에이전트: search_welfare → 거주 지역 청년 은둔 지원 사업 안내, 원하면 연결
```

## 20. 에이전트의 개입 단계

### 관찰 (0–29)

최근 생활 패턴 변화가 약하게 감지됨. 별도 개입 없이 주간 요약만 제공합니다.

> "오늘 날씨 좋은데, 편의점이라도 한 번 나가볼까요?"

### 주의 (30–49)

활동량 감소나 리듬 변화가 일정 기간 지속됨. 맥락 확인을 먼저 합니다.

> "요즘 좀 바쁘셨어요?"

### 적극적 넛지 (50–69)

양과 리듬이 함께 나빠진 상태가 2주 이상 지속됨. 유형 태그에 맞는 작은 행동을 제안하고 후속 체크인을 예약합니다.

> "요즘 집에 있는 시간이 좀 많아진 것 같아요. 15분만 바깥 공기 마셔봐요."

### 지원 연결 고려 (70–100)

생활 변화가 장기간 지속되고 지원이 필요할 가능성이 커지는 상황.

> "요즘 많이 힘드시다면 가까운 정신건강복지센터나 지역 복지기관에서 도움을 받아볼 수 있어요."

지원 연결 단계에서도 질환이나 고독사를 확정하는 표현은 사용하지 않습니다.

## 21. 에이전트가 하지 않는 것

- "당신은 고위험군입니다."라고 직접 라벨링
- 위험 점수 수치 공개
- "은둔형 외톨이입니다."라고 확정
- "고독사 위험이 높습니다."라고 확정
- 우울증 진단
- 다른 사용자와의 위험도 비교
- 공포감을 이용한 행동 유도
- 위험 단계를 스스로 판정하거나 올리기 (19.9 위기 신호 예외)
- 동의 없는 복지 신청이나 외부 기관 연락

앱은 **생활 패턴 변화에 대한 조기 개입**에만 집중합니다.

## 22. 개인 변화와 절대 수준을 함께 보는 이유

프로젝트의 핵심 설계는 다음 2개의 질문을 동시에 보는 것입니다.

```text
Q1. 평소의 나보다 얼마나 나빠졌는가?
Q2. 변화가 없어도 현재 상태가 장기간 너무 낮지는 않은가?
```

따라서 최종 탐지 구조는:

```text
                개인 baseline
                     ↓
             최근 변화량 계산
                     ↓
        ┌────────────┴────────────┐
        ↓                         ↓
   변화 위험(Change)          절대 저활동(Level)
        ↓                         ↓
        └────────────┬────────────┘
                     ↓
               리듬/수면 확인 (게이트)
                     ↓
                지속성 확인
                     ↓
              에이전트 개입
```

이 구조를 통해 **급락형**과 **지속적 저활동형**을 모두 다룰 수 있습니다.

## 23. 빅콘테스트 데이터와의 연결 — B2G 이중 구조

이 프로젝트는 개인 사용자용 앱으로 끝내지 않고, **개인 향 + 행정 향**의 이중 구조를 목표로 합니다.

### 23.1 개인 사용자 영역

개인 데이터:

```text
걸음수
수면
IS
이동성
생활 패턴
```

을 이용해 개인의 행동 변화를 탐지하고 에이전트가 개입합니다.

```text
개인 생활 데이터
       ↓
변화 감지
       ↓
AI Agent
       ↓
작은 행동 제안
```

### 23.2 행정·복지 영역

지역 단위 데이터에서는:

- 연령별 유동인구
- 시간대별 유동인구
- 요일별 유동인구
- 지역별 반복적인 저유동 패턴
- 식당·카페 등 생활 업종 소비 패턴
- 지역별 외부 활동 대리 지표

등을 분석하여 **생활활동 취약 지역**을 탐색합니다.

지역 단위 분석 아이디어:

| 분석 | 사용 데이터 | 보는 것 |
|---|---|---|
| 지역 × 연령대 저유동 지도 | `flow_age_pop` + 카드 `AGE_CCD` | 특정 연령대 유동과 소비가 함께 낮은 블록 |
| 시간 패턴 평탄화 | `flow_time_pop` (`TMST_00~23`) | 낮 피크가 없는 블록 — IS 논리를 지역 단위에 적용 |
| 주중·주말 차이 | `flow_wkdy_pop` | 주중과 주말 유동 차이가 거의 없는 블록 |
| 생활 업종 소비 | 카드 `MCT_RY_CD` | 식당·카페 결제가 극단적으로 낮은 연령·지역 조합 |

중요한 점은 지역 데이터는 개인을 직접 진단하는 용도가 아니라 **지역 수준의 생활 패턴과 환경을 파악하는 용도**로 사용하는 것입니다. (12.9 참조)

### 23.3 행정향 에이전트

행정 쪽 에이전트는 개인과 대화하지 않습니다. 대신 다음을 묶어 **담당자용 주간 리포트**를 작성합니다.

- 빅콘 데이터로 찾은 생활활동 취약 블록
- 해당 지역 앱 사용자의 비식별 개입 단계 분포
- 지역에서 연결 가능한 복지 자원 목록

### 전체 구조

```text
[지역 데이터]
공공·민간 데이터
        ↓
지역·연령·시간대별 생활 패턴 분석
        ↓
생활활동 취약 지역 탐색
        ↓
행정향 에이전트 → 담당자 주간 리포트

                    +

[개인 데이터]
걸음 + 수면 + 리듬 + 선택적 GPS
        ↓
개인 baseline
        ↓
변화 + 절대 저활동 + 지속성
        ↓
개인향 AI Agent
        ↓
행동 제안 / 지원 연결
```

따라서 프로젝트의 차별점은:

> **지역 수준에서는 어디에 개입할지를 찾고, 개인 수준에서는 언제 개입할지를 찾는 구조**

입니다.

## 24. 실제 데이터 매핑 — 1주차 핵심 작업

실제 제공 데이터에서는 가공 전에 원본 컬럼과 코드 체계를 먼저 확인합니다.

### 카드 데이터 (신한카드, 2025.07~12, 서울 강남구·강원 춘천시, 오프라인 결제 한정, 법인카드 제외)

## 27. LLM 토큰 비용 추정

위험도 계산은 규칙 엔진이 하므로 LLM을 쓰지 않습니다. **에이전트가 말을 할 때만 토큰 비용이 발생합니다.**

### 27.1 기준 가격 (Claude API, 2026년 9월 기준)

| 모델 | 입력 (100만 토큰당) | 출력 (100만 토큰당) |
|---|---:|---:|
| Claude Haiku 4.5 | $1 | $5 |
| Claude Sonnet 5 | $2 | $10 |

- 프롬프트 캐시 적중 시 입력 비용은 표준의 10%
- Batch API 사용 시 입출력 50% 할인

### 27.2 호출 가정

| 에이전트 동작 | 대상 | 월 횟수 | 1회 입력 / 출력 토큰 |
|---|---|---:|---|
| 아침 컨디션 체크 | 전원 | 30 | 2,500 / 100 |
| 주간 리듬 요약 | 전원 | 4 | 2,000 / 200 |
| 맥락 확인·넛지 대화 | 주의 이상 | 약 24턴 | 4,000 / 200 |
| 복지 자원 검색 (RAG) | 지원 연결 고려 | 2 | 6,000 / 400 |

입력이 큰 이유는 매 호출마다 시스템 프롬프트, 사용자 기록 요약, 도구 정의가 함께 들어가기 때문입니다.

### 27.3 1인당 월 비용 (환율 1,400원 가정)

| | Haiku 4.5 | Sonnet 5 |
|---|---:|---:|
| 정상 사용자 | 약 $0.10 (140원) | 약 $0.20 (280원) |
| 개입 대상 사용자 | 약 $0.24 (340원) | 약 $0.48 (670원) |

### 27.4 규모별 비용

| 규모 | Haiku 4.5 | Sonnet 5 |
|---|---:|---:|
| 사용자 1,000명 (정상 80%, 개입 대상 20%) | 월 약 $128 (18만 원) | 월 약 $256 (36만 원) |
| 행정향 주간 리포트 (지자체 1곳) | 월 수백 원 수준 | 월 수백 원 수준 |
| 빅콘 시연 (합성 50명 × 90일) | 수 달러 이내 | 수 달러 이내 |

### 27.5 비용 절감 방법

- **프롬프트 캐싱**: 모든 사용자가 공유하는 시스템 프롬프트를 캐싱해 입력 비용 절감
- **배치 처리**: 주간 요약, 행정 리포트처럼 실시간이 아니어도 되는 작업은 Batch API 사용
- **아침 체크를 버튼형으로**: 비용의 대부분이 매일 하는 체크인입니다. "좋음 / 보통 / 별로" 탭 선택으로 바꾸고 "별로"일 때만 LLM을 호출하면 전체 비용이 절반 가까이 줄어듭니다.
- **모델 나눠 쓰기**: 평소 메시지는 Haiku, "적극적 넛지" 이상 대화와 위기 신호 대응은 Sonnet. 품질이 중요한 대화에만 비싼 모델을 씁니다.

### 27.6 주의

한국어는 영어보다 같은 내용에 토큰이 더 많이 나오므로 위 수치는 대략적인 추정입니다. 프롬프트 초안이 나오면 실제 토큰 수를 측정해 표를 갱신합니다.

> 요약: **1인당 월 수백 원, 사용자 1,000명 기준 월 20~40만 원 수준.**

## 28. 기대하는 차별점

### 28.1 총량이 아니라 리듬을 본다

걸음수 총량만 보는 것이 아니라 **IS와 같은 시간적 규칙성**을 함께 봅니다.

### 28.2 급락과 원래 저활동을 모두 본다

개인 baseline 변화와 절대적 저활동을 함께 사용합니다.

### 28.3 판정은 규칙이, 대응은 에이전트가

위험 판정은 설명 가능한 규칙으로, 대응은 사람마다 다르게 판단하는 에이전트로 나눕니다.

### 28.4 위험 점수보다 행동에 집중한다

사용자에게 고위험 라벨을 주는 대신, 생활 변화에 맞는 작은 행동을 제안합니다.

### 28.5 결측도 실험한다

데이터의 부재 자체를 하나의 행동 신호 후보로 탐색합니다.

### 28.6 B2G까지 확장한다

개인용 조기 개입과 지역 수준의 복지 행정 분석을 하나의 구조로 연결합니다.

### 28.7 운영 비용이 낮다

판정에 LLM을 쓰지 않아 1인당 월 수백 원 수준으로 운영할 수 있습니다.

## 29. 한계와 주의점

1. **선행연구의 단면 설계**
   - 연관성은 보여줄 수 있지만 인과관계를 확정할 수 없습니다.

2. **임계값의 검증 필요**
   - 30%, 0.08, 4일, 1,000보 등의 값은 현재 프로토타입 기준이며 실제 고독사 위험을 직접 예측하도록 검증된 값이 아닙니다. (12.8 참조)

3. **생활 데이터의 오탐 가능성**
   - 여행, 부상, 질병, 휴가, 시험, 재택근무 등으로도 활동량과 수면이 변할 수 있습니다. 게이트(12.2)와 에이전트의 맥락 확인(19.2)으로 줄이지만 완전히 없앨 수는 없습니다.

4. **GPS 권한과 배터리**
   - 상시 GPS는 사용성과 배터리 문제를 일으킬 수 있습니다.

5. **결측 원인의 다양성**
   - 데이터 미수집이 곧 행동 변화라는 뜻은 아닙니다.

6. **진단 목적이 아님**
   - 우울증, 히키코모리, 고독사 위험을 확정적으로 진단하지 않습니다.

7. **합성 데이터의 한계**
   - 현재 50명 × 90일 데이터는 탐지 로직 검증용이며 실제 사용자 분포를 대표하지 않습니다.

8. **지역 데이터의 범위**
   - 빅콘 데이터는 블록 단위 집계이고 지역(강남구·춘천시)과 기간(2025.07~12)이 한정되어 있어, 개인 판단에 쓸 수 없고 다른 지역으로 바로 일반화할 수 없습니다.

9. **LLM 응답의 안전성**
   - 금지 표현과 위기 대응은 프롬프트 가드레일에 의존하므로, 시나리오별 응답 검증이 필요합니다.

## 31. 성공적으로 동작했다고 판단할 기준

단순히 "위험군을 맞췄다"가 아니라 다음을 확인합니다.

### 탐지

- 급락형을 놓치지 않는가?
- 지속적 저활동형을 baseline만으로 놓치지 않는가?
- 정상형을 불필요하게 호출하지 않는가?
- 리듬붕괴형에서 IS가 실제로 추가 정보를 주는가?
- 게이트가 부상·일시적 감소를 적절히 걸러내는가?

### 개입

- 사용자가 왜 제안을 받는지 이해할 수 있는가?
- 위험 라벨 없이도 행동 제안이 자연스러운가?
- 같은 알림을 반복해서 보내지 않는가?
- 이전 반응에 따라 제안이 바뀌는가?
- 작은 행동으로 연결되는가?
- 위기 표현에 즉시 반응하는가?

### 시스템

- GPS가 없어도 기본 탐지가 가능한가?
- 결측이 생겨도 시스템이 지나치게 민감해지지 않는가?
- 실제 데이터 컬럼으로 구현 가능한가?
- 1인당 운영 비용이 추정 범위 안에 있는가?

## 35. 핵심 설계 원칙 요약

| 원칙 | 적용 |
|---|---|
| 진단하지 않는다 | 질환·고독사 위험을 확정하지 않음 |
| 숫자로 낙인찍지 않는다 | 내부 점수는 사용자에게 직접 공개하지 않음 |
| 측정 사실은 알린다 | 생활 패턴 분석과 개인화 제안에 대해 고지 |
| 변화를 알려준다 | 숫자 대신 자연어로 변화 설명 |
| 개인 기준을 사용한다 | baseline 대비 변화를 탐지 |
| 절대 수준도 본다 | 원래부터 저활동인 사람의 사각지대 보완 |
| 양과 리듬을 함께 본다 | 상위 단계는 두 축이 동시에 나빠질 때만 |
| 지속성을 본다 | 일시적 변화와 장기 패턴 구분 (2주 연속) |
| 판정은 규칙이 한다 | 위험 단계는 설명 가능한 수식으로 결정 |
| 대응은 에이전트가 한다 | 맥락 확인·반응 기록 기반으로 제안 선택 |
| 위기 신호는 즉시 대응한다 | 대화 중 위기 표현은 점수와 무관하게 연결 |
| GPS는 선택적으로 쓴다 | 권한·배터리 문제 완화 |
| 결측은 보조 신호로 쓴다 | 원인 확인 없이 위험으로 단정하지 않음 |
| 넛지 중심으로 개입한다 | 통보보다 작은 행동 제안 |
| 지원 연결을 제공한다 | 장기 변화 시 지역사회 자원 안내 (동의 기반) |
| 개인과 지역을 분리한다 | 지역 집계 데이터로 개인을 판단하지 않음 |
| 인과를 주장하지 않는다 | 선행연구의 한계 반영 |

## 36. 연구와 서비스의 연결

### 연구가 말하는 것

- 활동량과 활동 시점은 서로 다른 정보를 가질 수 있습니다.
- 생활 리듬의 규칙성(IS)은 활동 패턴을 설명하는 데 활용될 수 있습니다.
- 생활 리듬과 외로움·우울 관련 지표 사이의 연관성이 관찰됩니다.
- 단면 연구만으로 인과관계를 확정할 수는 없습니다.

### 서비스가 하는 것

- 생활 데이터를 지속적으로 측정합니다.
- 개인 baseline과 비교합니다.
- 절대적 저활동과 최근 변화량을 함께 봅니다.
- 리듬 변화의 지속성을 확인합니다.
- 자연어로 변화를 설명합니다.
- 맥락을 확인하고 사람에 맞는 작은 행동을 제안합니다.
- 장기간 변화가 이어지는 경우 지원 자원을 안내합니다.

### 서비스가 하지 않는 것

- 우울증 진단
- 히키코모리 확정 판정
- 고독사 가능성 확정 판정
- 사용자를 고위험군으로 라벨링
- 타인과 위험도 비교

## 37. 최종 서사

이 프로젝트의 출발점은 "누가 위험한가?"가 아닙니다.

> **"생활의 작은 변화가 시작됐을 때, 그 사람보다 먼저 알아차리고 무엇을 해줄 수 있는가?"**

입니다.

그래서 우리가 만들고 싶은 것은:

```text
기존 접근
측정 → 분류 → 경고

우리의 접근
측정 → 변화 감지 → 자연스러운 대화
     → 작은 행동 제안 → 필요 시 지원 연결
```

입니다.

AI의 역할은 **판정자가 아니라 조기 개입을 시작하는 생활 동반자**입니다.
