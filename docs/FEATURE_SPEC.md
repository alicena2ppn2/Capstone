## 반응·출석 연출과 미션/일기 예외 처리

이웃의 응원/감사는 저장 성공 후 각각 ‘응원을 남겼어요’/‘고마움을 남겼어요’를 1.3초 표시한다. 선택 색·체크 문구는 유지한다. 기존 반응은 한 종류 선택 방식이며 취소 동작을 새로 추가하지 않았다. 같은 선택 재클릭은 중복 처리하지 않고 저장 실패는 재시도 안내를 남긴다. 웹은 localStorage 쓰기 성공 후 상태 변경, 앱은 commitState의 직렬 AsyncStorage 저장 성공 후 안내한다. 실제 상대 전달/읽음이 아닌 로컬 시연이다.

출석 지급 성공에서 새 날짜 영수증이 생긴 경우에만 출석표를 자동으로 닫고 앱 중앙의 작은 ‘오늘 받은 선물’ 패널을 1초 표시한다. 기존 RewardPanel/RewardGlyphDrawing/HouseDecor와 newAttendanceReward를 연결했다. 코인·XP는 실제 수치, 의상·소품은 실제 상품 도형과 이름을 표시한다. 중복 아이템은 지급된 대체 코인 영수증을 그대로 표시한다. 확인 버튼 없이 자동 종료하며 재열기/새로고침으로 반복하지 않는다. 오늘 받은 결과는 출석표에 남는다. 실패 시 출석표를 유지하고 성공 연출을 하지 않는다. 웹 모션 줄이기는 정적 표시, 네이티브는 확대/이동 없는 opacity만 사용한다. 보상량·확률·대체 규칙은 유지한다.

일일 구조는 고정3+활동3 그대로다. 활동의 의미는 challenges.js의 activityGroup으로 관리하며 새 계획에서 같은 의미의 활동을 동시에 추천하지 않는다. 최근 3개 날짜에 제공한 그룹을 덜 반복하고, 후보가 부족하면 부담을 올리지 않고 반복한다. 최근 부담 응답은 다음 배정에서 같은 활동 그룹보다 조건에 맞는 다른 행동을 우선하는 데 사용하며, 모든 활동을 effort 0으로 바꾸지는 않는다. 기존 날짜에 저장된 계획/지급 이력은 재작성하지 않는다. 교체는 오늘의 다른 활동·이미 완료한 의미 그룹과 겹치지 않고 기존보다 높은 effort를 사용하지 않는다. 완료/지급된 슬롯은 교체 불가, 대안이 없으면 유지하며 기존 화면이 안내한다. 최종 서버 선정/교체 정책은 미확정이며 이 규칙은 로컬 추천 개선이다.

서울 자정이 지나면 편집 중 본문·감정·질문을 보존하고 ‘오늘로 이어 쓰기 / 초안으로 남기기’를 제공한다. 오늘 저장 본문/초안이 있으면 유지 또는 합쳐 이어 쓰기를 사용자가 선택한다. 자동 덮어쓰기/자동 저장/자동 보상은 없다. 합친 내용이 2,000자를 넘으면 원본들을 유지하고 안내한다. 지난 초안은 날짜별 진입 버튼으로 새로고침 뒤에도 다시 찾을 수 있다. 초안을 옮기는 작업은 journals/스탬프/완료/보상을 만들지 않으며 오늘 저장 성공에만 기존 날짜별 지급 원장이 적용된다.

과거 일기는 수정 불가지만 삭제 확인 후 날짜와 무관하게 삭제할 수 있다. 본문·감정·연결된 day-diary 답변·해당 날짜 초안을 지우고 journalDates/completed/missionReceipts는 보존해 집계와 중복 지급을 방지한다. 삭제한 글은 초안에서 복원되지 않는다. 기존 자산·백엔드/API 계약은 변경하지 않는다.

관련 코드: 웹 App.jsx/Attendance.jsx/RewardPanel.jsx/Visit.jsx/Diary.jsx, 모바일 GameApp.jsx/RewardPanel.jsx/Visit.jsx/Diary.jsx, 공유 challenges.js/dailyMissions.js/journal.js/rewardFeedback.js/useBriefFeedback.js. 기존 저장 키를 사용하고 새 필드를 강제로 초기화하지 않는다.

검증: 로직 67개 테스트, 웹 build, 모바일 lint/typecheck·iOS/Android/Web export 통과. 임시 Edge에서 출석 4종/중복 대체/실패/재열기/재진입, 이웃 반응 성공/실패/선택 상태, 과거 초안 충돌/합치기와 과거 삭제를 확인했다. 실제 iPhone/Android 화면·실기기 안전 영역/키보드는 미확인이며 실제 사용자 인증/서버 보상/상대 전달은 미연결이다.


## 첫 진입 · 로그인 연결 범위

MY MOCHI 로그인/가입 화면에서 시작한다. 보라·크림 UI와 기존 친구 렌더러, 공식 카카오 로그인·Google 버튼 이미지를 사용한다. A2z 400~600을 유지하며 공급자 버튼 글씨는 공식 PNG에 포함된 스타일이다. 세션 확인 중 홈을 마운트하지 않는다. 설정의 로그아웃은 signOut 성공 후 로그인 화면으로 돌아가며 개발 미리보기도 종료한다. 실패 시 설정에서 다시 시도할 수 있고 게임 저장 데이터는 삭제하지 않는다. frontend 웹 인증 어댑터는 미연결이다. mobile의 iOS·Android에는 브라우저 Google OAuth → Supabase PKCE 코드 교환 → getUser 검증 → POST /auth/supabase 계정 연결 성공 후 홈 진입하는 코드가 있다. 실제 서버 주소/배포 계약 및 실기기 성공은 미검증이다. 세션·PKCE verifier는 SecureStore에 별도 저장하고 앱 활성 상태에서 자동 토큰 갱신한다. 사용자 ID나 임의 토큰을 로그인으로 취급하지 않는다. 실패/취소 시 재시도하고 진행 중 중복 입력을 막는다. 게임 데이터는 초기화하지 않는다.

개발 환경에서만 게임 미리보기 버튼을 제공한다. 웹 `http://127.0.0.1:5180/?preview=game`, 모바일 로그인 화면의 개발용 게임 미리보기. 모바일 Supabase Google 인증 코드가 연결됐으며 iPhone 실기기 로그인은 검증 대기다. 카카오·Apple·웹 인증, 계정별 게임 동기화와 신규 가입/온보딩은 별도 계약·앱 등록·설정이 필요하다. 게스트/계정 병합은 미확정이며 자동 병합하지 않는다. 약관·개인정보처리방침은 실제 URL이 없어 준비 상태만 표시한다. 자세한 연결 항목은 [AUTH_SETUP.md](AUTH_SETUP.md).

## 1. 의도와 구현 범위

현실의 작은 활동 → XP·코인 → 독립된 친구·옷·집 꾸미기 → 캐릭터 반응. 결석·미완료 벌점, 강제 진화, 심리 상태 진단은 없다. frontend/는 React/Vite·localStorage, mobile/은 Expo SDK 57·React Native 0.86.3·React 19.2.3·AsyncStorage다. 루트 shared/features와 shared/data의 규칙·콘텐츠로 계산하며 게임 백엔드 호출과 센서 인증은 연결 전이다. 모바일 Supabase Google 인증과 게임 기록 동기화는 별개이며 게임은 기존 AsyncStorage를 유지한다. 샘플 이웃에게 글이나 반응을 실제 전달하지 않는다.

실제 상점 캐릭터는12종이다. 기존6종의 외형·조건은 유지하고 추가6종은 아래 최종6종 표의 외형·레벨·가격을 사용한다. 원본/ABC는 개발 비교 화면에서만 보존한다.

모바일은 View/Text/Pressable/ScrollView/Modal 및 react-native-svg로 구현한다. 원래 친구의 옷·clipPath·Animated 반응·모션 줄이기·이탈 시 정리는 유지한다. 네이티브 OS SafeArea와 KeyboardAvoidingView, 단일 부모 ScrollView를 사용한다. 웹과 앱 저장소는 별개이며 설정 JSON 백업으로 수동 이관한다. 실제 기기 키보드/접근성은 미확인이다.

## 2. 화면과 홈

오늘의 도전 상단은 왼쪽 `<` 형태의 44px 홈 복귀 버튼으로 정리한다. 웹 퀘스트 내부의 달 아이콘·고정 숫자 200·집 버튼·플러스 3개와 중복 레벨 장식은 표시하지 않는다. 다른 공통 화면의 메뉴와 앱 상단의 실제 LV/XP·재화는 유지한다. 네이티브 오늘의 도전도 홈 라벨 대신 `<` 버튼으로 연결한다.

공통 셸은 아이폰 사용 목업이다. 데스크톱은 최대 390×844px, 뷰포트 높이에 맞춰 제한하는 검정 기기 테두리·48px 곡률·다이내믹 아일랜드·서울 시각 상태 바·하단 홈 표시줄을 제공한다. 신호/배터리는 정적인 장식이며 실제 기기 값을 읽지 않는다. 장식은 aria-hidden·비상호작용이며 게임 기능/저장과 무관하다. 상단 기기 영역·게임 상태·스크롤 콘텐츠·하단 기기 영역을 flex로 분리한다.

480px 이하 실제 모바일에서는 테두리/장식 상태 바/홈 표시줄을 숨겨 실제 OS 표시와 중복하지 않고 100dvh 전체 화면·네 방향 safe-area inset을 적용한다. viewport-fit=cover와 iOS 홈 화면 실행 메타 정보를 제공하지만 네이티브 앱·서비스 워커·오프라인 PWA 구현은 아니다. 모바일 폼 입력은 16px으로 설정해 iOS 자동 확대를 방지한다. 모든 화면 너비는 셸 안에 맞추며 상점은 좁은 기기 콘텐츠 폭을 고려해 1열로 표시한다. 이 기기 셸 내 상점/설정/방문 화면의 중복 테두리는 제거한다. 실제 iPhone/Safari·가상 키보드·홈 화면 실행 검증은 미수행이다.

웹은 React screen 상태로 홈·도전·일기·방명록·설정·상점·방문하기를 전환한다. 모바일은 Expo Router 경로를 GameApp 화면 구현에 연결한다. 양쪽 모두 하단 퀘스트 → 홈 → 상점 단축 메뉴가 있으며, 웹 내부 화면은 별도 URL 경로를 만들지 않는다. 전체 에이투지체 웹폰트, 실패 시 시스템 sans-serif.

폼 요소와 details/summary도 에이투지체 및 시스템 폴백을 상속한다. 상점/quest-ui 내부 타이포그래피는 화면 제목 21~22px, 카드 제목 16px·섹션 제목 18px, 본문/입력/펼침 제목 14px, 보조 정보 12~13px으로 명시한다. 홈의 기존 크기·배치는 유지한다. ui-disclosure는 기본 삼각형을 작은 CSS 꺾쇠로 대체하며 접힘/펼침·Enter/Space·포커스는 네이티브 details/summary 그대로다. 소개 본문은 1.7 줄간격과 한글 keep-all/긴 문자열 줄바꿈을 적용한다.

ui-secondary는 밝은 크림색·보라 계열 경계선·14px 곡률·최소 44px 터치 영역의 보조 버튼이다. 구매/저장/시작/완료는 차분한 보라 주요 버튼으로 구분한다. 상점 그리드는 시작 정렬해 펼친 카드의 옆 카드를 늘리지 않으며 430px 이하 뷰포트에서 1열로 표시한다. 상점/퀘스트 프레임 폭만 화면에 맞추며 다른 화면 구조는 변경하지 않는다.

홈은 코인/출석 한 줄, 방과 캐릭터, 말풍선 아래 실제 LV/XP, 오늘의 도전·꾸미기 주요 버튼, 오늘의 도전 요약 순서다. 홈의 상단 LV/XP는 제거하고 캐릭터 아래 말풍선 밑에 한 번만 표시하며 다른 화면 상단 LV/XP는 유지한다. 코인은 한 번 표시한다. 설정은 모서리 톱니바퀴, 방문·방명록은 방 안 보조 버튼, 애칭은 방 상단 중앙(방 기준 top 64px)의 14px 이름표이며 설정으로 연결한다. 방의 왼쪽 벽 달력은 월·일·요일, 오른쪽 벽 시계는 시침·분침과12눈금을 표시한다. 기기 현지 시간으로1초마다 갱신하며06~18시는 낮,18~06시는 밤의 하늘과 약한 배경 음영을 적용한다. 미션·출석은 기존 서울 날짜 기준을 유지한다.

홈 방문하기는 집 아이콘, 방명록은 작은 봉투 아이콘이며 밝은 표면과 보라 윤곽을 공유한다. 두 메뉴 라벨은 에이투지체 500(Medium), 기존 터치 영역과 이동 동작은 유지한다. 홈 메뉴에만 적용한다.

홈 전용 방 비율 368:500, viewBox 0 55 368 500로 빈 벽/바닥 비중을 줄이면서 가구·장착 소품과 카페트 중앙 캐릭터를 유지한다. 캐릭터 폭 66%, 최대 248px과 반응은 유지하며 새 viewBox의 바닥 좌표에 맞춰 위치를 조정한다. 말풍선/레벨은 방 하단 기준 86.8% 위치에서 묶어 표시하고 이름은 방 상단 중앙으로 분리하며 주요 버튼을 요약 목록보다 먼저 둬 첫 화면의 스크롤 부담을 줄인다. 짧은 화면은 내부 세로 스크롤을 유지하며 모든 높이에서 무스크롤을 보장하지 않는다. 하늘색·크림·나무색, UI의 주요 행동은 보라, 보상 포인트는 살구. src/refe/image.png는 분위기 참고이며 에셋을 복사하지 않는다. 기본 배경은 상점/이웃 방의 기존 비율을 유지한다. 돌봄·상태 바·가상 걸음·산책 코인 경로는 없다.

공통 ScreenHeader로 도전·상점·일기·방명록·이웃·설정 제목 21~22px, 뒤로가기 최소 44px, 상단 간격을 통일한다. 기존 이동 목적은 보존하며 장식은 기능과 관련 있는 작은 선 아이콘으로 제한한다. 주요 보라·선택 탭 보라/체크·작은 살구 보상·밝은 크림 카드, 기본/선택/비활성/장착 상태를 구분한다. 장착 중은 실행 불가 상태이며 해제는 보조 동작이다. 상점 미리보기와 방 배경 디자인은 바꾸지 않는다.

도전은 오늘/이번 주/이번 달 한 줄 탭, 기록·취향 별도 진입, 중복 하단 장식/설정/상점 제거. 웹 phone-content와 앱 메인 ScrollView 한 곳만 스크롤한다. 홈 주요 버튼 아래 도전 요약은 둥근 카드 안에 도전 중→시작 전→완료 순으로 표시한다(저장 순서는 유지). 누르면 해당 미션으로 이동한다. 상품 목표 선택 및 홈 목표 요약은 제거했다. 하단 꾸미기 버튼으로 상점에 진입한다.

## 3. 일일 미션과 선정

매일 제공하는 미션은 고정 3개 + 변경 3개 = 6개다. 모두 목록에 제공하며 선택 슬롯 제한이나 전체 완료 조건은 없다. 개별 완료를 인정하고 미완료 벌점은 없다.

| 영역 | 미션 | 완료 근거 |
| --- | --- | --- |
| 매일 하는 3가지: 크림/체크리스트 | 출석하기 | 기존 출석 지급 경로의 성공 |
| 같은 영역 | 오늘의 일기 쓰기 | 당일 유효한 공통 일기 저장 성공 |
| 같은 영역 | 방명록 남기기 | 다른 샘플 이웃의 방명록에 유효한 로컬 글 저장 성공 |
| 오늘의 활동 3가지: 연한 보라/나침반 | 현실 활동 3개 | 시작 후 사용자 해냈어요 확인 |

각 영역에 N/3 완료를 표시한다. 고정 행은 기능 진입 버튼이며 별도 수동 완료 버튼은 없다. 이미 완료된 일기는 일기 보기로 연결한다. 화면 방문·입력 중·초안·샘플 글·실패는 완료가 아니다. 완료 순서로 카드를 옮기지 않으며 새 활동 완료는 1.5초 피드백 후 간결하게 표시한다.

dailyMissions.js와 missionGuidance.js가 날짜별 로컬 추천을 담당한다. 초기 질문은 ‘요즘 다시 해보고 싶은 활동 / 편한 시간 / 지금 제외할 활동’ 3개이며 모두 건너뛸 수 있다. preferences.missions에 activities/exclude/minutes/reviewed를 저장하고 기존 음악·음식 취향을 보존한다. 도전 첫 진입의 선택 안내, 기록·취향 및 설정에서 같은 항목을 편집한다. 선호 저장 실패는 성공으로 표시하지 않으며 오늘 배정은 바꾸지 않는다.

사용자가 선택한 활동·과거 활동을 먼저 이어가고 기본 행동을 아주 작은 대안보다 우선한다. 최대 두 익숙한 후보를 우선하며 마지막 후보는 가능한 경우 다른 목적을 고려한다. 성취·연결·취향은 균형 기준이고 강제 할당이 아니다. 정보 부족 시 기본 후보라고 설명하며 익숙한 활동이라고 단정하지 않는다. 같은 그룹(정리, 짧은 외출, 인사, 사진 등)은 하루 중복하지 않으며 날짜 간 반복은 허용한다. 자동 난도 상승은 없고 easy 피드백도 확장 권한이 아니다. 후보 부족 시 조건을 어겨 채우지 않는다. 현재 실제 기본 풀은 모든 제공 선택 조건에서도 3개의 서로 다른 후보를 확보한다.

연락은 명시적 관심을 선택한 경우에만 기본 추천하며 이동/연락/사진/음악/독서 제외와 편한 시간을 반영한다. 음악은 선택한 관심이나 기존 music 취향을 활용한다. 독서·취미는 해당 관심 선택을 활용한다. 방명록 때문에 연락 추천을 낮추거나 오늘 목록을 자동 교체하지 않는다. 부담 응답은 다음 배정에서 해당 활동 그룹보다 다른 행동을 우선한다. 새로운 수행 수준 선택이나 자동 light/extend 저장은 하지 않는다. 완료 횟수로 난도를 올리지 않는다.

활동 콘텐츠는 기존 ID를 유지하면서 물건 세 개/자리 한 칸(동일 tidy 그룹), 컵, 취미, 음악 감상, 독서, 생활권 소식을 추가했다. day-diary 입력은 변동 풀에서 계속 제외한다. day-wake는 기상 시간 평가 없이 시작 행동, day-drink는 구매 없는 익숙한 장소 방문으로 안내한다. 미션 카드에 제목·구체적인 짧은 설명·예상 시간·진행 상태를 표시한다. 교류 설명에는 필요한 경우 대화 예시 한 개를 포함한다. 방법 보기와 단계 나열/수행 수준 선택 화면은 없다. 시간은 안내용이다.

활동을 바꾸는 경로는 ‘다른 활동으로’ 하나다. 새로운 base/light/extend 선택 UI·쓰기 함수와 상세 화면 연결은 제거했다. 기존 missionModes와 activityRecords의 mode/criterion/channel은 보존한다. legacyMissionConditions.js는 이전 조건을 읽기 위한 호환 데이터일 뿐 새 선택 UI나 추천 공급원이 아니다.

진행 중이거나 light/extend가 저장된 미션은 ensureDailyMissions에서 활동의 criterion을 한 번 고정해 문구 수정으로 완료 조건이 변하지 않게 한다. 새로 시작하는 활동은 시작 시 짧은 현재 조건을 같은 활동 데이터에 기록한다. 반복 이관은 보상을 지급하지 않는다. 기존에 물건 하나 조건을 선택한 경우 제목도 ‘물건 하나 제자리로’로 표시한다. 명시적 다시 보기로 이전 활동을 선택해도 저장된 작은 대안/확장 선택과 교체 당시 조건을 보존한다. 과거 기록은 제거하지 않는다. 완료 후 가벼웠어요/적당했어요/부담됐어요 응답은 선택이며 보상과 무관하다. 사진 첨부/공통 일기/기존 걷기 목표 입력은 수행에 필요한 기존 기능으로 유지한다.

샘플 이웃 글의 신규 지급 기록 channel은 sample-neighbor-local이며 현실 교류는 real-world-self-report, 사진은 local-photo-save다. 과거 channel 없는 기록을 실제 교류로 소급 해석하지 않는다. 실제 사용자 방명록 전달·서버 배정/확인/보상·센서 인증은 미연결이며 사용자 자기 확인을 자동 인증이라고 표현하지 않는다. [백엔드 협의 문서](QUEST_BACKEND_AGREEMENT.md)에 차이와 연결 조건을 별도로 기록한다.

카드의 ‘다른 활동으로’는 기존 하단 창에서 후보 한 개의 제목/설명/예상 시간을 먼저 보여 주고 ‘이 활동으로 바꾸기’로 확정한다. 같은 카테고리 제한 없이 사용자 시간·제외 조건을 지키며 현재와 비슷한 effort/시간을 우선한다. 현재보다 effort나 안내 시간이 큰 후보는 자동으로 넣지 않는다. 가벼운 방법을 선택한 상태는 effort0/1분 범위, 걷기 선택은 선택한 시간 범위를 사용한다. 동률은 날짜/슬롯/교체 수/ID의 고정 순서로 분산하며 렌더마다 무작위로 뽑지 않는다.

현재 활동 그룹, 다른 슬롯/오늘 완료 그룹, 오늘 넘긴 그룹을 제외한다. dailyMissions[서울날짜].passed와 기존 replacements의 출발 ID를 함께 읽어 구형 교체 이력도 보존한다. 새로고침/재접속 후에도 반복·다른 슬롯 재등장이 없으며 다음 날짜의 새 계획에는 passed를 가져오지 않는다. 지난 날짜 기록은 삭제하지 않는다. 명시적 교체는 같은 slot을 유지하고 시작 전으로 돌아가며 보상·완료 원장을 만들거나 초기화하지 않는다.

후보가 없으면 ‘지금 조건에 맞는 다른 활동을 모두 살펴봤어요’와 현재 미션 유지 안내를 표시한다. 사용자가 ‘살펴본 활동 다시 보기’를 선택한 경우에만 passed 제외를 해제해 후보를 재검토한다. 현재 활동/다른 슬롯/오늘 완료/시간/제외/부담 상한은 계속 지킨다. 다시 봐도 없으면 그 사실을 안내하고 성공으로 처리하지 않는다. 취소는 데이터 변경 없이 닫힌다. 교체 저장 실패는 기존 목록·이력을 유지하고 재시도를 제공한다.

수행 수준 변경 버튼은 없다. 완료/지급된 슬롯은 다른 활동 교체가 잠긴다. 나중에 하기의 기존 보류/다시 도전은 유지한다. 교체 횟수에 임의 서버 제한을 새로 만들지 않는다.


## 4. 진행과 통합 일기

활동은 도전하기(무보상) → 도전 중 → 해냈어요! → 완료. 걷기 목표는 유효한 선택인지 로직에서도 확인한다. 완료가 진행보다 우선한다. 카드에는 카테고리·제목/상태·완료 조건·실제 지급 가능 보상과 주요 버튼을 표시한다. 추천 이유/보상 안내/선택적 부담 응답은 작은 진입점에서 확인한다. QuestSheet는 앱 프레임 안에 표시하고 닫기·바깥 클릭·Escape, 배경 스크롤/inert 및 포커스 복귀를 지원한다. 전체 미완료 배지는 없다.

홈·일일 일기 미션·기록·취향 모두 Diary 공통 편집기로 같은 날짜를 연다. 별도 80자 도전 입력과 중복 기록 편집기는 제거했다. 공통 saveDiaryMission을 사용한다. 최대 2,000자, trim 후 공백 금지, 최소 글자 수 없음. 감정 5종과 짧은 질문은 선택 사항이며 자유로운 한 줄만으로 저장 가능하다. 다른 질문은 본문을 유지하며 자동 삽입하지 않는다. 임시 질문은 diaryPrompts.js로 분리했다. 실제 GET 일기 주제 계약은 있으나 서버·인증 연결 전이라 호출하지 않는다.

초안은 journalDrafts[날짜]의 text/emotion/prompt, 저장 본문은 journals[날짜]로 분리한다. 초안은 이동/복귀·새로고침 시 복원하지만 미션 완료·날짜 집계·스탬프·보상은 발생하지 않는다. 저장 중/성공/실패/다시 저장 상태를 표시한다. 웹은 localStorage 쓰기, 앱은 직렬 AsyncStorage 저장 성공 후 상태/보상을 반영한다. 저장 실패 시 화면의 글을 지우지 않는다. 저장소 자체가 차단된 경우 영구 복원은 보장하지 않으며 실패를 알린다.

서울 당일에는 수정·삭제 후 재작성 가능하며, 지난 날짜는 수정 불가지만 삭제할 수 있다. 삭제는 본문·감정·당일 도전 답변·초안을 제거하고 최소 날짜/완료/지급 원장은 보존한다. 재작성·수정은 같은 날짜 보상을 중복 지급하지 않는다. 날짜별 최신순 목록·월별 달력·윤년/월 이동 유지. 현재 저장 본문이 있는 날만 스탬프를 찍는다. journalDates는 과거 작성 집계 원장이라 삭제로 감소하거나 재작성으로 증가하지 않는다.

일간 키 YYYY-MM-DD:ID, 주간 월요일 날짜:ID, 월간 YYYY-MM:ID를 유지한다. 매초 및 웹 visibilitychange/앱 AppState 복귀로 서울 기간을 갱신한다. 로컬 제출은 성공 처리 시점의 서울 날짜를 사용하며, 열린 지난 날짜 일기 저장은 거절한다. 자정 제출의 최종 서버 정책은 합의 필요다.

## 5. 집계와 성장

| 목표 | 집계 | 보상 |
| --- | --- | --- |
| 주간 바깥 발견 | 해당 서울 주의 외출 완료 기록 2회 | 30XP·30코인 |
| 주간 기록 | 해당 주 서로 다른 기록 날짜 3일 | 30XP·30코인 |
| 주간 작은 연결 | 해당 주 교류 완료 기록 2회 | 30XP·30코인 |
| 월간 바깥 발견 | 해당 월 외출 완료 기록 8회 | 60XP·60코인 |
| 월간 기록 | 해당 월 서로 다른 기록 날짜 10일 | 60XP·60코인 |

진행률과 회수 표시, 목표 달성 후 보상 받기로 기간당 1회 지급한다. 동일 날짜:도전 키는 1개 기록이며 일기 수정은 1일 이상 집계되지 않는다. 다른 행동은 같은 날짜에도 각각 집계할 수 있다. 주간과 월간은 같은 기록을 각 기간 목표에 사용할 수 있지만 각 목표의 지급은 1회다.

LV = 1 + floor(XP/100) 유지. 실제 시작 0XP·90코인·감자 1개. initialGame({demo:true})는 명시적 시연용 540코인이며 앱 기본값으로 사용하지 않는다. 일간 기본 15XP·25코인, 처음 시도한 현실 행동 ID는 5XP 추가(입력은 추가 없음). 같은 행동은 다음 날짜에 기본 보상. 기존 전역 일간 최대 3회 경로는 새 화면에서 사용하지 않는다. 변경 활동 3개는 각각 날짜/슬롯당 1회 지급, 일기 날짜당 1회 지급, 출석은 기존 별도 지급이다. 방명록 루틴은 완료만 기록하며 추가 보상은 합의 전 보류한다. 교체/재진입으로 지급 키를 초기화하지 않는다. 쉬운 입력은 일기 하루 1회뿐이다. 레벨/사회적 행동에 따른 차등 기본 보상 없음. 누적 현실 행동 10개 키(날짜 달라도 가능, 입력 제외)로 펭귄 1회 지급. 기존 보유 친구는 회수하지 않는다. LV.3 토끼 무료 지급, 자동 장착 없음.

계산 예시(출석 제외): 매일 산책+일기 2개, 주간 기록/외출과 월간 기록/외출 보상 모두 수령 시 7일 275XP(LV.3), 14일 665XP(LV.7), 28일 1205XP(LV.13). 한 가지 산책만 매일 하는 예시는 7일 140XP(LV.2), 14일 335XP(LV.4), 28일 605XP(LV.7). 첫날 시작 90+행동 25=115코인으로 90코인 전등을 살 수 있다. 기존 상품 가격·해금 조건은 유지하며 신규6종의 가격/조건은 아래 최종표를 따른다. 수치는 콘텐츠 속도 조정용 가정, 예방 효과 검증 기준이 아니다. 실제 날짜 시작/주 경계/보상 수령 여부/출석에 따라 달라진다.

## 8. 친구 정체성과 반응

각 친구는 독립된 SVG 캐릭터다. catalog.js의 FRIEND_INTROS에 짧은 성격/소개 초안을 분리한다. 상점의 친구 소개에는 성격·짧은 introduction·좋아하는 것·작은 습관을 표시하며 초안 여부·애칭 설계 설명은 사용자 UI에 표시하지 않는다. 외형 기반 초안이며 상세 서사는 미확정이다. 고유 이름과 애칭은 별개. game.nicknames는 캐릭터 ID별 애칭, 없으면 고유 이름 표시. 기존 mochi.petName은 첫 이관 때 현재 장착 친구에만 할당하고 원본 키 보존. 새 이름은 해당 친구만 변경한다.

홈 모든 친구: 눈 전체 그룹 3~6.5초 간격 깜빡임, 클릭/터치/Enter/Space 점프·하트 약 1초, 반응 중 추가 입력 무시. 새 실제 도전/집계 완료 이벤트 또는 다른 소유 의상 착용 ID 변경 시 축하 1회. 구매만 하기/같은 의상/해제/재렌더/홈 재진입은 생성하지 않음. 다른 화면 이벤트는 현재 친구에 대기 후 홈에서 1회 소비하며 친구 변경 시 대기 취소. 최근 이벤트 하나로 합치며 새로고침은 재생하지 않는다. 출석/가구 배치는 연결하지 않는다.

몸·옷·장식·얼굴은 같은 SVG 그룹, 그림자는 고정, 기존 내부 transform/clipPath 유지. 홈 이탈 시 타이머 정리, prefers-reduced-motion은 큰 움직임·눈 압축 없이 효과 투명도만 변화. 상점·이웃 미리보기는 비상호작용이다. 감자는 기존 Potato 로직, 나머지는 useFriendReaction/FriendEffects 사용.

## 10. 설정과 저장

### 웹 방명록 신고·차단·필터

필터 안내와 차단 작성자 펼침은 12px 보조 글씨와 작은 패딩으로 표시한다. 펼침 터치 영역은 44px을 유지하며 다른 화면의 펼침 스타일은 변경하지 않는다.

내 방명록·이웃 방명록은 같은 `guestModeration.js` 규칙과 GuestbookSafety UI를 사용한다. 신고 사유는 욕설/혐오 표현/스팸/기타이며, 확인 창은 앱 프레임 내부에 열고 취소·바깥 클릭·Escape 및 키보드 포커스 제어는 기존 QuestSheet를 사용한다. 차단한 작성자의 글은 두 방명록에서 숨기며 차단 목록 확인·해제는 내 방명록에서만 제공한다. 방문한 이웃 방명록에서는 목록을 표시하지 않는다. 글 원본과 좋아요 기록은 차단 때문에 삭제하지 않는다.

등록 전 NFKC 정규화·공백/기호/제로폭 제거 후 욕설·일부 집단 혐오 표현을 검사한다. 필터는 규칙 기반이며 문맥 오탐·누락 가능성이 있다. 기존 위반 글은 내용을 가리고 신고 동작을 유지한다. 신고된 글에서 필터가 위반을 확인하면 해당 글을 목록에서 제거하고 `신고 시각 + 7×24시간`까지 해당 작성자의 작성 제한을 저장한다. 같은 글 신고는 1회, 재신고로 제재를 연장하지 않는다. 다른 위반 글 신고는 별도 처리한다. 정상 글의 신고는 기록만 남기며 자동 삭제/정지는 하지 않는다. 입력 거절 자체로 제재하지 않는다.

별도 localStorage `mochi.guestModeration.v1`: version=1, blocked[작성자ID], `reports[방범위:글ID]`(사유/작성자/시각/확인 결과, 원문 없음), deleted[방범위:글ID], suspensions[작성자ID].until(UTC 밀리초)를 저장한다. 게임·옷장 데이터는 변경하지 않는다. 기존 글에 계정 ID가 없으면 샘플 이름 기반 ID로 해석하고 기존 m숫자/로컬 글은 local:self로 식별하며 애칭 변경으로 정지를 우회하지 않는다. 신규 로컬 글에는 authorId와 source를 붙인다. 제한 중에는 내/이웃 작성칸과 등록을 차단하고 함수에서도 재검사한다. 화면 타이머·focus·storage 이벤트로 해제를 반영하며 이탈 시 정리한다. 동일 브라우저 탭 상태를 공유하지만 서버 트랜잭션/기기 간 동기화는 아니다.

현재 Vite 웹 로컬 목업만 구현. 실제 사용자 계정 식별·전달·7일 제재의 서버 강제·운영자 심사·이의제기·서버 시간·백업 연동은 미구현이다. 안전 설정을 저장하지 못하면 신고/차단 적용 실패를 알리며 작성 시 안전 설정을 읽지 못하면 등록을 거절한다. 별도 Edge 프로필로 시험하며 실제 사용자 데이터를 초기화하지 않는다. 모바일은 이번에 이웃 등록 전 필터만 재사용하며 전체 신고/차단 UI와 7일 제재는 웹 로컬 구현이다. backend/는 변경하지 않는다.

### 가격 산정과 진행 예시

현재 고정3+활동3 구조를 확인했다. 활동 1개=15XP/25코인, 처음 수행하는 활동에는5XP 추가. 일기=15XP/25코인, 방명록=0(정책 대기), 출석은 기존 랜덤 지급만(코인10/20/30, XP5/8/10, 의상·소품 후보 및 중복30코인 대체). 과거 전역3회 한도를 가격 산정에 사용하지 않았다. 현재 활동은 하루3슬롯의1회 지급이고 일기/출석은 각 원장으로 별도 중복 방지한다. 레벨=1+floor(XP/100), 시작90코인/시연540코인, 주간30XP·30코인 및 월간60XP·60코인도 변경하지 않았다. 의상120~300, 가구90~520, 기존 구매 친구300/450/600과 비교해 초반120~150, 후반300~375로 정했다.

표의3개=매일 활동3개(45기본XP/75코인); 6개=활동3+출석+일기+방명록(60기본XP/100코인+출석). 6개 예시는 출석이 매일20코인인 유효한 예시이며 기대값/보장값이 아니다. 실제 출석에 따라 해당 날짜 코인 추가는0~30이고 XP·아이템을 받을 수도 있다. `node scripts/simulate-friend-economy.mjs`로 실제 날짜 선정·처음 수행XP·원장을 적용해 계산했다. 신규XP0/90코인, 2026-10-08 시작, 소비 없음, 주월 보상 청구 없음, 미션 교체/반복 보상 없음이 가정이다. 주월 청구/출석XP/수행구성에 따라 달라진다. 표의 가격 일수는 해금 후 잔액0에서 활동3개 수입을 모으는 기준이며 해금 소요와 다르다. 같은 계산의 누적 코인(초기90포함)은 밀루 해금 때3개540/6개690, 도토 해금 때3개4065/6개4890이다. 해금 전 저축하면 바로 살 수 있다. 기존 공식을 유지하므로 LV25까지 수입이 많이 쌓이는 특성은 남으며 임의로 회수·보상 축소하지 않는다. 예방 효과가 검증된 수치가 아니다.

## Supabase 백엔드 계정 연결의 현재 범위

모바일 getSession은 verified/user.id/source를 보존하고 실제 access_token을 반환한다. 공유 authBackendController/BackendClient가 POST /auth/supabase에 Bearer와 조회용{} 또는 등록용{nickname}을 보낸다. 알려진 신규회원404 detail만 닉네임으로 전환하고 다른 오류는 재시도 상태로 남긴다. 등록은 중복 제출을 막고 서버422/409를 표시한다.2~12자 검증의 최종 주체는 서버다.

backendUserId와 supabaseUserId는 AuthContext에 별도 메모리 필드로 유지한다. 연결 성공 후에만 홈으로 이동하며 재실행은 SDK 세션과 백엔드 연결을 다시 확인한다. requestUser는 백엔드 ID 경로와 새 SDK 토큰을 사용하고 계정 변경/로그아웃/늦은 응답에서 이전 계정을 차단한다. 토큰을 별도 영구 저장하지 않는다. 기존 로컬 게임 데이터와 계정 데이터를 자동 병합하지 않는다. Vite 웹은 같은 연결 구조/UI만 준비되어 있고 소셜 인증은 미설정이다.

계약은 origin/backend-onboarding-survey 82c24f5에서 읽었다. 2026-10-15 최신 main 반영 후 backend/app/main.py에도 해당 경로가 존재한다. 앱의 실제 서버 주소(EXPO_PUBLIC_API_URL)는 아직 설정되지 않았다. 실제 서버 연결/실기기 성공은 미확인이다. Android 남은 Firebase 어댑터는 로컬 백업 후 Supabase native 공유로 바꿨다. backend/의 인증·API 정책은 변경하지 않았다. [연결 설정/재개 문서](AUTH_BACKEND_SETUP.md)를 따른다.

## 소스 책임과 공유 경계

실제 최신 경로는 루트 shared/features의 게임·퀘스트·보상·일기 규칙, shared/data의 미션·캐릭터·상품·일일 문장, shared/utils의 서울 날짜·기기 시간, shared/theme의 공통 UI 값이다. shared/api와 shared/auth는 HTTP·계정 연결 상태 머신이며 토큰을 새 저장소에 복제하지 않는다. 공유 SVG는 shared/art에서 태그를 주입받고, React 공유 훅/컨텍스트는 순수 규칙과 별도 경계다.

모바일 src/app은 기존 라우트만, GameApp은 화면 연결, hooks/useGameState는 저장·날짜·출석/반응 이벤트, storage/storage는 기존 AsyncStorage와 백업 형식, auth는 실제 Supabase SDK/플랫폼 복귀, api/client는 기존 환경변수 주소를 맡는다. home/quests/login 전용 UI는 screens 하위에 둔다. 웹은 자체 DOM/CSS/IndexedDB, 모바일은 네이티브 UI/카메라/SecureStore를 유지한다. 저장 키·ID·보상·상품 가격·캐릭터 그림·경로·OAuth 설정은 변경하지 않았다. 상세 구조와 검증은 docs/ARCHITECTURE.md.
