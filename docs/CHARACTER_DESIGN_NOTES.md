# 승인된 캐릭터 제작 기준

최종 수정: 2026-10-08

## 승인된 그림체 기준

과거 A 원본은 `PrototypeFriendBaseline.jsx`에 보존하고 최종 기준은 아래 확정6종 표다. 큰 머리와 작은 몸, 짧고 통통한 팔·발, 몸 안에 배치된 눈, 여러 크기의 하이라이트와 은은한 볼터치를 유지한다. 기본 외곽선은 SVG 200×210 기준 2.5이며 크림·살구·연한 청회색과 부드러운 윤곽을 사용한다. 귀·꼬리·얼굴 윤곽으로 실루엣을 구분하고, 장식은 한 가지 작은 포인트를 중심으로 한다. 몸을 옷에 맞추지 않고 체형과 팔 경계에 옷을 맞춘다. 머리·귀·눈·입은 함께 움직이고 눈 전체를 깜빡이며, 기본 그림으로 정확히 돌아온다.

## 6종 개성 비교 시안 (개발 전용)

밀루·라니·루루·메루·도토·포포는 A(현재 원본), B(눈·표정만), C(B+체형·기본 자세)의 정적인 비교 시안을 제공한다. 실제 원본 렌더러를 A에 사용하고 B/C는 별도 스냅샷으로 분리한다. ABC 비교 화면 자체는 구매·지급·저장·의상·반응을 실행하지 않는다. 실제 게임은 선택한 최종6종을 사용한다. 승인된 3종의 기존 의상·모션과 다른 캐릭터는 유지한다.

웹 개발 서버 `http://localhost:5180/?preview=friends&review=abc`, 앱 개발 경로 `/friend-identity-review` 또는 기존 친구 미리보기의 ‘친구 개성 A/B/C 비교’에서 연다. 캐릭터별 A/B/C와 같은 안의 6종, 같은 파스텔/실제 홈 배경, 200/180/110/64/40px을 비교한다. SVG 원본 비율을 유지하며 비교 화면은 게임 저장·출석 초기화를 실행하지 않는다. 네이티브 실기기 시각 확인은 미확인이다.

| 친구 | B: 눈·표정 | C: 추가 체형·자세 |
|---|---|---|
| 밀루 | 편안한 둥근 눈·큰 원형 빛과 작은 타원 빛·넉넉한 미소 | 통통한 몸·배 앞의 두 손 |
| 라니 | 또렷한 세로 눈·길쭉한 빛·작게 열린 웃음 | 한쪽 앞발 인사, 처진 귀와 머리 장식 유지 |
| 루루 | 가로 눈·부드러운 눈꼬리·곡선 빛·작은 미소 | 모은 앞발·가까이 말린 꼬리 |
| 메루 | 살짝 처진 세로 눈·좁고 긴 빛·쑥스러운 입 | 모은 앞발·조금 긴 몸과 다리 |
| 도토 | 작은 둥근 눈·넓은 간격·작은 원형 빛·엉뚱한 입 | 짧고 통통한 몸·작은 발 |

## 최종 6종과 상점 연결

기존6종에 밀루·라니·루루·포포·메루·도토를 추가한 실제 상품12종이다. 기존 ID를 유지하며 A/B/C는 별도 상품이 아니다. 레벨 달성은 구매만 열고 자동 지급·자동 선택하지 않는다. 미구현8종은 상품에 없으며 LV30~100 조건은 미정이다.

| 친구 / ID | 최종 외형 | 구매 LV | 코인 | 활동3개 기준 가격에 해당하는 수입 일수 | 해금일 예시: 3개 / 6개 |
|---|---|---:|---:|---:|---|
| 밀루 / proto-pebble | B | 4 | 120 | 1.6일 | 6일 / 5일 |
| 라니 / proto-pear | A | 7 | 150 | 2일 | 13일 / 10일 |

| 메루 / draft-deer | A, 장식 점무늬만 제거 | 20 | 350 | 약4.7일 | 42일 / 31일 |

메루의 눈 하이라이트·코·볼·주둥이는 유지한다. B 외형에 C 체형을 섞지 않는다. FinalPrototypeFriendDrawing/FinalExpansionFriendDrawing은 선택한 원본 도형을 사용한다. 과거 기본/ABC 원본은 비교용 파일에 보존한다. 몸통·팔 경계 clipPath, 꼬리→몸/옷→발/팔/소매→머리/얼굴 순서, 기존4종 의상, 깜빡임·터치/키보드·실제 완료/새 의상 축하·동작 줄이기를 웹/앱 어댑터에서 연결한다. 탈의와 종료는 기본 도형으로 돌아온다.

상점은 LV순이며 일반 잠금 친구의 외형·이름·성격·소개·가격·필요 LV를 공개한다. 레벨 미달/코인 부족/구매 가능/보유 중/함께하는 중을 구분한다. 구매는 기존 buyCharacter로 1회 차감하고 저장 성공 후 환영 카드·‘함께하기’를 표시한다. 구매만으로 선택하지 않는다. 다음 레벨 친구를 짧게 안내한다. 목표 선택 기능은 없다. 홈·상점·작은 아바타·이웃에서 같은 렌더러를 사용하고 애칭은 기존 nicknames의 ID별 저장을 유지한다.

### 가격 산정과 진행 예시

현재 고정3+활동3 구조를 확인했다. 활동 1개=15XP/25코인, 처음 수행하는 활동에는5XP 추가. 일기=15XP/25코인, 방명록=0(정책 대기), 출석은 기존 랜덤 지급만(코인10/20/30, XP5/8/10, 의상·소품 후보 및 중복30코인 대체). 과거 전역3회 한도를 가격 산정에 사용하지 않았다. 현재 활동은 하루3슬롯의1회 지급이고 일기/출석은 각 원장으로 별도 중복 방지한다. 레벨=1+floor(XP/100), 시작90코인/시연540코인, 주간30XP·30코인 및 월간60XP·60코인도 변경하지 않았다. 의상120~300, 가구90~520, 기존 구매 친구300/450/600과 비교해 초반120~150, 후반300~375로 정했다.

표의3개=매일 활동3개(45기본XP/75코인); 6개=활동3+출석+일기+방명록(60기본XP/100코인+출석). 6개 예시는 출석이 매일20코인인 유효한 예시이며 기대값/보장값이 아니다. 실제 출석에 따라 해당 날짜 코인 추가는0~30이고 XP·아이템을 받을 수도 있다. `node scripts/simulate-friend-economy.mjs`로 실제 날짜 선정·처음 수행XP·원장을 적용해 계산했다. 신규XP0/90코인, 2026-10-08 시작, 소비 없음, 주월 보상 청구 없음, 미션 교체/반복 보상 없음이 가정이다. 주월 청구/출석XP/수행구성에 따라 달라진다. 표의 가격 일수는 해금 후 잔액0에서 활동3개 수입을 모으는 기준이며 해금 소요와 다르다. 같은 계산의 누적 코인(초기90포함)은 밀루 해금 때3개540/6개690, 도토 해금 때3개4065/6개4890이다. 해금 전 저축하면 바로 살 수 있다. 기존 공식을 유지하므로 LV25까지 수입이 많이 쌓이는 특성은 남으며 임의로 회수·보상 축소하지 않는다. 예방 효과가 검증된 수치가 아니다.

### 저장·서버 범위와 검증

새 키/일괄지급/자산 이관 없이 기존 game.characters/character/nicknames 및 옷장 키를 사용한다. XP·코인·과거 완료·의상·가구·배치는 보존한다. 기존 무료 감자/토끼/펭귄 조건은 유지한다. 웹은 localStorage, 앱은 AsyncStorage의 기존 저장 성공 경로를 사용한다. 실제 서버 상점 연동은 없다. backend/app/data/shop.json은 기존6종뿐이므로 서버 팀에 동일ID·레벨·가격 등록과 인증 구매/장착 연결이 필요하다. 이번에 backend나 API 계약은 수정하지 않았다.

임시 Edge 프로필에서 선택6종과 최종 SVG 도형 일치, 4의상×6종, 탈의, 고유 clip ID, 실제 구매/빠른중복클릭/자동교체 없음/선택 후 재접속/기존자산, 저장실패 시 환영 없음, 실제 활동 완료 후 홈 축하1회, 의상 축하, 깜빡임·터치·Enter·연타·모션 줄이기·360/390/430 폭을 확인했다. ‘내가 남긴 글 → 그 집 방명록 보기’는 ui-secondary 둥근44px 버튼으로 통일했고 실제 이동을 검사했다. 앱도 공통 Button을 사용한다. 웹 build와 모바일 lint/typecheck/export, 규칙 테스트 결과는 검증 절을 따른다. 실제 iPhone/Android의 의상·모션·키보드·터치는 미확인이다.
