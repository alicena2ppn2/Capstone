작성/정보 확인: 2026-10-17. 정식 기능·모바일 네이티브 기능이 아닌 독립된 React 웹 시안이다. 기존 앱의 인증, 게임 상태, 저장 키, 화면 라우트는 수정하지 않는다.

## 열기

`frontend/`에서 `npm run dev -- --port 5180 --strictPort` 실행 후:

- 비교 프레임: http://localhost:5180/dev/exploration/
- 최상위 체험 화면: http://localhost:5180/dev/exploration/app.html
- 선택된 A안 전용 간결 시안: `C:\dev\MY-MOCHI\.worktrees\gps-exploration\frontend`에서 `npm.cmd run dev -- --host localhost --port 5190 --strictPort` 실행 후 `http://localhost:5190/dev/exploration/a.html` (390×844 프레임), `/dev/exploration/a-app.html` (직접 화면)

비교 프레임은 390×844 CSS px iframe을 같은 비율로 축소한다. 실제 기기 에뮬레이터가 아니다. A안에는 웹 전용 카카오 지도·브라우저 위치 권한·카카오 장소 검색이 있다. B/C와 네이티브 앱은 예시 지도만 사용한다. 서버·실제 보상·포스트잇 공유는 연결하지 않는다. 정식 앱은 이 시안을 import하지 않는다.

## 3안 비교

| 안 | 사용 순서 | 장점 | 검토할 제한 |
|---|---|---|---|
| A 모찌와 동네 탐험 | 지도 → 장소 → 바텀시트 → 도착/메모 | 캐릭터 이동과 자유 탐색이 잘 보임 | 지도 읽기가 익숙하지 않으면 시작할 곳이 불명확할 수 있음 |
| B 오늘의 작은 외출 | 장소 카드 선택 → 지도/거리 → 도착 확인 → 보상/메모 | 목적지 하나와 다음 행동이 명확함 | 자유 탐험의 느낌이 A보다 적고 목적지 선택이 추가됨 |
| C 동네 포스트잇 | 글 미리보기 → 장소 → 도착 후 읽기/쓰기, 지도 전환 | 장소에 머문 기록이 탐험 동기가 됨 | 실제 공유 서비스로 발전시키려면 운영·신고·차단·개인정보 정책이 필요 |

**현재 선택:** A안 ‘모찌와 동네 탐험’. 예시 위치 모드는 `SampleMap.jsx`를 쓰고, 실제 지도 모드는 `KakaoLiveMap.jsx`·`placeSearch.mjs`·`livePlaceMarkers.mjs`·`livePlaces.mjs`에서 관리한다. 실제 지도에는 선택한 캐릭터의 내 위치 마커와 카카오 장소 검색 결과를 좌표 오버레이로 표시한다. 장소 아이콘을 누르면 하단 상세 카드, 선택한 장소의 쪽지 아이콘을 누르면 포스트잇 시안이 열린다. `PreviewPostit.jsx`로 두 모드가 같은 종이 디자인을 사용한다. 지도 키가 없으면 실제 위치 연결 버튼을 비활성화한다.

기존 세 고정 장소는 이전 시안의 쪽지와 데이터 호환을 위해 `livePlaces.mjs`에 남겨 두었지만 **실제 지도 마커 목록으로 사용하지 않는다.** 실제 마커에는 카카오 검색 응답의 장소 ID·이름·좌표만 사용한다. 검색 반경은 처음 1km이며 결과가 없으면 사용자가 2km 확대를 선택할 수 있다. 첫 페이지 결과를 종류별로 모아 ID 중복을 제거하고 최대 10곳을 보여 준다. 카테고리 탭은 이미 받은 결과를 필터링하며 추가 요청을 보내지 않는다. 가까이 겹친 마커는 한 개로 묶고 이름은 선택한 장소에만 표시한다. 위치 갱신·지도 이동·재진입으로 자동 검색하지 않는다. 사용자가 ‘이 지역 둘러보기’를 눌러 현재 지도 중심에서 검색하거나 ‘서울 예시 지역 검색’을 선택할 때만 요청한다. 같은 범위의 중복 요청과 검색 중 추가 요청은 막는다. 내 위치가 없을 때 서울 예시 지역에서 검색을 시험할 수 있지만, 이 지역을 내 주변이라고 표시하지 않는다.

카카오 [장소 검색 문서](https://apis.map.kakao.com/web/documentation/)에 따라 문화시설 `CT1`·카페 `CE7`은 `categorySearch`, 공원·도서관은 각각 ‘공원’·‘도서관’ `keywordSearch`를 사용한다. 네 검색 모두 중심 좌표와 반경을 명시한다. 장소 검색은 기존 JavaScript 키에 `libraries=services`를 추가해 사용한다. 새 REST 키나 Client Secret은 필요하지 않다. 검색 쿼터·권한이 제한된 경우에는 카카오 앱 설정에서 Maps 사용 여부를 확인해야 한다.

**무료 사용 범위:** 비즈월렛 연결·결제수단 등록·유료 API 활성화를 진행하지 않는다. 카카오의 [현재 지도 이용 정책](https://developers.kakao.com/docs/ko/kakaomap/common)에 따르면 개발자 계정에서 첫 번째로 활성화한 지도 앱에만 무료 쿼터가 제공될 수 있다. 콘솔에서 해당 앱의 ‘카카오맵 무료 쿼터’ 표시와 사용량을 직접 확인해야 하며, 시안 코드만으로 무료 대상임을 보증할 수 없다. Maps JavaScript SDK의 장소 검색 콜백은 `OK`·`ZERO_RESULT`·일반 `ERROR`만 제공해 쿼터 초과를 다른 오류와 확정적으로 구분하지 못한다. 따라서 일부 또는 전체 검색이 실패하거나 10초 동안 응답이 없으면 해당 화면에서 추가 검색을 차단하고 자동 재시도하지 않으며 사용량 확인 안내를 보여 준다. 한 번의 명시적 전체 검색은 네 종류 각각 첫 페이지만 요청하고 추가 페이지를 자동 조회하지 않는다.

쪽지 샘플은 실제 주민 글이 아닌 창작 예시다. 새로 검색된 장소에는 기본 예시 글을 붙이지 않고 ‘아직 쪽지가 없어요’로 표시한다. 기존 서울 장소에 대응하는 검색 결과에서만 이전 창작 예시와 이전 시안 글을 확인할 수 있다. 새 쪽지는 `localStorage['my-mochi:dev:exploration:live-place-notes:v1']`에 **카카오 장소 ID**·본문·종이색·스티커·작성일만 저장한다. 이전 시안의 고정 장소 ID로 저장한 글도 이름과 위치가 일치하는 장소에서 읽을 수 있다. 계정/위치/게임 저장 데이터는 읽거나 쓰지 않는다. 글 삭제는 이 기기의 글에만 제공한다. 하트 반응은 이 화면의 임시 상태다. 포스트잇 본문은 React 텍스트로 표시하고 HTML로 해석하지 않는다.

### 방문 전 미리보기와 발견한 쪽지

장소 카드에는 검색된 장소 이름과 이 시안에서 확인 가능한 쪽지 수를 표시한다. 방문 전에는 새 쪽지 본문과 새 글 등록을 잠그지만 이미 이 기기에서 발견하거나 직접 작성한 쪽지는 다시 읽을 수 있다. 도착 후 쪽지를 하나씩 열면 장소 ID·쪽지 ID·모의/기기 위치 구분만 `localStorage['my-mochi:dev:exploration:discovered-notes:v1']`에 보존한다. 작성 중 내용은 장소 ID별 `localStorage['my-mochi:dev:exploration:note-drafts:v1']`에 따로 보존하고, 위치가 불확실해져도 지우지 않는다. 등록 시 현재 위치 조건을 다시 확인한다. 실제 계정·재화·서버에는 쓰지 않는다. 나중에 새 쪽지가 생겨도 발견 이력이 없는 ID는 잠긴다.

`arrivalGate.mjs`의 **시안용** 기준은 카페 50m, 도서관·문화시설 60m이고, 장소 ID별 반경을 따로 지정할 수 있는 설정을 분리했다. 최근 15초 이내이고 정확도 30m 이하인 **서로 다른 두 측정**이 반경 안에 들어와야 도착으로 본다. 반경 밖으로 25m 더 벗어난 서로 다른 두 측정 후 잠근다. 정확도가 낮다고 반경을 넓히지 않으며, 오래된 측정·권한 거부·실패는 미도착과 구분한다. 넓은 공원은 검색 결과 좌표가 입구라고 검증되지 않았으므로 실제 기기 위치만으로 자동 해제하지 않는다. 개발 시안의 ‘도착 전 / 도착 / 위치 부정확’ 조작은 선택한 장소에만 적용되는 메모리 상태이며 실제 GPS 방문 기록을 만들지 않는다. 모의 도착으로 발견한 글은 시안 저장소에 `simulation`으로 구분한다.

이 잠금은 **프론트 시연용 화면 상태**다. 실제 서버의 장소 방문 인증이나 쪽지 접근 권한 검증을 대신하지 않는다. 정식 서비스에서 위치 위조 방지·도착 판정·게시물 권한을 제공하려면 서버 계약과 운영 정책이 필요하다.

모의 상태에서 발견·작성한 새 쪽지는 `simulation`, 브라우저 위치로 발견·작성한 새 쪽지는 `device-preview`로 구분하여 서로의 새 기록을 열지 않는다. 이전 버전의 로컬 작성 글은 호환을 위해 두 모드 모두에서 볼 수 있다. 두 기록 모두 서버의 실제 방문 기록은 아니다.

### 실제 지도 개발 설정

1. `frontend/.env.local`에 `VITE_KAKAO_MAP_JS_KEY`를 설정한다. `frontend/.env.local`은 Git 제외 대상이다. 이 웹 지도에는 Kakao Developers의 **JavaScript 키**만 사용한다. 로그인용 REST 키와 Client Secret은 사용하지 않는다.
2. Kakao Developers에서 앱의 `[카카오맵] > [사용 설정]`을 켠다.
3. `[앱] > [플랫폼 키] > [JavaScript 키] > [JavaScript SDK 도메인]`에 현재 로컬 미리보기 출처를 등록한다. 현재 고정 포트는 `http://localhost:5190`이다. 장소 검색은 같은 Maps JavaScript SDK의 `services` 라이브러리를 쓰며 별도 REST 키를 앱에 넣지 않는다.
4. `frontend/`에서 `npm run dev -- --host localhost --port 5190 --strictPort`를 실행하고 `/dev/exploration/a.html`을 연다.

위치 권한은 사용자가 실제 위치 모드에서 직접 ‘내 위치로 시작’을 눌렀을 때 요청한다. 브라우저 위치 API는 HTTPS 또는 localhost 같은 보안 컨텍스트에서만 동작한다. 위치가 거부되거나 실패해도 서울 예시 지역의 실제 장소 검색을 체험할 수 있다. 위치 변화는 캐릭터 지도 마커와 사용자가 따라가기를 켠 경우의 지도 중심에만 반영한다. 지도 드래그 시 따라가기를 멈추고, ‘내 위치’ 버튼으로 다시 따라간다. 화면을 닫거나 예시 모드로 돌아가면 `clearWatch`로 위치 구독을 종료하고, 브라우저 탭이 숨겨져도 구독을 멈춘다. 정확도 100m 초과 또는 마지막 측정 30초 초과 상태는 별도로 알린다. 이 임계값은 표시용 상태 기준이지 도착 판정 정책이 아니다. 기본 ROADMAP 타일의 색과 글자는 SDK의 일반 스타일 옵션으로 변경하지 않는다. 커스텀 장소 오버레이만 꾸미며 카카오 로고와 출처 영역은 덮지 않는다.

## 공통 데이터와 상태

- `model.mjs`의 가상 공공 공원·공공 도서관·공공 광장 3곳과 고정 산책 순서를 공유한다. 좌표는 가상 평면의 미터 단위이며 실제 위경도가 아니다. 거리도 가상 평면의 직선거리다. 점선은 예시 이동 순서이며 실제 보행 경로·소요시간을 뜻하지 않는다.
- `POLICY`: 반경35m, 정확도20m 이하, 최근15초 내 서로 다른 두 측정값. **전부 시안용 값이며 확정 정책이 아니다.** 범위 안 측정이 있어도 직접 도착 확인을 누르기 전에는 방문/보상이 생기지 않는다.
- 최근 위치/정확도 부족은 ‘측정 상황’으로 체험한다. ‘도착 상황 보기’는 선택한 장소(미선택이면 첫 장소)로 예시 위치만 옮긴다. 글 작성은 도착 확인 후 열리며 보상 수령의 조건이 아니다.
- 예시 보상: 장소별20코인·10XP·스티커 이름. 실제 게임 재화나 아이템을 지급하는 코드가 없고 시안 내부의 방문/확인 여부만 기록한다. 반복 클릭·재진입으로 같은 안/장소의 확인이 중복되지 않는다.
- 저장: `sessionStorage['my-mochi.dev.exploration.v1']`. A/B/C 각각 방문·보상 확인·작성한 글을 구분한다. 같은 탭 새로고침에 유지되고 개발용 초기화로 해당 안만 지울 수 있다. 브라우저/탭 종료 시 보존은 보장하지 않는다. 실제 게임의 localStorage/IndexedDB, 로그인 저장소에는 접근하지 않는다.
- 샘플 글은 ‘시연 메모’, 본인 입력은 ‘내 예시 글·이 브라우저’로 구분한다. 날짜·현재 위치·이동 경로를 글에 첨부하거나 공개하지 않는다. 공유·전달·신고 접수 기능은 없다. 내 예시 글 삭제만 제공한다.
- 기존 승인 SVG 렌더러와 캐릭터 목록을 읽기 전용으로 재사용한다. 선택은 시안 전용이며 실제 보유·장착 상태를 읽거나 바꾸지 않는다. 지도 원화/핀을 memo로 유지하고 위치 변경은 캐릭터 마커의 위치와 거리/도착 상태에 반영한다. 지도 드래그/방향 버튼 후 자동 따라가기가 꺼지고 ‘내 위치’로 복귀한다. 모션 줄이기에서는 이동 transition을 끈다.

## 이번 범위에서 보류한 항목

실제 도착 판정·GPS 기반 걷기 판정·게임 보상·포스트잇 서버 저장/공유·신고/차단·백그라운드 위치 추적·네이티브 지도는 구현하지 않았다. 검색은 공식 카카오 장소 응답의 첫 페이지만 사용하는 개발 시안이며 정식 서비스의 호출량·검색 대상·장소 검수 기준은 미정이다. 실제 기기에서의 위치 정확도와 권한 UX는 별도 검증이 필요하다. 프론트 위치 값만으로 실제 방문이나 위치 위조 방지를 입증할 수 없다.

## 정식 적용 전 팀 합의/구현

**프론트:** 현재 시안의 주변 검색 범위와 표시 수 검토, 도착 요청/결과 표시, 서버 지급 결과만 반영, 포스트잇 서버 목록/작성/삭제/신고/차단과 실패·재시도 UI. 네이티브는 별도 지도·위치 어댑터가 필요하다.

**백엔드/운영:** 검토된 장소 ID와 좌표 관리, 도착 판정/정확도·최근성 정책, 인증 사용자 기준의 멱등 지급과 지급 이력, 보상표/아이템 중복 대체, 재방문 지급 주기와 서울 날짜 경계, 호출 제한·위치 위조 대응 수준, 최소 위치 수집/보관/삭제 정책, 공개 글 검토·신고·차단·악용 방지·개인정보 삭제. 프론트 거리 판정만으로 위치 위조를 방지하거나 실제 방문을 입증할 수 없다.

개인 주거지·임의 개인 좌표 게시, 작성자 실시간 위치/경로 공개는 대상에서 제외한다. 메모를 쓰지 않아도 도착 보상을 받을 수 있게 유지한다. 실제 서비스 전 수집 목적·동의·노출 범위와 운영 책임을 확정해야 한다.

## 확인 범위

기존 A/B/C 가상 시안의 장소 선택·예시 도착·쪽지 흐름은 앞선 개발 시안 확인 대상이었다. 2026-10-17 변경의 실제 지도 모드는 개발 서버의 HTML/JSX 모듈 응답과 Vite 변환, 위치·검색·도착 판정·발견/초안 저장 처리 테스트를 확인했다. 현재 브라우저 자동 조작이 연결되지 않아 카카오 타일과 실제 장소 검색 결과 표시, 장소 아이콘 클릭→쪽지 열기→글 작성, GPS 권한 허용/거부 화면을 직접 눌러 확인하지 못했다. 무료 쿼터 적용 앱인지도 콘솔에서 확인하지 못했다. 실기기·서버·네이티브 검증도 수행하지 않았다.
