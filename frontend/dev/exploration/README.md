# 위치 기반 탐험 · 개발 전용 비교 시안

작성/정보 확인: 2026-10-17. 정식 기능·모바일 네이티브 기능이 아닌 독립된 React 웹 시안이다. 기존 앱의 인증, 게임 상태, 저장 키, 화면 라우트는 수정하지 않는다.

## 열기

`frontend/`에서 `npm run dev -- --port 5180 --strictPort` 실행 후:

- 비교 프레임: http://localhost:5180/dev/exploration/
- 최상위 체험 화면: http://localhost:5180/dev/exploration/app.html
- 선택된 A안 전용 간결 시안: `C:\dev\MY-MOCHI\.worktrees\gps-exploration\frontend`에서 `npm.cmd run dev -- --host localhost --port 5190 --strictPort` 실행 후 `http://localhost:5190/dev/exploration/a.html` (390×844 프레임), `/dev/exploration/a-app.html` (직접 화면)

비교 프레임은 390×844 CSS px iframe을 같은 비율로 축소한다. 실제 기기 에뮬레이터가 아니다. A안에는 웹 전용 카카오 지도와 브라우저 위치 권한 흐름이 있다. 검토용 실제 장소 3곳의 고정 좌표를 표시하지만 주변 장소 검색 API는 연결하지 않았다. B/C와 네이티브 앱은 예시 지도만 사용한다. 서버·실제 보상·포스트잇 공유는 연결하지 않는다. 정식 앱은 이 시안을 import하지 않는다.

## 3안 비교

| 안 | 사용 순서 | 장점 | 검토할 제한 |
|---|---|---|---|
| A 모찌와 동네 탐험 | 지도 → 장소 → 바텀시트 → 도착/메모 | 캐릭터 이동과 자유 탐색이 잘 보임 | 지도 읽기가 익숙하지 않으면 시작할 곳이 불명확할 수 있음 |
| B 오늘의 작은 외출 | 장소 카드 선택 → 지도/거리 → 도착 확인 → 보상/메모 | 목적지 하나와 다음 행동이 명확함 | 자유 탐험의 느낌이 A보다 적고 목적지 선택이 추가됨 |
| C 동네 포스트잇 | 글 미리보기 → 장소 → 도착 후 읽기/쓰기, 지도 전환 | 장소에 머문 기록이 탐험 동기가 됨 | 실제 공유 서비스로 발전시키려면 운영·신고·차단·개인정보 정책이 필요 |

**현재 선택:** A안 ‘모찌와 동네 탐험’. 예시 위치 모드는 `SampleMap.jsx`를 쓰고, 실제 지도 모드는 `KakaoLiveMap.jsx`·`livePlaceMarkers.mjs`·`livePlaces.mjs`에서 관리한다. 실제 지도에는 선택한 캐릭터의 내 위치 마커와 고정된 서울 장소 3곳의 좌표 오버레이를 표시한다. 장소 아이콘을 누르면 하단 상세 카드, 쪽지 아이콘을 누르면 포스트잇 시안이 열린다. `PreviewPostit.jsx`로 두 모드가 같은 종이 디자인을 사용한다. 지도 키가 없으면 실제 위치 연결 버튼을 비활성화한다.

서울도서관·서울광장·남산공원은 실제 장소다. 이름·위치는 [서울도서관](https://lib.seoul.go.kr/), [서울광장](https://plaza.seoul.go.kr/), [서울시 남산공원 안내](https://english.seoul.go.kr/%EA%B3%B5%EC%9B%90/?pidx=24&sub=2)로 확인했고, 표시 좌표는 `livePlaces.mjs`에 각 좌표 출처와 함께 기록했다. 넓은 장소의 참고 좌표이며 입구, 정확한 방문 지점이나 도착 반경이 아니다. 서울도서관·서울광장이 멀리서 겹칠 때는 `2곳`으로 묶고 확대하면 각각 표시한다. 사용자의 주변에 등록 장소가 없으면 서울 검토 지역으로 이동할 수 있다. 예시 지역 이동은 현재 위치를 바꾸지 않는다.

쪽지 샘플은 실제 주민 글이 아닌 창작 예시다. 새 쪽지는 `localStorage['my-mochi:dev:exploration:live-place-notes:v1']`에 장소 ID·본문·종이색·스티커·작성일만 저장한다. 계정/위치/게임 저장 데이터는 읽거나 쓰지 않는다. 글 삭제는 이 기기의 글에만 제공한다. 하트 반응은 이 화면의 임시 상태다. 포스트잇 본문은 React 텍스트로 표시하고 HTML로 해석하지 않는다.

### 실제 지도 개발 설정

1. `frontend/.env.local`에 `VITE_KAKAO_MAP_JS_KEY`를 설정한다. `frontend/.env.local`은 Git 제외 대상이다. 이 웹 지도에는 Kakao Developers의 **JavaScript 키**만 사용한다. 로그인용 REST 키와 Client Secret은 사용하지 않는다.
2. Kakao Developers에서 앱의 `[카카오맵] > [사용 설정]`을 켠다.
3. `[앱] > [플랫폼 키] > [JavaScript 키] > [JavaScript SDK 도메인]`에 현재 로컬 미리보기 출처를 등록한다. 현재 고정 포트는 `http://localhost:5190`이다.
4. `frontend/`에서 `npm run dev -- --host localhost --port 5190 --strictPort`를 실행하고 `/dev/exploration/a.html`을 연다.

위치 권한은 사용자가 실제 위치 모드에서 직접 ‘내 위치로 시작’을 눌렀을 때 요청한다. 브라우저 위치 API는 HTTPS 또는 localhost 같은 보안 컨텍스트에서만 동작한다. 위치가 거부되거나 실패해도 서울 검토 지역의 지도를 둘러볼 수 있다. 위치 변화는 캐릭터 지도 마커와 사용자가 따라가기를 켠 경우의 지도 중심에만 반영한다. 지도 드래그 시 따라가기를 멈추고, ‘내 위치’ 버튼으로 다시 따라간다. 화면을 닫거나 예시 모드로 돌아가면 `clearWatch`로 위치 구독을 종료하고, 브라우저 탭이 숨겨져도 구독을 멈춘다. 정확도 100m 초과 또는 마지막 측정 30초 초과 상태는 별도로 알린다. 이 임계값은 표시용 상태 기준이지 도착 판정 정책이 아니다. 기본 ROADMAP 타일의 색과 글자는 SDK의 일반 스타일 옵션으로 변경하지 않는다. 커스텀 장소 오버레이만 꾸미며 카카오 로고와 출처 영역은 덮지 않는다.

## 공통 데이터와 상태

- `model.mjs`의 가상 공공 공원·공공 도서관·공공 광장 3곳과 고정 산책 순서를 공유한다. 좌표는 가상 평면의 미터 단위이며 실제 위경도가 아니다. 거리도 가상 평면의 직선거리다. 점선은 예시 이동 순서이며 실제 보행 경로·소요시간을 뜻하지 않는다.
- `POLICY`: 반경35m, 정확도20m 이하, 최근15초 내 서로 다른 두 측정값. **전부 시안용 값이며 확정 정책이 아니다.** 범위 안 측정이 있어도 직접 도착 확인을 누르기 전에는 방문/보상이 생기지 않는다.
- 최근 위치/정확도 부족은 ‘측정 상황’으로 체험한다. ‘도착 상황 보기’는 선택한 장소(미선택이면 첫 장소)로 예시 위치만 옮긴다. 글 작성은 도착 확인 후 열리며 보상 수령의 조건이 아니다.
- 예시 보상: 장소별20코인·10XP·스티커 이름. 실제 게임 재화나 아이템을 지급하는 코드가 없고 시안 내부의 방문/확인 여부만 기록한다. 반복 클릭·재진입으로 같은 안/장소의 확인이 중복되지 않는다.
- 저장: `sessionStorage['my-mochi.dev.exploration.v1']`. A/B/C 각각 방문·보상 확인·작성한 글을 구분한다. 같은 탭 새로고침에 유지되고 개발용 초기화로 해당 안만 지울 수 있다. 브라우저/탭 종료 시 보존은 보장하지 않는다. 실제 게임의 localStorage/IndexedDB, 로그인 저장소에는 접근하지 않는다.
- 샘플 글은 ‘시연 메모’, 본인 입력은 ‘내 예시 글·이 브라우저’로 구분한다. 날짜·현재 위치·이동 경로를 글에 첨부하거나 공개하지 않는다. 공유·전달·신고 접수 기능은 없다. 내 예시 글 삭제만 제공한다.
- 기존 승인 SVG 렌더러와 캐릭터 목록을 읽기 전용으로 재사용한다. 선택은 시안 전용이며 실제 보유·장착 상태를 읽거나 바꾸지 않는다. 지도 원화/핀을 memo로 유지하고 위치 변경은 캐릭터 마커의 위치와 거리/도착 상태에 반영한다. 지도 드래그/방향 버튼 후 자동 따라가기가 꺼지고 ‘내 위치’로 복귀한다. 모션 줄이기에서는 이동 transition을 끈다.

## 이번 범위에서 보류한 항목

실제 도착 판정·GPS 기반 걷기 판정·게임 보상·주변 장소 검색·포스트잇 서버 저장/공유·신고/차단·백그라운드 위치 추적·네이티브 지도는 구현하지 않았다. 주변 장소를 동적으로 찾으려면 카카오 지도 장소 검색 서비스 라이브러리 또는 별도 서버 장소 API의 범위·호출량·검수 기준을 먼저 정해야 한다. 현재 세 장소는 고정된 검토용 목록이다. 실제 기기에서의 위치 정확도와 권한 UX는 별도 검증이 필요하다. 프론트 위치 값만으로 실제 방문이나 위치 위조 방지를 입증할 수 없다.

## 정식 적용 전 팀 합의/구현

**프론트:** 개발 시안의 검토용 고정 장소에서 정식 장소 데이터로 전환, 주변 검색 범위와 표시 수 결정, 도착 요청/결과 표시, 서버 지급 결과만 반영, 포스트잇 서버 목록/작성/삭제/신고/차단과 실패·재시도 UI. 네이티브는 별도 지도·위치 어댑터가 필요하다.

**백엔드/운영:** 검토된 장소 ID와 좌표 관리, 도착 판정/정확도·최근성 정책, 인증 사용자 기준의 멱등 지급과 지급 이력, 보상표/아이템 중복 대체, 재방문 지급 주기와 서울 날짜 경계, 호출 제한·위치 위조 대응 수준, 최소 위치 수집/보관/삭제 정책, 공개 글 검토·신고·차단·악용 방지·개인정보 삭제. 프론트 거리 판정만으로 위치 위조를 방지하거나 실제 방문을 입증할 수 없다.

개인 주거지·임의 개인 좌표 게시, 작성자 실시간 위치/경로 공개는 대상에서 제외한다. 메모를 쓰지 않아도 도착 보상을 받을 수 있게 유지한다. 실제 서비스 전 수집 목적·동의·노출 범위와 운영 책임을 확정해야 한다.

## 확인 범위

기존 A/B/C 가상 시안의 장소 선택·예시 도착·쪽지 흐름은 앞선 개발 시안 확인 대상이었다. 2026-10-17 변경의 실제 지도 모드는 개발 서버의 HTML/JSX 모듈 응답과 Vite 변환, 위치 처리 테스트 8개, 검토 장소 데이터와 시안 전용 로컬 저장 왕복을 확인했다. 현재 브라우저 자동 조작이 연결되지 않아 카카오 타일의 실제 표시, 장소 아이콘 클릭→쪽지 열기→글 작성, GPS 권한 허용/거부 화면을 직접 눌러 확인하지 못했다. 실기기·서버·네이티브 검증도 수행하지 않았다.
