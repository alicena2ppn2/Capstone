## 1. 의도와 구현 범위

### 신규 친구 디자인 검토 범위 (2026-10-07)

정식 캐릭터는 기존 6종을 유지한다. 조약돌 누비(`proto-pebble`), 배꽃 포리(`proto-pear`), 물결 소솜(`proto-quilt`) 3종은 별도의 PROTOTYPE_FRIENDS 데이터와 SVG로 구현한 개발용 시안이다. 이름·성격·좋아하는 것·작은 습관·소개·눈 중심·반응 크기는 prototypeFriends.js에 분리한다. 각각 낮고 넓은 조약돌, 세로 배 모양, 물결 쿠션 몸체·얼굴·의상 목선/팔다리가 다르다. 체형 경로 clipPath 안에 기존 의상 색/무늬를 적용하며 눈 전체 그룹 깜빡임·터치/키보드 하트·축하 반짝이를 연결한다. 이는 서로 독립된 친구이며 기존 캐릭터의 진화가 아니다.

웹 개발 실행 `?preview=friends`는 App 대신 FriendPreview만 마운트한다. 기본 3종·의상 12조합·실제 Home 360/390/430px·상점 카드·40/64px 프로필·반응 시연을 제공한다. 앱 `/friend-preview`는 Expo Router의 별도 경로로 GameApp을 우회하며 같은 SVG의 네이티브 변환과 홈과 동일한 방 비율/캐릭터 크기 규칙을 사용한다. 앱 개발 모드에서만 시안 내용을 표시한다. 선택·의상·반응 상태는 메모리에서만 유지하고 저장·구매·자동 지급·출석 보상은 호출하지 않는다. 실제 퀘스트 완료를 발생시키는 버튼이 아니라 성공 반응을 시연한다. 일반 게임 이벤트 렌더러에도 신규 ID 분기를 준비하되 실제 지급/장착 경로는 열지 않는다. 레벨/가격/전체 수는 미확정이다. 참고 이미지 Poc1.webp, poc2.webp, poc3.webp, poc4.webp, poc5.jpg, POC6.jpeg, POC7.jpg는 직접 확인했고 배색/분위기만 참고했다.

현실의 작은 외출·교류 도전 → XP·코인 → 독립된 친구 수집·옷·집 꾸미기 → 캐릭터 반응의 흐름이다. 세 카테고리를 매일 모두 수행하도록 강제하지 않는다. 결석·미완료 벌점, 강제 진화, 친밀도 감소, 심리 상태 진단은 없다.

주 모바일 프론트는 `mobile/`의 Expo SDK 57 / React Native 0.86.3 / React 19.2.3이며 Expo Router·네이티브 View/Text/Pressable/ScrollView/Modal·react-native-svg·AsyncStorage로 구현한다. 기존 React/Vite 웹은 `frontend/`에 유지하며 localStorage를 사용한다. 게임 데이터와 계산은 `frontend/src/utils`를 두 프론트가 공유한다. 실제 계정·서버·활동 인증·AI·GPS·건강 앱은 연결하지 않는다. 이웃은 샘플 데이터이며 글·반응을 상대에게 전달하지 않는다.

### 모바일 구현과 범위

홈·도전/기록/취향·주/월 집계·상점/컬렉션/옷/소품·출석·설정·샘플 이웃/방명록을 네이티브 UI로 연결한다. 보상량·가격·해금·저장 기록의 규칙은 공유 계산으로 유지한다. 기존 여섯 캐릭터·가구·풍경 SVG 도형과 clipPath를 유지하며 CSS 반응은 Animated/AppState/AccessibilityInfo로 옮긴다. 앱 비활성/이탈 시 모션 정리, 모션 줄이기, 반복 터치 차단, 보상과 새 의상 반응 1회 소비를 지원한다. 구매만으로 착용/축하하지 않는다.

화면은 실제 OS SafeArea/상태 바를 사용하며 기기 장식 프레임은 없다. 홈은 이름 밑 LV/XP와 방 중심 배치, 노랑 방문/분홍 방명록·굵은 라벨, 하단 도전/꾸미기를 유지한다. 반응형 폭과 자연스러운 세로 스크롤, 44px 이상 주요 터치 영역, 기기 키보드 회피를 적용한다. 네이티브 상세 펼침은 Pressable과 Modal로 구현하며 웹 details/CSS는 사용하지 않는다. 글꼴은 번들 에이투지체 Regular/Medium/SemiBold, fallback은 OS 글꼴이다. 실제 기기·브라우저에서 시각/키보드/모션/접근성 검증은 미수행이다. 아래 기기 셸/CSS 설명은 유지된 웹 구현의 범위다.

AsyncStorage의 기존 `mochi.*` 키와 게임/옷장 구조를 유지한다. 새 앱은 XP 0/코인 90/감자 1개로 시작한다. 웹 설정의 백업 JSON을 앱 설정에서 확인 후 가져오며 XP·코인·자산·배치·기록·애칭·이웃/방명록을 보존한다. 가져오기는 기존 앱 상태를 교체하므로 먼저 앱 백업이 가능하다. 기존 이관 함수를 재사용하고 복원 시 보상/축하를 재지급하지 않는다. 손상된 데이터는 오류로 표시하고 자동 초기화하지 않는다. 비동기 저장은 직렬화한다. 모바일 선호 설정만 `mochi.settings.v1`로 추가 저장하며 실제 소리·알림은 연결하지 않는다.

Expo Router 경로: `/`, `/quest`, `/shop`, `/settings`, `/visit`, `/guest`, `/diary`. `mobile/src/GameApp.jsx`가 상태/날짜/저장/반응을 관리하고 `screens/`, `Character.jsx`, `ui.jsx`가 UI를 구현한다. `src/storage.js`는 백업/이관, `src/actions.js`는 의상 구매와 반응 이벤트를 관리한다. 서명 IPA/APK·EAS 계정·서버/인증·센서·사진·실제 알림·스토어 제출은 미구현이다. EAS 프로필은 로컬 설정 초안이다. 의존성 감사의 Expo/Metro 등 경고는 출시 전 별도 해소 필요다.

모바일 검증: 공유 게임 테스트 32개와 모바일 저장/구매/반응 테스트 5개, 일기 테스트 3개 포함 총 40개 통과. Expo iOS/Android/웹 번들 생성·린트·JS 허용 타입 검사·SDK 의존성 호환 검사 통과, 기존 웹 Vite 빌드 통과. 실제 기기 실행/화면/모션/키보드/접근성은 미확인이다.

## 2. 화면과 홈

오늘의 도전 상단은 왼쪽 `<` 형태의 44px 홈 복귀 버튼으로 정리한다. 웹 퀘스트 내부의 달 아이콘·고정 숫자 200·집 버튼·플러스 3개와 중복 레벨 장식은 표시하지 않는다. 다른 공통 화면의 메뉴와 앱 상단의 실제 LV/XP·재화는 유지한다. 네이티브 오늘의 도전도 홈 라벨 대신 `<` 버튼으로 연결한다.

공통 셸은 아이폰 사용 목업이다. 데스크톱은 최대 390×844px, 뷰포트 높이에 맞춰 제한하는 검정 기기 테두리·48px 곡률·다이내믹 아일랜드·서울 시각 상태 바·하단 홈 표시줄을 제공한다. 신호/배터리는 정적인 장식이며 실제 기기 값을 읽지 않는다. 장식은 aria-hidden·비상호작용이며 게임 기능/저장과 무관하다. 상단 기기 영역·게임 상태·스크롤 콘텐츠·하단 기기 영역을 flex로 분리한다.

480px 이하 실제 모바일에서는 테두리/장식 상태 바/홈 표시줄을 숨겨 실제 OS 표시와 중복하지 않고 100dvh 전체 화면·네 방향 safe-area inset을 적용한다. viewport-fit=cover와 iOS 홈 화면 실행 메타 정보를 제공하지만 네이티브 앱·서비스 워커·오프라인 PWA 구현은 아니다. 모바일 폼 입력은 16px으로 설정해 iOS 자동 확대를 방지한다. 모든 화면 너비는 셸 안에 맞추며 상점은 좁은 기기 콘텐츠 폭을 고려해 1열로 표시한다. 이 기기 셸 내 상점/설정/방문 화면의 중복 테두리는 제거한다. 실제 iPhone/Safari·가상 키보드·홈 화면 실행 검증은 미수행이다.

React screen 상태로 홈·도전·방명록·설정·상점·방문하기 전환. URL 라우터/공통 하단 내비게이션 없음. 전체 에이투지체 웹폰트, 실패 시 시스템 sans-serif.

폼 요소와 details/summary도 에이투지체 및 시스템 폴백을 상속한다. 상점/quest-ui 내부 타이포그래피는 화면 제목 21~22px, 카드 제목 16px·섹션 제목 18px, 본문/입력/펼침 제목 14px, 보조 정보 12~13px으로 명시한다. 홈의 기존 크기·배치는 유지한다. ui-disclosure는 기본 삼각형을 작은 CSS 꺾쇠로 대체하며 접힘/펼침·Enter/Space·포커스는 네이티브 details/summary 그대로다. 소개 본문은 1.7 줄간격과 한글 keep-all/긴 문자열 줄바꿈을 적용한다.

ui-secondary는 크림색·보라 테두리·12px 곡률·최소 44px 터치 영역의 보조 버튼이다. 목표 문구는 목표로 선택/목표로 선택됨, aria-pressed 및 선택색으로 구분하며 선택된 버튼을 다시 누르면 기존처럼 해제한다. 구매/장착/완료는 노랑 주요 버튼으로 구분한다. 상점 그리드는 시작 정렬해 펼친 카드의 옆 카드를 늘리지 않으며 430px 이하 뷰포트에서 1열로 표시한다. 상점/퀘스트 프레임 폭만 화면에 맞추며 다른 화면 구조는 변경하지 않는다.

홈은 코인/출석 한 줄, 방과 캐릭터, 이름 아래 실제 LV/XP, 오늘의 도전·꾸미기 주요 버튼, 선택한 도전/목표 상품 요약 순서다. 홈의 상단 LV/XP는 제거하고 캐릭터 이름 밑에 한 번만 표시하며 다른 화면 상단 LV/XP는 유지한다. 코인은 한 번 표시한다. 설정은 모서리 톱니바퀴, 방문·방명록은 방 안 보조 버튼, 애칭은 캐릭터 아래 15px 이름표이며 설정으로 연결한다. 서울 시간은 창문 근처 11px으로 오전 9:07 · 10월 2일처럼 표시한다.

홈 방문하기의 집 아이콘은 파스텔 노랑 채움/짙은 노랑 윤곽, 방명록의 메모 아이콘은 파스텔 분홍 채움/짙은 분홍 윤곽이다. 두 메뉴 라벨은 에이투지체 500(Medium), 기존 터치 영역과 이동 동작은 유지한다. 홈 메뉴에만 적용한다.

홈 전용 방 비율 368:500, viewBox 0 55 368 500로 빈 벽/바닥 비중을 줄이면서 가구·장착 소품과 카페트 중앙 캐릭터를 유지한다. 캐릭터 폭 66%, 최대 248px과 반응은 유지하며 새 viewBox의 바닥 좌표에 맞춰 위치를 조정한다. 이름/레벨은 방 하단 86.8%에서 묶어 표시하고 주요 버튼을 요약 목록보다 먼저 둬 첫 화면의 스크롤 부담을 줄인다. 짧은 화면은 내부 세로 스크롤을 유지하며 모든 높이에서 무스크롤을 보장하지 않는다. 하늘색·크림·나무색, 주요 행동은 파랑, 재화는 노랑. src/refe/image.png는 분위기 참고이며 에셋을 복사하지 않는다. 기본 배경은 상점/이웃 방의 기존 비율을 유지한다. 돌봄·상태 바·가상 걸음·산책 코인 경로는 없다.

## 3. 도전 데이터와 추천

utils/challenges.js의 일간 15개, 주간 3개, 월간 2개로 총 20개다. 기존 음악/음식 입력은 취향 프로필로 이동하며 보상 없음. 모호한 주/월 생활 리듬 항목은 별도 목표에서 제외한다. 기존 ID/답변/완료 기록은 삭제하지 않는다.

현실 행동은 사용자 확인 방식이며 실제 수행·시간을 센서로 검증하지 않는다. 샘플 방명록 작성이 실제 교류로 자동 계산되지는 않는다.

규칙 기반 추천은 서울 날짜별 후보 3개와 이유를 생성·저장한다. 역할은 익숙한 도전/한 걸음 도전/다른 방식의 도전이며 카테고리와 고정 대응하지 않는다. 최근 10개 기록 중 최근 현실 행동과 그 부담 응답을 참고한다. 편했어요 응답이 있을 때만 한 단계 확장 후보를 허용하고, 버거웠어요는 작은 후보, 응답 없으면 최근 수준을 넘지 않는다. 정보 없는 사용자는 짧은 외출을 기본 후보로 받지만 전체 목록에서 다른 갈래를 자유롭게 선택한다. 난이도 숫자는 후보 크기 비교용이며 개인의 실제 부담을 단정하지 않는다. 프로필은 저장·수정 기능이며 현재 추천 필터에는 사용하지 않는다.

후보/전체 목록에서 오늘 도전 최대 3개 선택. 하나만 완료해도 보상. 완료한 선택은 당일 목록에 남긴다. 나중에 하기는 기존 보류로 슬롯을 비운다. 바꾸기는 앱 프레임 안 하단 창에서 더 가볍게(hard)/더 짧게(time)/다른 활동으로(taste)를 선택한다. 기존 대안 기준을 그대로 사용해 보류+대안 선택을 함께 처리하고, 대안이 전혀 없으면 현재 도전을 유지한다. 교체 로그·시작/완료/보상 기록은 보존하며 교체만으로 시작·완료·보상을 지급하지 않는다. 취소는 저장을 변경하지 않는다.

## 4. 진행·입력·기록

일간 기본 카드는 작은 카테고리, 제목 옆 상태 배지, 조건을 유지한 짧은 설명, 실제 지급 가능 XP/코인, 주요 선택/시작/해냈어요 버튼과 차분한 바꾸기/나중에 하기만 표시한다. 제목 16px·설명 14px·보조 12~13px·터치 44px은 유지하며 여백만 줄이고 높이 제한/텍스트 잘라내기는 없다. 완료 카드는 제목/완료 표시 중심, 선택적 부담 응답도 작은 버튼으로 창에서 제공한다.

카드 안 보류/교체 펼침 메뉴는 없다. 추천 이유는 정보 버튼, 일일 한도 등 반복 규칙은 화면의 보상 안내에서 같은 하단 창으로 확인한다. 한도 소진 시 완료 전에 추가 보상 없음/기록만 남음을 표시하며 보상은 previewReward 결과와 일치한다. QuestSheet는 프레임에 포털로 표시하고 닫기/바깥 클릭/Escape로 취소한다. 열린 동안 앱 배경을 inert, 목록/문서 스크롤을 잠그고 Tab 포커스를 창에 유지한다. 닫히면 원래 버튼으로 복귀, 교체/날짜 변경 등으로 버튼이 사라졌으면 선택한 도전 제목으로 복귀한다. 날짜 변경 시 창을 닫는다. 기존 단일 목록 스크롤과 저장 스키마/추천 기준/보상량은 유지한다.

행동형: 선택 → 도전하기(무보상) → 도전 중 → 해냈어요! → 완료 ✓. 걷기 목표는 로직에서도 유효한 선택인지 확인한다. 하루 기록은 최대 80자, trim 후 빈 입력 차단, 저장하면 완료. 완료 상태를 진행보다 우선하고 버튼·입력을 잠근다.

완료 후 편했어요/적당했어요/버거웠어요 응답은 선택이며 보상 조건 아님. 기록·취향 탭에서 날짜별 하루 기록을 읽고 당일 글만 수정한다. 수정은 XP/코인이나 날짜 수를 늘리지 않는다. 음악/음식 프로필은 언제든 수정 가능하며 보상 없음. 기록·취향 화면에는 보상 없는 수정 안내를 표시하지 않으며, 하루 기록 저장 성공 시에만 짧게 수정 완료를 표시한다. 준비/외출/교류 기록은 category를 분리하고 외출/준비를 교류로 집계하지 않는다.

시작·완료·답변 키는 서울 일간 YYYY-MM-DD:ID, 주간 월요일 YYYY-MM-DD:ID, 월간 YYYY-MM:ID. 매초와 visibilitychange에 날짜를 갱신한다. 새 날 추천/선택을 분리하고 이전 기록은 보존한다. 전체 미완료 개수 배지는 없다. 새 완료 결과만 1.5초 알림, 재진입은 반복하지 않는다. 보상은 시작 전에 카드에 작게 표시한다. 하루 보상 한도 소진 시 기록만 남는다고 안내한다.


### 일기

홈 방명록 오른쪽에 같은 둥근 스타일의 연보라 노트 아이콘과 굵은 일기 라벨을 추가한다. 서울 날짜 기준 하루 한 편(최대 2,000자), 공백 저장 불가. 당일에는 수정·삭제 가능, 다음 날짜부터 수정 불가이며 삭제는 언제든 가능하다. 삭제 확인을 받고, 삭제한 날은 재작성하지 못한다. 날짜별 최신순 목록은 기존 부모 스크롤을 사용한다. 월별 달력의 ✿ 스탬프는 현재 글이 있는 날짜에 표시하며 선택하면 해당 일기를 연다. 월 이동·윤년·연도 경계를 지원한다.

기존 하루 기록과 같은 game.journals를 공유하며 기존 글을 보존한다. 도전 입력은 기존 80자/완료 보상을 유지하고, 기록 편집과 새 일기 화면은 2,000자다. 과거 기록 편집도 모든 저장 경로에서 막는다. 일기 화면 작성·수정 자체는 XP/코인을 지급하지 않는다. journalDates는 기존 글에서 기본값을 유도하는 작성 날짜 원장이다. 삭제하면 글과 해당 날짜의 day-diary 답변을 제거하되 완료·보상·작성 날짜는 유지한다. 주간/월간 날짜 집계는 삭제로 감소하지 않으며 재작성·보상을 중복 획득하지 못한다. localStorage/AsyncStorage의 기존 mochi.game.v1에 함께 저장되고 백업도 포함한다.

설정에는 계정 삭제 안내를 제공한다. 프론트에 실제 로그인·인증·서버 연결이 없어 원격 계정 삭제는 미구현이며 버튼은 이 제약을 안내한다. 로컬 데이터 초기화를 계정 삭제로 표시하지 않으며 기존 데이터는 삭제하지 않는다. 백엔드 DELETE /users/{user_id}는 인증된 사용자 식별과 프론트 API 연결이 마련된 뒤 연결해야 한다.

## 5. 집계와 성장

| 목표 | 집계 | 보상 |
| --- | --- | --- |
| 주간 바깥 발견 | 해당 서울 주의 외출 완료 기록 2회 | 30XP·30코인 |
| 주간 기록 | 해당 주 서로 다른 기록 날짜 3일 | 30XP·30코인 |
| 주간 작은 연결 | 해당 주 교류 완료 기록 2회 | 30XP·30코인 |
| 월간 바깥 발견 | 해당 월 외출 완료 기록 8회 | 60XP·60코인 |
| 월간 기록 | 해당 월 서로 다른 기록 날짜 10일 | 60XP·60코인 |

진행률과 회수 표시, 목표 달성 후 보상 받기로 기간당 1회 지급한다. 동일 날짜:도전 키는 1개 기록이며 일기 수정은 1일 이상 집계되지 않는다. 다른 행동은 같은 날짜에도 각각 집계할 수 있다. 주간과 월간은 같은 기록을 각 기간 목표에 사용할 수 있지만 각 목표의 지급은 1회다.

LV = 1 + floor(XP/100) 유지. 실제 시작 0XP·90코인·감자 1개. initialGame({demo:true})는 명시적 시연용 540코인이며 앱 기본값으로 사용하지 않는다. 일간 기본 15XP·25코인, 처음 시도한 현실 행동 ID는 5XP 추가(입력은 추가 없음). 같은 행동은 다음 날짜에 기본 보상. 일간 지급 최대 3회, 교체/재진입으로 한도나 완료 키를 초기화하지 않는다. 쉬운 입력은 일기 하루 1회뿐이다. 레벨/사회적 행동에 따른 차등 기본 보상 없음. 누적 현실 행동 10개 키(날짜 달라도 가능, 입력 제외)로 펭귄 1회 지급. 기존 보유 친구는 회수하지 않는다. LV.3 토끼 무료 지급, 자동 장착 없음.

계산 예시(출석 제외): 매일 산책+일기 2개, 주간 기록/외출과 월간 기록/외출 보상 모두 수령 시 7일 275XP(LV.3), 14일 665XP(LV.7), 28일 1205XP(LV.13). 한 가지 산책만 매일 하는 예시는 7일 140XP(LV.2), 14일 335XP(LV.4), 28일 605XP(LV.7). 첫날 시작 90+행동 25=115코인으로 90코인 전등을 살 수 있다. 가격·해금 레벨은 유지하며 수치는 콘텐츠 속도 조정용 가정, 예방 효과 검증 기준이 아니다. 실제 날짜 시작/주 경계/보상 수령 여부/출석에 따라 달라진다.

## 8. 친구 정체성과 반응

각 친구는 독립된 SVG 캐릭터다. catalog.js의 FRIEND_INTROS에 짧은 성격/소개 초안을 분리한다. 상점의 친구 소개에는 짧은 introduction 본문만 표시하며 초안 여부·애칭 설계 설명은 사용자 UI에 표시하지 않는다. 외형 기반 초안이며 상세 서사는 미확정이다. 고유 이름과 애칭은 별개. game.nicknames는 캐릭터 ID별 애칭, 없으면 고유 이름 표시. 기존 mochi.petName은 첫 이관 때 현재 장착 친구에만 할당하고 원본 키 보존. 새 이름은 해당 친구만 변경한다.

홈 모든 친구: 눈 전체 그룹 3~6.5초 간격 깜빡임, 클릭/터치/Enter/Space 점프·하트 약 1초, 반응 중 추가 입력 무시. 새 실제 도전/집계 완료 이벤트 또는 다른 소유 의상 착용 ID 변경 시 축하 1회. 구매만 하기/같은 의상/해제/재렌더/홈 재진입은 생성하지 않음. 다른 화면 이벤트는 현재 친구에 대기 후 홈에서 1회 소비하며 친구 변경 시 대기 취소. 최근 이벤트 하나로 합치며 새로고침은 재생하지 않는다. 출석/가구 배치는 연결하지 않는다.

몸·옷·장식·얼굴은 같은 SVG 그룹, 그림자는 고정, 기존 내부 transform/clipPath 유지. 홈 이탈 시 타이머 정리, prefers-reduced-motion은 큰 움직임·눈 압축 없이 효과 투명도만 변화. 상점·이웃 미리보기는 비상호작용이다. 감자는 기존 Potato 로직, 나머지는 useFriendReaction/FriendEffects 사용.

## 9. 이웃·방명록

서울 날짜별 샘플 이웃 12명 중 3명 고정 추천(이전 3명 제외). 오늘 추천/최근 방문/저장한 이웃/내가 남긴 글 탭. 방문 ID 최근순 중복 제거, 이웃 즐겨찾기 자유 저장/해제, 날짜 추천이 바뀌어도 USERS의 ID로 재방문. 친구·의상·방·풍경 다양성 유지.
