# 프론트 기능 명세서

최종 수정: 2026-10-02 · 현재 코드 구현 기준

설치·실행 방법, 코드 구조와 전체 기능 안내는 [README.md](./README.md)를 참고한다.

## 문서 관리 규칙

프론트 기능을 추가·변경·삭제하면 같은 작업에서 이 문서도 수정한다. 화면별 동작, 보상 수치, 데이터 저장 방식, 미구현 사항, 검증 내용과 변경 이력을 실제 코드와 일치시킨다. 계획을 구현 완료로 표시하지 않는다.

## 1. 서비스 원칙 및 구현 범위

핵심 루프는 퀘스트 수행 → XP·코인 획득 → 레벨 상승 → 선택 가능한 캐릭터·의상 증가 → 사용자가 구매·장착 선택이다. 레벨업이나 구매는 현재 캐릭터를 강제로 교체하지 않는다. 캐릭터는 획득 후 컬렉션에 유지되며 언제든 다시 선택할 수 있다.

현재는 React 기반 프론트 목업이다. 실제 사용자 계정, 서버 저장, 실제 활동 검증, 결제는 연결되지 않았다. 캐릭터와 의상은 구현되어 있으며 액세서리·방 소품 구매, 공간 배치, 추가 콘텐츠는 향후 구현 대상이다.

## 3. 홈 / 캐릭터 돌봄

초기 상태: 배부름 80, 행복 95, 기운 70, 걸음 수 7,850, 밥 요청·청소 요청 표시. 상태 수치는 0~100으로 제한된다.

| 조작 | 결과 |
| --- | --- |
| 밥 주기 | 배부름 +15, 밥 요청 숨김 |
| 놀아주기 | 행복 +5, 기운 -10, 잠 해제 |
| 치우기 | 청소 요청 및 배지 숨김 |
| 재우기 | 잠자는 얼굴, 기운 +20 |
| 산책 가기 | 걸음 수 +500, 코인 +5, 잠 해제. 실제 센서 연결 없음 |
| 행동 메시지 | 행동 후 약 2.2초 말풍선 표시 |
| 이름 클릭 | 설정으로 이동하여 이름 지정 |
| 오른쪽 위·하단 설정 | 설정 화면 이동 |
| 하단 상점·코인으로 옷 사기 | 상점 화면 이동 |
| 색상 팔레트 | 크림·복숭아·민트·라벤더·바나나·하늘·딸기·흰떡 8종. 구름 모찌에 적용하며 고정 색 캐릭터에는 적용되지 않음 |

홈의 이름·현재 캐릭터·의상·코인·LV는 공통 상태와 연결된다. 돌봄·걸음 수·선택 색상은 새로고침 시 초기화된다. 시간 경과에 따른 상태 감소와 돌봄에 의한 XP 지급은 없다.

### 일일 출석 / 주간 도장표

팝업 제목은 `이번주의 출석표`, 안내 문구는 `이번 주 N일 함께했어요. 언제든 반가워요.`만 표시한다. 기간·7칸 도장표·출석하기/출석 완료·닫기 버튼을 유지한다. 보상 수령 후에는 `+수치 코인/XP`만 짧게 표시하고, 보상 방식·리셋 규칙·결석 정책 등의 설명은 팝업에 표시하지 않는다.

서울 날짜별 하루 한 번 출석 보상을 지급한다. 앱이 실행 중이면 매초 날짜를 확인해 0시에 새 날짜 팝업을 띄우며, 앱이 꺼져 있으면 다음 방문 시 그날 출석 팝업을 표시한다. 비활성 탭 복귀 시에도 날짜를 확인한다. 이미 보상받은 날짜는 방문 시 자동 팝업을 다시 띄우지 않지만 출석표 버튼으로 항상 열 수 있다. 닫기·Escape로 출석 없이 닫을 수 있으며 같은 화면에 머무는 동안 닫은 팝업을 반복해서 열지 않는다.

도장표는 해당 서울 날짜가 속한 월~일 7칸이다. 출석한 날짜에만 체크하고 이번 주 출석 일수를 표시한다. 매주 월요일 0시에 새 주의 표를 표시하며 기존 주 기록은 저장해 둔다. 코인·XP·캐릭터·의상은 초기화하지 않는다. 연속 출석 요구, 결석 벌점, 보상 감소, 주간 출석 수에 따른 팝업 제한은 없다. 결석한 날짜의 소급 출석은 제공하지 않는다.

보상 후보: 코인 10·20·30 또는 XP 20·35·50. 여섯 후보는 각각 동일한 확률이며 코인/XP 중 한 종류만 지급한다. 클릭 시 한 번 추첨하고 같은 날짜의 재수령은 차단한다. 받은 종류·수치를 해당 날짜 출석 기록에 저장하고 팝업에 표시한다. XP 보상에도 레벨과 milestone 해금을 적용하며 자동 캐릭터 교체는 하지 않는다. 기존 저장 데이터에 출석 항목이 없으면 빈 기록으로 시작한다.

보상·출석은 기기 시각과 프론트 localStorage를 기준으로 하는 목업이다. 서버 시간·보상 검증, 다중 탭 동시 수령 방지는 아직 없다. 앱이 종료된 상태의 시스템 알림은 제공하지 않는다.

## 4. XP / 레벨 / 퀘스트

시작 LV.1, XP 0, 코인 540(목업용 시작 자금). `LV = 1 + floor(누적 XP / 100)`. 코인을 사용해도 XP와 레벨은 감소하지 않는다. 최대 레벨 제한은 현재 없다.

오늘·이번 주·이번 달 탭에 각각 3개 퀘스트를 제공한다. 완료 버튼으로 활동을 수동 확인한 뒤 XP와 코인을 동시에 지급한다. 이미 완료한 동일 퀘스트의 버튼은 비활성화하고 중복 지급을 막는다. 완료 기록은 화면 이동·새로고침 후에도 유지한다.

성장 퀘스트 제목은 Pretendard 700 굵기, 단일 글자 표시로 사용하며 기존 중첩 text-shadow 외곽선/그림자는 제거한다.

| 기간 | 퀘스트 | XP | 코인 |
| --- | --- | ---: | ---: |
| 오늘 | 잠깐 밖에 나가보기 | 100 | 30 |
| 오늘 | 내 시간에 일어나기 | 100 | 30 |
| 오늘 | 오늘의 하루 기록하기 | 100 | 40 |
| 이번 주 | 이번 주 산책 두 번 | 150 | 50 |
| 이번 주 | 일정한 생활 리듬 만들기 | 150 | 50 |
| 이번 주 | 하루 기록 다섯 번 | 150 | 50 |
| 이번 달 | 새로운 장소 가보기 | 200 | 80 |
| 이번 달 | 꾸준한 생활 이어가기 | 200 | 80 |
| 이번 달 | 한 달 기록 열다섯 번 | 200 | 80 |

레벨업 결과와 새 캐릭터 선택지가 열린 사실을 안내한다. LV.3 무료 보상과 오늘 퀘스트 3개 완료 특별 보상을 컬렉션에 지급하며 자동 장착은 하지 않는다. 일기 입력 화면, 실측 활동 검증, 날짜별/주별/월별 퀘스트 재생성·초기화는 미구현이다. 현재 각 퀘스트는 저장 데이터당 한 번 완료할 수 있다. XP·가격·해금 레벨은 목업 수치다.

## 5. 상점 / 캐릭터 컬렉션

상점에는 캐릭터·의상 탭과 보유 코인, 홈으로 돌아가기 버튼이 있다. 캐릭터 탭은 현재 장착한 캐릭터와 전체 목록/내 컬렉션 필터를 제공한다.

| 캐릭터 | 획득 조건 | 비용 | 표현 |
| --- | --- | ---: | --- |
| 꼬질 감자 모찌 | 첫 방문 제공 | 무료 | `refe/pot1.webp` 참고: 얼룩·작은 팔다리·큰 눈의 감자 SVG |
| 복숭아 구름 모찌 | LV.3 milestone 자동 지급 | 무료 | 분홍색 구름 form |
| 구름 모찌 | LV.5에서 구매 가능 | 300 | `refe/cha1.png` 참고: 크림색 몸, 하늘색 귀·꼬리, 꽃·리본, 큰 반짝이는 눈 |
| 라벤더 모찌 | LV.8에서 구매 가능 | 450 | 라벤더 구름 form |
| 민트 모찌 | LV.12에서 구매 가능 | 600 | 민트 구름 form |
| 하루 친구 모찌 | 오늘 퀘스트 3개 완료 시 자동 지급 | 무료 | 하늘색 구름 form |

획득 전 잠금 상태에서는 캐릭터 그림을 렌더링하지 않고 `?`, 이름 `???`, `LV.?`로 표시한다. 필요한 레벨에 도달하면 구매 가능한 캐릭터의 모습과 이름·가격을 공개한다. 특별 퀘스트 캐릭터는 획득 전까지 숨긴다. 컬렉션에서는 획득한 캐릭터만 표시한다.

구매는 코인이 충분하고 레벨 조건을 충족할 때만 가능하며 중복 구매를 막는다. 구매 후 컬렉션에 추가하고 현재 캐릭터는 유지한다. 보유 캐릭터는 장착하기로 선택하며 현재 장착 중 표시를 별도로 제공한다. 추가 캐릭터 장착 해제 시 기본 감자 모찌로 돌아간다. 해제해도 컬렉션에서 삭제되지 않는다. 기본 캐릭터는 항상 제공되며 캐릭터 없는 상태는 제공하지 않는다.

참고 이미지는 디자인 참고용이다. UI에는 참고 파일을 그대로 쓰지 않고 SVG를 사용한다. 추후 캐릭터군·콘텐츠·획득 조건은 데이터 정의를 확장하는 방식으로 추가한다.

## 6. 의상 구매 / 착용

모든 옷·내 옷장 필터, 클릭 미리보기, 가격, 코인 부족·레벨 잠금 안내를 제공한다. 미리보기는 실제 장착과 구분된다. 구매는 보유 목록에만 추가하고 사용자가 입기를 눌러 착용한다. 기본 모습 입기는 의상을 해제한다. 캐릭터를 바꿔도 의상 보유 기록은 유지된다.

| 의상 | 필요 LV | 코인 | 모찌 장식 |
| --- | ---: | ---: | --- |
| 하늘빛 맨투맨 | 1 | 120 | 구름 |
| 딸기 우유 티셔츠 | 1 | 180 | 하트 |
| 새싹 산책복 | 3 | 220 | 잎 |
| 별빛 잠옷 | 5 | 300 | 별 |

홈의 현재 캐릭터에 착용한 옷을 표시한다. 감자 캐릭터 의상은 공통 별 장식을 쓰는 단순 목업이다. 작은 아바타는 의상보다 캐릭터 얼굴 중심으로 표시한다. 미리보기/상점 필터는 상점을 다시 열면 초기화된다.

| 기능 | 현재 동작 / 제약 |

## 8. 방명록

8개의 샘플 글을 제공하며 페이지당 4개 표시한다. 작성자·날짜·내용·좋아요 수·아바타를 보여준다. 60자 이내 입력 후 등록 버튼/Enter로 글을 맨 위에 추가한다. 공백만 있는 글은 등록하지 않는다. 작성자는 목업 이름 `나`이며 날짜는 기기 로컬 날짜다. 새 글 등록 후 첫 페이지로 이동한다.

좋아요 버튼은 선택/해제를 토글하며 샘플 수에서 +1/-1 반영한다. 이전·다음 페이지 버튼은 범위 밖에서 비활성화된다. 답글 버튼은 표시만 있으며 답글 작성은 미구현이다. API·계정·영구 저장은 없다. 방명록 화면을 떠나면 작성 글·좋아요가 샘플 데이터로 초기화된다.

## 9. 저장 및 데이터 경계

| 데이터 | 저장 방식 |
| --- | --- |
| 이름 | `mochi.petName` localStorage |
| XP·코인·완료 퀘스트·보유 캐릭터·장착 캐릭터·출석 | `mochi.game.v1` localStorage. `attendance`에 서울 날짜별 보상 종류/수치 저장 |
| 보유 의상·착용 의상 | `mochi.wardrobe.v1` localStorage |
| 돌봄·걸음 수·색상·설정 토글/음량 | React 메모리, 새로고침하면 초기화 |
| 방명록 작성·좋아요·페이지 | 방명록 컴포넌트 메모리, 화면을 떠나면 초기화 |

서버 계정에 연결된 영구 보관은 아직 없다. 같은 브라우저와 동일 origin에서만 기록이 유지된다. 포트/도메인을 변경하면 다른 저장소로 취급된다. 브라우저 데이터를 지우거나 저장이 차단되면 유지되지 않는다. 손상된 JSON은 초기값으로 돌아간다. 코인·XP·보유 데이터의 서버 검증과 변조 방지는 미구현이다.

## 10. 향후 구현 대상

- 계정/백엔드 저장을 통한 영구 컬렉션, 동기화, 보상·구매 검증.
- 실제 퀘스트 수행 검증, 일기 기록, 반복 퀘스트 갱신.
- 액세서리·방 소품 상품, 공간 배치·테마, 레벨별 새 콘텐츠와 캐릭터군.
- 실제 음악·효과음·알림, 설정 저장 연동.
- 방명록 서버 연동, 답글, 작성자 계정.
- 모바일 전체 반응형과 실제 브라우저 상호작용 검증.

## 11. 실행 / 검증

`frontend`에서 `npm.cmd ci`, `npm.cmd run dev -- --host 127.0.0.1 --port 5180 --strictPort`로 실행한다. 현재 접속 주소는 `http://127.0.0.1:5180/`이며 포트는 실행 설정에 따라 달라질 수 있다.

검증: `npm.cmd run build`, `node --test src/utils/game.test.js src/utils/attendance.test.js`, `git diff --check`. 게임 테스트는 초기 제공, 보상 중복 방지, 해금 레벨, 코인 부족, 구매 후 장착 유지, 무료 보상 및 이전 캐릭터 재장착을 확인한다. 출석 테스트는 서울 자정·월요일·연도 경계, 하루 중복 수령과 복원 기록, 결석 후 보상, 주 변경 시 재화 유지, XP 무료 해금을 확인한다. 브라우저 자동화 연결이 없어 실제 화면/클릭 검증은 별도 확인이 필요하다.
