## 1. 의도와 구현 범위

현실의 작은 활동 → XP·코인 → 독립된 친구·옷·집 꾸미기 → 캐릭터 반응. 결석·미완료 벌점, 강제 진화, 심리 상태 진단은 없다. frontend/는 React/Vite·localStorage, mobile/은 Expo SDK 57·React Native 0.86.3·React 19.2.3·AsyncStorage다. 공유 utils로 계산하며 백엔드 호출·계정·센서 인증은 연결 전이다. 샘플 이웃에게 글이나 반응을 실제 전달하지 않는다.

정식 친구 6종은 기존 그림·ID·획득 조건·소유·의상을 유지한다. 개발용 시안 3종은 버터 곰 밀루(proto-pebble), 살구 강아지 라니(proto-pear), 솜귀 고양이 루루(proto-quilt)로 기본 정면 SVG를 다시 설계했다. 큰 머리/작은 몸, 서로 다른 귀·얼굴·실루엣·꼬리·파스텔 배색을 사용한다. PrototypeFriendDrawing.jsx의 몸·팔·발·귀·눈·입 그룹을 웹/네이티브 어댑터가 공유한다. 이름·성격·좋아하는 것·습관·소개는 prototypeFriends.js의 초안이며 확정 서사가 아니다.

웹 개발 ?preview=friends, 앱 개발 /friend-preview에서 기존 구름/달빛 양과 신규 3종을 같은 배경·200/110/64/40px 및 방 배치로 비교한다. 게임 상태·출석 처리를 마운트하지 않으며 저장·자동 지급·구매·해금은 연결하지 않는다. 승인된 정면 원본은 PrototypeFriendBaseline.jsx로 보존한다. 기존 의상 4종은 실제 몸통·팔 경계의 clipPath로 표시하며 꼬리→몸통/옷→발/팔/소매→머리/얼굴 순으로 그린다. 밀루의 목 장식과 루루의 가슴 장식은 옷 착용 시 가리고 탈의 시 복원하며 라니의 머리 장식은 유지한다. 웹 useFriendReaction와 앱 Character의 기존 성공 이벤트·키보드·터치·깜빡임·동작 줄이기 처리를 재사용한다. 밀루 끄덕임/라니 꼬리 흔들기/루루 고개 기울이기는 1초 안팎으로 종료하고 타이머·프레임을 정리한다. 개발 미리보기 의상 선택·축하 실행·승인본/현재 기본·의상 12조합 비교를 제공한다. 정식 게임의 반응은 유지한다. Poc1.webp, poc2.webp, poc3.webp, poc4.webp, poc5.jpg, POC6.jpeg, POC7.jpg를 직접 확인하고 색감·귀여운 비율만 참고했다. 특징적인 기존 캐릭터를 복제하지 않는다. 시안 3종까지만 제작하며 총수·가격·LV100 해금은 피드백 후 결정한다.

모바일은 View/Text/Pressable/ScrollView/Modal 및 react-native-svg로 구현한다. 원래 친구의 옷·clipPath·Animated 반응·모션 줄이기·이탈 시 정리는 유지한다. 네이티브 OS SafeArea와 KeyboardAvoidingView, 단일 부모 ScrollView를 사용한다. 웹과 앱 저장소는 별개이며 설정 JSON 백업으로 수동 이관한다. 실제 기기 키보드/접근성은 미확인이다.

## 2. 화면과 홈

오늘의 도전 상단은 왼쪽 `<` 형태의 44px 홈 복귀 버튼으로 정리한다. 웹 퀘스트 내부의 달 아이콘·고정 숫자 200·집 버튼·플러스 3개와 중복 레벨 장식은 표시하지 않는다. 다른 공통 화면의 메뉴와 앱 상단의 실제 LV/XP·재화는 유지한다. 네이티브 오늘의 도전도 홈 라벨 대신 `<` 버튼으로 연결한다.

공통 셸은 아이폰 사용 목업이다. 데스크톱은 최대 390×844px, 뷰포트 높이에 맞춰 제한하는 검정 기기 테두리·48px 곡률·다이내믹 아일랜드·서울 시각 상태 바·하단 홈 표시줄을 제공한다. 신호/배터리는 정적인 장식이며 실제 기기 값을 읽지 않는다. 장식은 aria-hidden·비상호작용이며 게임 기능/저장과 무관하다. 상단 기기 영역·게임 상태·스크롤 콘텐츠·하단 기기 영역을 flex로 분리한다.

480px 이하 실제 모바일에서는 테두리/장식 상태 바/홈 표시줄을 숨겨 실제 OS 표시와 중복하지 않고 100dvh 전체 화면·네 방향 safe-area inset을 적용한다. viewport-fit=cover와 iOS 홈 화면 실행 메타 정보를 제공하지만 네이티브 앱·서비스 워커·오프라인 PWA 구현은 아니다. 모바일 폼 입력은 16px으로 설정해 iOS 자동 확대를 방지한다. 모든 화면 너비는 셸 안에 맞추며 상점은 좁은 기기 콘텐츠 폭을 고려해 1열로 표시한다. 이 기기 셸 내 상점/설정/방문 화면의 중복 테두리는 제거한다. 실제 iPhone/Safari·가상 키보드·홈 화면 실행 검증은 미수행이다.

React screen 상태로 홈·도전·방명록·설정·상점·방문하기 전환. URL 라우터/공통 하단 내비게이션 없음. 전체 에이투지체 웹폰트, 실패 시 시스템 sans-serif.

폼 요소와 details/summary도 에이투지체 및 시스템 폴백을 상속한다. 상점/quest-ui 내부 타이포그래피는 화면 제목 21~22px, 카드 제목 16px·섹션 제목 18px, 본문/입력/펼침 제목 14px, 보조 정보 12~13px으로 명시한다. 홈의 기존 크기·배치는 유지한다. ui-disclosure는 기본 삼각형을 작은 CSS 꺾쇠로 대체하며 접힘/펼침·Enter/Space·포커스는 네이티브 details/summary 그대로다. 소개 본문은 1.7 줄간격과 한글 keep-all/긴 문자열 줄바꿈을 적용한다.

ui-secondary는 크림색·보라 테두리·14px 곡률·최소 44px 터치 영역의 보조 버튼이다. 목표 문구는 목표로 선택/목표로 선택됨, aria-pressed 및 선택색으로 구분하며 선택된 버튼을 다시 누르면 기존처럼 해제한다. 구매/저장/시작/완료는 차분한 파랑 주요 버튼으로 구분한다. 상점 그리드는 시작 정렬해 펼친 카드의 옆 카드를 늘리지 않으며 430px 이하 뷰포트에서 1열로 표시한다. 상점/퀘스트 프레임 폭만 화면에 맞추며 다른 화면 구조는 변경하지 않는다.

홈은 코인/출석 한 줄, 방과 캐릭터, 이름 아래 실제 LV/XP, 오늘의 도전·꾸미기 주요 버튼, 선택한 도전/목표 상품 요약 순서다. 홈의 상단 LV/XP는 제거하고 캐릭터 이름 밑에 한 번만 표시하며 다른 화면 상단 LV/XP는 유지한다. 코인은 한 번 표시한다. 설정은 모서리 톱니바퀴, 방문·방명록은 방 안 보조 버튼, 애칭은 캐릭터 아래 15px 이름표이며 설정으로 연결한다. 서울 시간은 창문 근처 11px으로 오전 9:07 · 10월 2일처럼 표시한다.

홈 방문하기의 집 아이콘은 파스텔 노랑 채움/짙은 노랑 윤곽, 방명록의 메모 아이콘은 파스텔 분홍 채움/짙은 분홍 윤곽이다. 두 메뉴 라벨은 에이투지체 500(Medium), 기존 터치 영역과 이동 동작은 유지한다. 홈 메뉴에만 적용한다.

홈 전용 방 비율 368:500, viewBox 0 55 368 500로 빈 벽/바닥 비중을 줄이면서 가구·장착 소품과 카페트 중앙 캐릭터를 유지한다. 캐릭터 폭 66%, 최대 248px과 반응은 유지하며 새 viewBox의 바닥 좌표에 맞춰 위치를 조정한다. 이름/레벨은 방 하단 86.8%에서 묶어 표시하고 주요 버튼을 요약 목록보다 먼저 둬 첫 화면의 스크롤 부담을 줄인다. 짧은 화면은 내부 세로 스크롤을 유지하며 모든 높이에서 무스크롤을 보장하지 않는다. 하늘색·크림·나무색, 주요 행동은 파랑, 재화는 노랑. src/refe/image.png는 분위기 참고이며 에셋을 복사하지 않는다. 기본 배경은 상점/이웃 방의 기존 비율을 유지한다. 돌봄·상태 바·가상 걸음·산책 코인 경로는 없다.

공통 ScreenHeader로 도전·상점·일기·방명록·이웃·설정 제목 21~22px, 뒤로가기 최소 44px, 상단 간격을 통일한다. 기존 이동 목적은 보존하며 구름 장식은 작은 포인트다. 주요 파랑·선택 탭 연보라·보상 노랑·카드 크림, 기본/선택/비활성/장착 상태를 구분한다. 장착 중은 실행 불가 상태이며 해제는 보조 동작이다. 상점 미리보기와 방 배경 디자인은 바꾸지 않는다.

도전은 오늘/이번 주/이번 달 한 줄 탭, 기록·취향 별도 진입, 중복 하단 장식/설정/상점 제거. 웹 phone-content와 앱 메인 ScrollView 한 곳만 스크롤한다. 홈 주요 버튼 아래 도전 요약은 둥근 카드 안에 도전 중→시작 전→완료 순으로 표시한다(저장 순서는 유지). 누르면 해당 미션으로 이동한다. 목표 상품은 작은 미리보기, 코인 현재/필요·레벨 현재/필요와 충족 여부를 분리한다. 미선택 시 상점 진입만 제공한다.

## 3. 일일 미션과 선정

매일 제공하는 미션은 고정 3개 + 변경 3개 = 6개다. 모두 목록에 제공하며 선택 슬롯 제한이나 전체 완료 조건은 없다. 개별 완료를 인정하고 미완료 벌점은 없다.

| 영역 | 미션 | 완료 근거 |
| --- | --- | --- |
| ☀ 매일의 작은 루틴: 크림/연보라 | 출석하기 | 기존 출석 지급 경로의 성공 |
| 같은 영역 | 오늘의 일기 쓰기 | 당일 유효한 공통 일기 저장 성공 |
| 같은 영역 | 방명록 남기기 | 다른 샘플 이웃의 방명록에 유효한 로컬 글 저장 성공 |
| ✧ 오늘의 새로운 발견: 하늘/파랑 | 현실 활동 3개 | 시작 후 사용자 해냈어요 확인 |

각 영역에 N/3 완료를 표시한다. 고정 행은 기능 진입 버튼이며 별도 수동 완료 버튼은 없다. 이미 완료된 일기는 일기 보기로 연결한다. 화면 방문·입력 중·초안·샘플 글·실패는 완료가 아니다. 완료 순서로 카드를 옮기지 않으며 새 활동 완료는 1.5초 피드백 후 간결하게 표시한다.

dailyMissions.js가 기존 challenges.js 데이터·최근 활동/부담 응답을 활용한 날짜별 후보와 구형 당일 기록에서 일기 외 활동 3개를 준비한다. 부족한 후보는 날짜별 결정적인 작은 행동으로 채운다. dailyMissions[서울 날짜]에 저장해 재진입·새로고침으로 변경하지 않는다. prepare/outside/connect 분류를 유지하고 혼자 외출/준비를 교류로 계산하지 않는다. 샘플 방명록은 루틴만 완료하며 실제 교류 목표의 category 기록으로 가산하지 않는다.

물 한 모금/커튼 열기/제철 음식 알아보기, 문밖 한 걸음/짧은 외출/1·5·10분 선택 걷기/무료 동네 구경, 눈인사/안부/감사/커뮤니티 질문/활동 제안의 기존 조건을 유지한다. 답장·약속 성사를 요구하지 않는다. 음악/음식은 보상 없는 취향 프로필이다. 반복만으로 부담을 높이지 않는다. 실제 최종 선정 주체·교체 횟수·인증은 백엔드 합의 전이며 이 알고리즘은 로컬 시연이다.

바꾸기는 기존 하단 선택 창(더 가볍게/더 짧게/다른 활동으로). 같은 목적의 적절한 대안 없으면 유지한다. 나중에 하기는 해당 미션을 보류 표시하며 제공된 3개 슬롯을 없애지 않는다. 다시 도전 가능. 교체·보류는 지급하지 않고 슬롯별 지급 이력을 지우지 않는다. 무제한 생산용 교체 횟수를 새로 확정한 것이 아니다.

## 4. 진행과 통합 일기

활동은 도전하기(무보상) → 도전 중 → 해냈어요! → 완료. 걷기 목표는 유효한 선택인지 로직에서도 확인한다. 완료가 진행보다 우선한다. 카드에는 카테고리·제목/상태·완료 조건·실제 지급 가능 보상과 주요 버튼을 표시한다. 추천 이유/보상 안내/선택적 부담 응답은 작은 진입점에서 확인한다. QuestSheet는 앱 프레임 안에 표시하고 닫기·바깥 클릭·Escape, 배경 스크롤/inert 및 포커스 복귀를 지원한다. 전체 미완료 배지는 없다.

홈·일일 일기 미션·기록·취향 모두 Diary 공통 편집기로 같은 날짜를 연다. 별도 80자 도전 입력과 중복 기록 편집기는 제거했다. 공통 saveDiaryMission을 사용한다. 최대 2,000자, trim 후 공백 금지, 최소 글자 수 없음. 감정 5종과 짧은 질문은 선택 사항이며 자유로운 한 줄만으로 저장 가능하다. 다른 질문은 본문을 유지하며 자동 삽입하지 않는다. 임시 질문은 diaryPrompts.js로 분리했다. 실제 GET 일기 주제 계약은 있으나 서버·인증 연결 전이라 호출하지 않는다.

초안은 journalDrafts[날짜]의 text/emotion/prompt, 저장 본문은 journals[날짜]로 분리한다. 초안은 이동/복귀·새로고침 시 복원하지만 미션 완료·날짜 집계·스탬프·보상은 발생하지 않는다. 저장 중/성공/실패/다시 저장 상태를 표시한다. 웹은 localStorage 쓰기, 앱은 직렬 AsyncStorage 저장 성공 후 상태/보상을 반영한다. 저장 실패 시 화면의 글을 지우지 않는다. 저장소 자체가 차단된 경우 영구 복원은 보장하지 않으며 실패를 알린다.

서울 당일에는 수정·삭제·삭제 후 재작성 가능, 지난 날짜는 읽기만 가능하다. 삭제는 본문·감정·당일 도전 답변·초안을 제거하고 최소 날짜/완료/지급 원장은 보존한다. 재작성·수정은 같은 날짜 보상을 중복 지급하지 않는다. 날짜별 최신순 목록·월별 달력·윤년/월 이동 유지. 현재 저장 본문이 있는 날만 스탬프를 찍는다. journalDates는 과거 작성 집계 원장이라 삭제로 감소하거나 재작성으로 증가하지 않는다.

일간 키 YYYY-MM-DD:ID, 주간 월요일 날짜:ID, 월간 YYYY-MM:ID를 유지한다. 매초 및 웹 visibilitychange/앱 AppState 복귀로 서울 기간을 갱신한다. 로컬 제출은 성공 처리 시점의 서울 날짜를 사용하며, 열린 지난 날짜 일기 저장은 거절한다. 자정 제출의 최종 서버 정책은 합의 필요다.

## 10. 설정과 저장

### 웹 방명록 신고·차단·필터

내 방명록·이웃 방명록은 같은 `guestModeration.js` 규칙과 GuestbookSafety UI를 사용한다. 신고 사유는 욕설/혐오 표현/스팸/기타이며, 확인 창은 앱 프레임 내부에 열고 취소·바깥 클릭·Escape 및 키보드 포커스 제어는 기존 QuestSheet를 사용한다. 차단한 작성자의 글은 두 방명록에서 숨기며 목록에서 차단 해제할 수 있다. 글 원본과 좋아요 기록은 차단 때문에 삭제하지 않는다.

등록 전 NFKC 정규화·공백/기호/제로폭 제거 후 욕설·일부 집단 혐오 표현을 검사한다. 필터는 규칙 기반이며 문맥 오탐·누락 가능성이 있다. 기존 위반 글은 내용을 가리고 신고 동작을 유지한다. 신고된 글에서 필터가 위반을 확인하면 해당 글을 목록에서 제거하고 `신고 시각 + 7×24시간`까지 해당 작성자의 작성 제한을 저장한다. 같은 글 신고는 1회, 재신고로 제재를 연장하지 않는다. 다른 위반 글 신고는 별도 처리한다. 정상 글의 신고는 기록만 남기며 자동 삭제/정지는 하지 않는다. 입력 거절 자체로 제재하지 않는다.

별도 localStorage `mochi.guestModeration.v1`: version=1, blocked[작성자ID], reports[방범위:글ID](사유/작성자/시각/확인 결과, 원문 없음), deleted[방범위:글ID], suspensions[작성자ID].until(UTC 밀리초)를 저장한다. 게임·옷장 데이터는 변경하지 않는다. 기존 글에 계정 ID가 없으면 샘플 이름 기반 ID로 해석하고 기존 m숫자/로컬 글은 local:self로 식별하며 애칭 변경으로 정지를 우회하지 않는다. 신규 로컬 글에는 authorId와 source를 붙인다. 제한 중에는 내/이웃 작성칸과 등록을 차단하고 함수에서도 재검사한다. 화면 타이머·focus·storage 이벤트로 해제를 반영하며 이탈 시 정리한다. 동일 브라우저 탭 상태를 공유하지만 서버 트랜잭션/기기 간 동기화는 아니다.

현재 Vite 웹 로컬 목업만 구현. 실제 사용자 계정 식별·전달·7일 제재의 서버 강제·운영자 심사·이의제기·서버 시간·백업 연동은 미구현이다. 안전 설정을 저장하지 못하면 신고/차단 적용 실패를 알리며 작성 시 안전 설정을 읽지 못하면 등록을 거절한다. 별도 Edge 프로필로 시험하며 실제 사용자 데이터를 초기화하지 않는다. 모바일은 이번에 이웃 등록 전 필터만 재사용하며 전체 신고/차단 UI와 7일 제재는 웹 로컬 구현이다. backend/는 변경하지 않는다.
