# Frontend

사용자 화면과 시연용 화면을 담당합니다.
범위: **홈(침실) · 퀘스트 · 기록 · 지원 연결 카드** 4개 화면 + 데모 흐름.
형태: **Flutter 앱** (디자인은 Figma), App Store 출시 목표
마감: **10/22 발표** — 실제 스마트폰으로 걷기 → 데이터 전달 → 미션 판정 → AI 응답 → 캐릭터 말풍선까지 하나의 흐름으로 시연

## 실행

```bash
cd frontend
npm install
npm run dev
```

React + Vite. 화면: `src/screens/` (Home · Quest · Guestbook), 공통 부품: `src/components/` (Mochi 캐릭터, 상단·하단 바).
지금은 mock 데이터로 동작하고, API 연결 자리는 코드에 `TODO`로 표시해 두었다.

## 디자인 시안

폰 화면 기준 390×844.

| 화면 | 구성 |
|---|---|
| 홈 — 캐릭터 키우기 | 떡 캐릭터 "MOCHI"(색 7가지 중 선택), 상태 바(레벨 · 배부름 · 행복 · 기운), 말풍선, 걸음 수, 코인, 행동 버튼 5개(밥 주기 · 놀아주기 · 치우기 · 재우기 · 산책 가기), 방이 어지러우면 "치워줘!" 표시 |
| 오늘의 퀘스트 | 탭: 오늘 / 이번 주 / 이번 달. 퀘스트 카드에 진행 상태(완료 · 진행 중 · 예정)와 버튼(예: 기록하기 →), 아래에 보상 카드(방 소품 · 새 옷 · 새 방 테마)와 받기 버튼 |
| 방명록 | 글 작성 + 등록하기, 카드에 이름 · 날짜 · 내용 · 좋아요 수, 한 페이지에 4개씩 |

퀘스트 예시 (시안 기준):

| 범위 | 퀘스트 | 보상 |
|---|---|---|
| 오늘 | 잠깐 밖에 나가보기, 평소 시간에 일어나기, 오늘의 하루 기록하기 | 방에 새 소품 추가 |
| 이번 주 | 집 앞 산책 두 번, 비슷한 시간에 일어나기(3일), 하루 기록 다섯 번 | 새 옷 한 벌 |
| 이번 달 | 새로운 장소 한 곳 가보기, 리듬 일정한 주 두 번, 한 달 기록 열다섯 번 | 새 방 테마 |

디자인 기준:
- 글꼴: 본문 **Gowun Dodum**, 제목·숫자 **Jua** (둘 다 Google Fonts)
- 색: 하늘색 계열 배경(`#EAF4FC`, 테두리 `#8DBDE6`), 강조 노랑(`#FFE79A` / `#E0B83A`), 글자 `#2E2A3A`
- 퀘스트 카드 색: 외출 = 초록, 기상 = 파랑, 기록 = 보라
- 하단에 상점 · 설정 버튼

시안에 아직 없는 화면: **기록**(수면·활동·기분 카드, 하루 리듬 띠), **지원 연결 카드**, 상태별 화면(기준선 수집 중·기록 없음·퀘스트 없음), 데모 조작 패널, 심사위원 보기, 경험치 바 효과.

## 사용 API

API 상세는 [`../backend/README.md`](../backend/README.md) 참고.
사용자 화면에는 원점수를 표시하지 않고, 점수·근거는 심사위원 보기(`/admin`)에서만 보여준다.

## 시연 흐름 (10/22 발표)

```
실제 스마트폰으로 걷기
  → 걸음수 데이터 백엔드로 전달
  → 미션 판정
  → AI 응답
  → 캐릭터 말풍선 + 경험치 바 상승
```

데모 조작 패널로 합성 인물 상태 변화 보여주기:

```
B형(급락형) 합성 인물 선택
  → 1일차: 퀘스트 평범, 캐릭터 평온
  → 날짜 넘기기: 걸음수·리듬 떨어짐
  → 퀘스트가 "집 앞 5분 나가기"로 바뀜, 말풍선 변화
  → 계속 넘기기: 지원 연결 카드 등장
  → 심사위원 보기에서 각 시점의 점수·판단 근거 확인
```
