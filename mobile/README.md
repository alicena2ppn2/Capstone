## 현재 소스 구조 (2026-10-15)

모바일 진입점은 `expo-router/entry` → `src/app/_layout.jsx`이다. `src/app`은 기존 경로·레이아웃·인증 복귀/개발 미리보기 라우트만 유지하고, 내부 화면 전환은 GameApp에서 기존 방식대로 연결한다.

- `mobile/src/GameApp.jsx`: 화면 연결과 게임 동작 전달.
- `mobile/src/hooks/useGameState.js`: 한 곳에서 저장 복원·저장 큐·서울 날짜 갱신·출석 연출·축하 이벤트 관찰.
- `mobile/src/screens/home`, `screens/quests`, `screens/login`: 화면별 UI와 전용 컴포넌트/스타일. 작은 나머지 화면은 `screens/*.jsx` 유지.
- `mobile/src/components`: 공통 UI·아이콘·캐릭터 렌더러·하단바·보상 표시. `src/art`는 네이티브 SVG/모션 어댑터.
- `mobile/src/auth`: Supabase native/Android 어댑터·세션 훅·AuthGate·닉네임 입력. `src/api/client.js`: EXPO_PUBLIC_API_URL 주입.
- `mobile/src/storage/storage.js`: AsyncStorage/웹 백업 호환. 기존 저장 키와 형식 유지.
- 루트 `shared/features`: 순수 미션·배정·교체·보상·상점·일기 규칙. `shared/data`: 캐릭터/미션/의상/가구/소개/문장 콘텐츠.
- `shared/utils`: 날짜·시간·색 표시 함수. `shared/theme`: 색/타이포/아이콘 값. `shared/api`·`shared/auth`: 플랫폼 독립 HTTP/인증 계정 연결.
- `shared/art`·`shared/hooks`·`shared/auth/AuthContext.js`: React를 사용하는 공유 렌더링/훅/컨텍스트 경계이며 순수 게임 규칙과 분리. SVG 태그를 웹/네이티브에서 주입한다.

모바일은 이제 frontend/src를 직접 import하지 않는다. Metro는 shared만 감시하며 React를 모바일의 설치본으로 해석한다. Vite도 자신의 React를 사용한다. 실제 웹 UI·IndexedDB 사진 저장과 모바일 AsyncStorage·SecureStore·카메라·OAuth는 각각 유지한다. 모노레포 패키지 설치/의존성 변경 없이 상대 경로를 사용한다.

자세한 변경 전후 구조와 검증/남은 문제는 [구조 문서](../mobile/ARCHITECTURE.md)를 참고한다.

최종 수정: 2026-10-15.

현재 모바일 프론트는 Expo SDK 57, React Native 0.86.3, React 19.2.3이다. `View`, `Text`, `Pressable`, `TextInput`, `ScrollView`, `Modal`과 StyleSheet로 화면을 구현한다. WebView로 Vite 화면을 감싼 앱이 아니다. 기존 웹은 `../frontend`에 보존하며, 게임 데이터/계산은 루트 `shared/`를 공유한다.

## 현재 백엔드 로그인 연결

모바일 Supabase getSession은 검증된 user.id와 실제 access_token을 반환한다. POST /auth/supabase에 조회{}·등록{nickname}을 보내고 알려진 신규회원404만 닉네임 입력으로 전환한다. 성공한 backendUserId는 Supabase ID와 분리해 메모리에 저장하며 requestUser가 서버ID·현재 토큰을 사용한다. 연결 실패/닉네임 오류/재시도/복원/중복콜백/로그아웃·계정전환을 처리한다. 연결 성공 전 홈에 들어가지 않으며 토큰 추가 저장·로컬 기록 자동 병합은 없다.

현재 실제 서버 주소가 미설정이고 체크아웃의 backend에는 해당API가 없다. 원격 backend-onboarding-survey의 계약으로 코드와 모의 검증을 진행했다. Vite 웹 소셜 인증은 기존처럼 미연결이며 공유 연결 구조/UI만 준비했다. [설정·검증·재개 문서](AUTH_BACKEND_SETUP.md)에서 EXPO_PUBLIC_API_URL/백엔드 배포와 실기기 확인 항목을 본다.

## 현재 퀘스트 추천과 수행 안내

고정 출석/일기/방명록3개와 변동 활동3개를 유지한다. 세 가지 선택 질문은 건너뛸 수 있고 설정·기록/취향에서 같은 선호를 수정한다. 기존 preferences에 missions를 추가해 음악/음식과 자산을 보존한다. 익숙한 활동을 우선하며 정보가 없으면 기본 후보라고 안내한다. 같은 날짜 목록은 그대로, 제외 조건은 다음 배정과 명시적 교체에 반영한다. 같은 의미 그룹은 하루 중복하지 않으며 날짜 간 반복을 허용한다.

미션 카드의 제목과 짧은 설명으로 행동·완료 기준을 안내한다. 방법 보기와 단계 나열/수행 수준 선택 UI는 제거했다. 기존 missionModes는 보존하고 진행 중/이미 선택한 조건은 criterion으로 고정한다. 신규 시작은 현재 짧은 조건을 기록한다. 사진·공통 일기·기존 걷기 목표 입력을 유지하며 활동 변경은 다른 활동으로로 통일한다. 완료 후 선택 피드백은 보상 조건이 아니고 자동 난도 상승에 사용하지 않는다. 방명록이 현실 교류 추천을 자동 변경하지 않는다. 실제 게임 서버 연결은 아직 없으며 보상/레벨/서버 확인 차이는 [협의 문서](../frontend/QUEST_BACKEND_AGREEMENT.md)를 따른다.

검증용: mobile에서 npm test / npm run typecheck / npm run lint, 웹에서 npm run build. 웹 임시 Edge 검증은 frontend/scripts/check-mission-guidance.mjs를 사용하며 사용자 저장소를 사용하지 않는다.

현재 교체: 카드 ‘다른 활동으로’ → 조건에 맞는 후보 확인 → 확정. 날짜별 passed/기존 replacements로 넘긴 활동을 모든 슬롯에서 기억한다. 비슷한 부담을 우선하며 자동 확대하지 않는다. 소진 시 기존 활동을 유지하고 명시적인 ‘살펴본 활동 다시 보기’에서만 지난 후보를 재검토한다. 다시 보기에서도 사용자 조건·오늘 완료·슬롯 중복 제한을 지킨다. 이미 저장된 작은 대안/확장 선택은 읽기 전용으로 보존하며 새 수행 수준 선택은 제공하지 않는다. 현재24개 후보/보상 슬롯만 사용한다.

제한 예: 1분짜리 가장 작은 활동에서 교체하면 effort0/1분 이내 후보만 남는다. 이동·연락·사진 등을 제외하고 다른 슬롯/오늘 완료/넘긴 그룹까지 제외하면 후보가 없을 수 있다. 조건을 몰래 완화하거나 후보를 추가하지 않는다. 일자별 기록은 새 날짜에 가져오지 않지만 과거 이력은 보존한다.

## 반응·출석 연출과 미션/일기 예외 처리

이웃의 응원/감사는 저장 성공 후 각각 ‘응원을 남겼어요’/‘고마움을 남겼어요’를 1.3초 표시한다. 선택 색·체크 문구는 유지한다. 기존 반응은 한 종류 선택 방식이며 취소 동작을 새로 추가하지 않았다. 같은 선택 재클릭은 중복 처리하지 않고 저장 실패는 재시도 안내를 남긴다. 웹은 localStorage 쓰기 성공 후 상태 변경, 앱은 commitState의 직렬 AsyncStorage 저장 성공 후 안내한다. 실제 상대 전달/읽음이 아닌 로컬 시연이다.

출석 지급 성공에서 새 날짜 영수증이 생긴 경우에만 출석표를 자동으로 닫고 앱 중앙의 작은 ‘오늘 받은 선물’ 패널을 1초 표시한다. 기존 RewardPanel/RewardGlyphDrawing/HouseDecor와 newAttendanceReward를 연결했다. 코인·XP는 실제 수치, 의상·소품은 실제 상품 도형과 이름을 표시한다. 중복 아이템은 지급된 대체 코인 영수증을 그대로 표시한다. 확인 버튼 없이 자동 종료하며 재열기/새로고침으로 반복하지 않는다. 오늘 받은 결과는 출석표에 남는다. 실패 시 출석표를 유지하고 성공 연출을 하지 않는다. 웹 모션 줄이기는 정적 표시, 네이티브는 확대/이동 없는 opacity만 사용한다. 보상량·확률·대체 규칙은 유지한다.

일일 구조는 고정3+활동3 그대로다. 활동의 의미는 challenges.js의 activityGroup으로 관리하며 새 계획에서 같은 의미의 활동을 동시에 추천하지 않는다. 최근 3개 날짜에 제공한 그룹을 덜 반복하고, 후보가 부족하면 부담을 올리지 않고 반복한다. 최근 버거웠어요 응답이면 effort 0을 유지한다. 기존 날짜에 저장된 계획/지급 이력은 재작성하지 않는다. 교체는 오늘의 다른 활동·이미 완료한 의미 그룹과 겹치지 않고 기존보다 높은 effort를 사용하지 않는다. 완료/지급된 슬롯은 교체 불가, 대안이 없으면 유지하며 기존 화면이 안내한다. 최종 서버 선정/교체 정책은 미확정이며 이 규칙은 로컬 추천 개선이다.

서울 자정이 지나면 편집 중 본문·감정·질문을 보존하고 ‘오늘로 이어 쓰기 / 초안으로 남기기’를 제공한다. 오늘 저장 본문/초안이 있으면 유지 또는 합쳐 이어 쓰기를 사용자가 선택한다. 자동 덮어쓰기/자동 저장/자동 보상은 없다. 합친 내용이 2,000자를 넘으면 원본들을 유지하고 안내한다. 지난 초안은 날짜별 진입 버튼으로 새로고침 뒤에도 다시 찾을 수 있다. 초안을 옮기는 작업은 journals/스탬프/완료/보상을 만들지 않으며 오늘 저장 성공에만 기존 날짜별 지급 원장이 적용된다.

과거 일기는 수정 불가지만 삭제 확인 후 날짜와 무관하게 삭제할 수 있다. 본문·감정·연결된 day-diary 답변·해당 날짜 초안을 지우고 journalDates/completed/missionReceipts는 보존해 집계와 중복 지급을 방지한다. 삭제한 글은 초안에서 복원되지 않는다. 기존 자산·백엔드/API 계약은 변경하지 않는다.

관련 코드: 웹 App.jsx/Attendance.jsx/RewardPanel.jsx/Visit.jsx/Diary.jsx, 모바일 GameApp.jsx/RewardPanel.jsx/Visit.jsx/Diary.jsx, 공유 challenges.js/dailyMissions.js/journal.js/rewardFeedback.js/useBriefFeedback.js. 기존 저장 키를 사용하고 새 필드를 강제로 초기화하지 않는다.

검증: 로직 67개 테스트, 웹 build, 모바일 lint/typecheck·iOS/Android/Web export 통과. 임시 Edge에서 출석 4종/중복 대체/실패/재열기/재진입, 이웃 반응 성공/실패/선택 상태, 과거 초안 충돌/합치기와 과거 삭제를 확인했다. 실제 iPhone/Android 화면·실기기 안전 영역/키보드는 미확인이며 실제 사용자 인증/서버 보상/상대 전달은 미연결이다.


## 걸음 수 · 건강 앱 연결 (2026-10-16)

- iPhone은 Apple 건강(HealthKit), Android는 Health Connect에서 **하루 걸음 합계만 읽는다**(쓰지 않음). 코드: `src/health/steps.ios.js`·`steps.android.js`, 웹 미리보기는 `steps.js`(연결 안 함)
- 퀘스트 화면의 '걸음 수 연결하기'를 한 번 누르면 권한을 묻고, 그 뒤로는 화면을 열 때와 '걸음 확인' 전에 오늘과 지난 7일 걸음을 `POST /users/{id}/steps`로 올린다(`src/health/syncSteps.js`). 서버가 이 값으로 '어제보다·지난주보다 더 걷기'를 정하고 확인한다
- 네이티브 모듈이라 **Expo Go에서는 안 되고 개발 빌드(EAS)가 필요**하다: `npx eas-cli@latest build --profile development --platform ios|android`
- 설정은 `app.json` 플러그인: `@kingstinct/react-native-healthkit`(권한 문구·HealthKit 권한), `react-native-health-connect`(READ_STEPS·권한 설명 화면), `expo-build-properties`(Android minSdk 26)
- 출시 전: App Store는 건강 데이터를 쓰는 이유와 개인정보처리방침, Google Play는 Health Connect 사용 신고(Play Console '건강 앱' 양식)가 필요하다. Android 기기에 Health Connect 앱이 없으면(Android 13 이하) 연결 버튼이 나오지 않는다

Expo 웹 localhost:5183 실행 상태에서 mobile/에서 `npm run dev:preview`를 실행하고 http://localhost:5184/에 접속한다. 실제 앱을 390×844 CSS px iframe으로 불러오며, PC 창 높이/폭에 맞춰 바깥 표시만 균일 축소한다. 개발자 도구 없이 버튼·탭·스크롤을 사용할 수 있다. 실제 iPhone/기기 에뮬레이터가 아니며, 앱 레이아웃·CSS·저장 데이터를 변경하지 않는다. 별도 loopback 개발 서버이고 production 실행을 거절하며 앱 배포 entry에서 import하지 않는다.

### 2026-10-15 도움이 필요할 때
