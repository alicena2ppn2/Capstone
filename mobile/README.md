# 모찌와 친구들 — React Native

현재 모바일 프론트는 Expo SDK 57, React Native 0.86.3, React 19.2.3이다. `View`, `Text`, `Pressable`, `TextInput`, `ScrollView`, `Modal`과 StyleSheet로 화면을 구현한다. WebView로 Vite 화면을 감싼 앱이 아니다. 기존 웹은 `../frontend`에 보존하며, 게임 데이터/계산은 `../frontend/src/utils`를 공유한다.

## 실행

Node.js 22.13 이상이 필요하다. 설치된 잠금 파일을 기준으로 실행한다.

```powershell
cd mobile
npm.cmd ci
npm.cmd start -- --lan --port 8081
```

SDK 57을 지원하는 Expo Go에서 QR을 스캔한다. PC와 휴대폰은 같은 네트워크를 사용해야 한다. 기기/Expo Go 버전에 맞는 개발 빌드가 필요한 경우 EAS 개발 설정을 별도로 추가한다. 이 작업은 Dev Tunnel 공개 설정을 변경하지 않는다.

```powershell
npm.cmd run web -- --port 8081
npm.cmd run test
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run export
```

`export`는 iOS/Android/웹 JS·Hermes 번들 생성이며, 서명된 IPA/APK 빌드나 실기기 테스트는 아니다. TypeScript 검사는 기존 JavaScript를 허용하는 `allowJs/checkJs:false` 구성이다. 엄격한 TypeScript 전환까지 완료한 것은 아니다.

## 현재 기능

- 홈: 기존 방/가구 SVG, 여섯 친구의 원래 도형과 체형별 옷/clipPath, 서울 시각, 애칭 아래 실제 LV/XP, 코인·출석, 도전/꾸미기, 설정·방문·방명록.
- 도전: 규칙 추천·최대 3개 선택·시작/완료·입력 공백 차단·보류/교체·추천 이유·선택적 부담 응답·주/월 집계·하루 기록 조회/수정·취향 입력. 기존 보상량·가격·레벨 공식·일일 한도 유지.
- 상점: 캐릭터/옷/집 꾸미기, 보유 필터, 소품별 분류, 미리보기·구매·장착·해제·목표 상품·친구 소개. 친구 해제는 기본 감자로 돌아간다. 구매는 자동 장착하지 않는다.
- 출석: 서울 날짜/월요일 기준 표, 고정 주간 계획, 일일 한 번 보상, 의상/가구 중복 보상 처리.
- 반응: 평상시 깜빡임, 터치/웹 키보드 반응, 새 보상/새 의상 축하. 반복 입력 차단, 앱 비활성/화면 이탈 시 타이머·애니메이션 정리, OS 모션 줄이기 대응. 홈 밖 이벤트는 홈에서 한 번 소비한다. 복원과 단순 진입은 축하 이벤트가 아니다.
- 이웃: 명시적인 샘플 이웃, 날짜별 추천·최근/저장 목록·재방문·기기 내부 방명록/좋아요·응원/감사·내 작성 글. 실제 사용자에게 전달하지 않는다.
- 설정: 친구별 애칭, 소리/알림 선호값 저장, 기록 백업/가져오기. 실제 음악 재생/알림 발송은 미구현이다.

Expo Router의 `src/app/_layout.jsx`에서 앱 상태를 유지하고 `/`, `/quest`, `/shop`, `/settings`, `/visit`, `/guest`로 화면을 전환한다. 기존 화면 스타일은 네이티브 `src/ui.jsx`에서 관리한다. OS 상태 바와 SafeArea를 사용하며 웹 목업의 검정 기기 프레임을 중복하지 않는다. 각 페이지는 한 개의 메인 ScrollView로 스크롤한다.

## 저장과 웹 데이터 이관

AsyncStorage를 사용하며 기존 `mochi.game.v1`, `mochi.wardrobe.v1`, 이웃/방명록 키를 그대로 사용한다. 앱과 브라우저는 별도 저장소다. 웹 데이터는 자동으로 앱에 들어오지 않는다.

1. 기존 웹의 설정 → **현재 기록 백업**에서 JSON을 복사한다.
2. 앱 설정 → **백업·가져오기** → 붙여넣기 → 확인한다.
3. 가져오기는 현재 앱 기록을 백업으로 교체한다. 기존 앱 기록을 보유하려면 먼저 **현재 기록 복사**를 사용한다.

XP·코인·완료/시작·답변·출석·보유 자산·배치·애칭·목표·이웃/방명록을 보존한다. 기존 버전 이관을 재사용하며 이관 자체로 보상을 지급하지 않는다. 잘못된 JSON/재화/옷장/방명록 형식은 거절한다. 저장 읽기 실패 시 새 게임으로 덮어쓰지 않는다. 비동기 저장은 순서대로 실행한다. 선호값은 `mochi.settings.v1`에 저장한다. 백업에는 일기와 글이 포함되므로 사용자가 보관하는 개인 데이터이며, 서버로 전송하지 않는다.

## 코드와 에셋

`src/GameApp.jsx`: 상태·저장·날짜·화면 연결. `src/screens`: 네이티브 화면. `src/actions.js`: 원자적 의상 구매/착용, 축하 이벤트 판별. `src/storage.js`: 복원/백업/이관. `src/Character.jsx`: Animated·AppState·AccessibilityInfo를 사용하는 반응.

`src/art`는 기존 SVG 도형을 react-native-svg로 변환한 파일이다. `python mobile/scripts/port-svg.py`는 저장소 루트에서 실행한다. CSS/DOM 이벤트는 포함하지 않고 네이티브 반응을 별도로 연결한다. 기존 참고 이미지는 앱 에셋으로 복사하지 않았다. Pretendard Regular/Bold는 공식 저장소의 폰트이며 `assets/fonts/LICENSE.txt`에 SIL OFL 라이선스를 포함한다.

## 출시 전 남은 범위

계정·Supabase 인증·백엔드 동기화·서버 기준 보상·실제 이웃·신고/차단·계정 삭제·개인정보 동의는 연결되지 않았다. 실제 걸음 센서/HealthKit·사진/앨범·음악·기기 알림도 이번 전환에 추가하지 않았다. 앱 아이콘은 템플릿 임시 에셋이다.

`eas.json`은 내부 테스트/출시 빌드 프로필 초안이다. EAS 프로젝트/계정·앱 식별자·서명·Apple 개발자 계정은 아직 연결하지 않았다. 실제 빌드/제출은 별도 작업이다. `npm audit`에 Expo/Metro·일부 간접 패키지 경고가 남아 있다. SDK를 깨뜨리는 자동 downgrade/force fix는 적용하지 않았으며 출시 전에 호환 패치 검토가 필요하다.

직접 확인한 검증 결과는 [프론트 기능 명세서](../frontend/FEATURE_SPEC.md)에 기록한다. 실제 iPhone/Android·브라우저 렌더링·터치·접근성 읽기·키보드/모션은 현재 환경에서 미확인이다.

공식 기준: [SDK 57](https://docs.expo.dev/versions/v57.0.0/), [Router](https://docs.expo.dev/router/installation/), [SVG](https://docs.expo.dev/versions/v57.0.0/sdk/svg/), [AsyncStorage](https://docs.expo.dev/versions/v57.0.0/sdk/async-storage/).

### 일기

홈 방명록 오른쪽에 같은 둥근 스타일의 연보라 노트 아이콘과 굵은 일기 라벨을 추가한다. 서울 날짜 기준 하루 한 편(최대 2,000자), 공백 저장 불가. 당일에는 수정·삭제 가능, 다음 날짜부터 수정 불가이며 삭제는 언제든 가능하다. 삭제 확인을 받고, 삭제한 날은 재작성하지 못한다. 날짜별 최신순 목록은 기존 부모 스크롤을 사용한다. 월별 달력의 ✿ 스탬프는 현재 글이 있는 날짜에 표시하며 선택하면 해당 일기를 연다. 월 이동·윤년·연도 경계를 지원한다.

기존 하루 기록과 같은 game.journals를 공유하며 기존 글을 보존한다. 도전 입력은 기존 80자/완료 보상을 유지하고, 기록 편집과 새 일기 화면은 2,000자다. 과거 기록 편집도 모든 저장 경로에서 막는다. 일기 화면 작성·수정 자체는 XP/코인을 지급하지 않는다. journalDates는 기존 글에서 기본값을 유도하는 작성 날짜 원장이다. 삭제하면 글과 해당 날짜의 day-diary 답변을 제거하되 완료·보상·작성 날짜는 유지한다. 주간/월간 날짜 집계는 삭제로 감소하지 않으며 재작성·보상을 중복 획득하지 못한다. localStorage/AsyncStorage의 기존 mochi.game.v1에 함께 저장되고 백업도 포함한다.

설정에는 계정 삭제 안내를 제공한다. 프론트에 실제 로그인·인증·서버 연결이 없어 원격 계정 삭제는 미구현이며 버튼은 이 제약을 안내한다. 로컬 데이터 초기화를 계정 삭제로 표시하지 않으며 기존 데이터는 삭제하지 않는다. 백엔드 DELETE /users/{user_id}는 인증된 사용자 식별과 프론트 API 연결이 마련된 뒤 연결해야 한다.
