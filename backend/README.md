# Backend

미션으로 행동을 유도하는 서버입니다. 밖에 잘 나가지 않는 사용자에게 하루 미션(하늘 사진 올리기, 동네 맛집 찾아보기, 주제 일기 쓰기 등)을 주고, 해내면 코인과 경험치를 줍니다. 경험치가 쌓이면 레벨이 오릅니다.

- 스택: Python, FastAPI, SQLite
- 프론트: React (`frontend/`, 기능 명세는 `frontend/FEATURE_SPEC.md`)
- 마감: 10/22 발표 — 휴대폰으로 걷기 → 걸음 전달 → 미션 판정 → 캐릭터 반응까지 한 흐름으로 시연
- 작업 기록: [CHANGELOG.md](CHANGELOG.md) — 작업할 때마다 날짜별로 남김
- 프론트 연결: [FRONTEND_GUIDE.md](FRONTEND_GUIDE.md) — 게임 규칙은 서버가 기준, 화면별 API
- DB 구조: [DATABASE.md](DATABASE.md) — DB 파일 하나를 모든 회원이 같이 쓰고 `user_id`로 구분

## 실행

```bash
cd backend
python -m venv .venv
.venv/Scripts/activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload   # API 문서: http://localhost:8000/docs
pytest                          # 테스트
```

환경변수 (모두 선택)

| 이름 | 기본값 | 용도 |
|---|---|---|
| `CAPSTONE_DB` | `backend/app.db` | SQLite 파일 경로 |
| `CAPSTONE_UPLOADS` | `backend/uploads/` | 사진 저장 폴더 |
| `CORS_ORIGINS` | `http://localhost:5173` | 프론트 주소 (쉼표로 여러 개) |

## 시연용 데이터

```bash
python scripts/seed_demo.py                         # 서울 기준 오늘을 시연 당일로, 21일치
python scripts/seed_demo.py --date 2026-10-22 --days 21
```

- 주인공 `demo-mochi`(모찌주인): 3주 전엔 하루 900보 정도로 거의 집에만 있다가 점점 9,000보까지 늘고, 미션 수행률도 35% → 90%로 오르는 회복 이야기
- 친구 `demo-haneul`(하늘이) · `demo-walker`(산책왕) · `demo-slow`(느림보): 주인공 방에 놀러 오고 방명록을 남김
- 실제 API를 호출해서 쌓기 때문에 코인·경험치·레벨·상점 지급이 실제 규칙대로 계산됨
- 시연 당일 미션은 정해만 두고 수행하지 않음 → 발표 때 걸음 올리기·미션 완료를 직접 보여 줌
- 다시 돌리면 데모 사용자 4명만 지우고 똑같이 다시 만듦 (`--seed`가 같으면 같은 데이터)

## API

| API | 하는 일 |
|---|---|
| `POST /auth/supabase` | Supabase 로그인 → 서버 사용자. 이미 연결됐으면 200, 처음이면 `nickname`으로 만들어 201, 닉네임이 없으면 404 |
| `POST /users` | 가입: 닉네임 → `id` (앱이 저장해 두고 모든 API에 사용) |
| `GET /nicknames/check?nickname=` | 닉네임 쓸 수 있는지 확인 |
| `GET /users/{id}` | 사용자 정보 (닉네임·레벨) |
| `PATCH /users/{id}` | 닉네임 바꾸기 |
| `DELETE /users/{id}` | 계정 삭제 — 걸음·미션·코인·사진·일기·방문·방명록까지 모두 삭제 (App Store 필수) |
| `GET /survey/questions` | 처음 설문 질문과 답 목록 (직업·함께 사는 사람·반려동물·외출 빈도·관심 취미·평소 하는 일) |
| `PUT /users/{id}/survey` | 처음 설문 답 저장 (모든 질문 건너뛸 수 있음, 다시 보내면 통째로 바뀜) |
| `GET /users/{id}/survey` | 내 설문 답, `done=false`면 아직 안 함 |
| `POST /users/{id}/steps` | 하루 걸음 수 올리기 (앱 만보기 → 서버) |
| `GET /users/{id}/home` | 걸음, 걸음 목표(8,000보), 코인, 레벨, 출석 여부, 미션 진행, 말풍선, 오래 쉬다 돌아온 날이면 `welcome_back` |
| `GET /users/{id}/missions/today` | 매일 고정(출석·걸음·지난주보다·일기·방문·방명록) + 매일 바뀌는 3개(움직이기·집·이어지기, 그날 처음 부를 때 정해지고 하루 동안 고정) + `ladder` |
| `PUT /users/{id}/missions/{mission_id}/feedback` | 미션 소감 (기분 1~5·한 줄, 그날 완료한 미션만, 보상 없음, 위기 표현 확인) |
| `GET /users/{id}/feedback?from=&to=` | 내 미션 소감 목록 |
| `GET /admin/feedback/stats` | [관리자] 미션별 소감 수·평균 기분 (`X-Admin-Token`) |
| `POST /users/{id}/missions/{mission_id}/reroll` | 미션 새로고침: 매일 바뀌는 미션을 같은 칸·같은 단계의 다른 미션으로 (하루 3번, 완료한 미션·매일 고정은 안 됨) |
| `GET /users/{id}/ladder` | 단계 사다리: 움직이기·이어지기 지금 단계와 다음 단계까지 (`stage`·`done`/`need`·`top`) |
| `POST /users/{id}/missions/{mission_id}/complete` | 완료 판정 → 코인·경험치 지급 (중복 지급 없음), 레벨업 여부, 단계가 오른 갈래 `stage_up` |
| `POST /users/{id}/attendance` | 출석하기 (앱을 열 때 호출, 하루 한 번 보상) |
| `GET /users/{id}/weekly` | 이번 주(월~일) 주간 미션과 진행도 |
| `POST /users/{id}/weekly/{quest_id}/complete` | 주간 미션 하루 채우기 (사진). 서로 다른 날 목표 횟수를 채우면 보상 한 번 |
| `POST /users/{id}/photos` | 사진 업로드 → `photo_id` (jpeg·png·webp·heic, 10MB 이하). 촬영 일시는 서버에만 저장 |
| `GET /photos/{photo_id}` | 사진 보기 |
| `GET /users/{id}/album?from=&to=&page=&per_page=` | 사진첩: 내가 올린 사진, 날짜 최신순, 어떤 미션·일기에 올렸는지 |
| `GET /users/{id}/album/months` | 사진첩 월별 개수 |
| `DELETE /users/{id}/photos/{photo_id}` | 사진 지우기 (일기에서도 떼어 냄, 받은 보상은 그대로) |
| `GET /users/{id}/diary/topic` | 오늘의 일기 주제 |
| `PUT /users/{id}/diary/{date}` | 일기 쓰기·고치기 (글·기분·사진, 오늘의 주제 사용 여부). 일기 미션이 있으면 자동 완료 |
| `GET /users/{id}/diary/{date}` | 하루 일기 보기 |
| `DELETE /users/{id}/diary/{date}` | 일기 지우기 — **지운 날은 다시 쓸 수 없음** (앱과 같은 규칙), 받은 보상은 그대로 |
| `GET /users/{id}/diary/export?from=&to=` | 일기 내보내기 — 텍스트 파일(.txt) 내려받기. 기관 연동 없이 사용자가 직접 보관·공유 |
| `GET /users/{id}/diary?from=&to=` | 일기 목록 (기록 탭) |
| `GET /users/{id}/coins` | 코인 잔액 |
| `GET /admin/users/{id}/signals?from=&to=` | [관리자] 위기 신호 기록. `ADMIN_TOKEN` 환경변수 + `X-Admin-Token` 헤더 필요, 없으면 꺼짐 |
| `GET /users/{id}/shop` | 상점: 캐릭터·의상·집 꾸미기 소품과 내 상태 (보유·구매 가능·코인 부족·잠김·비공개, 장착·배치 중) |
| `POST /users/{id}/shop/buy` | 구매 — 레벨·코인·중복을 서버에서 확인하고 코인 차감 |
| `PUT /users/{id}/equipped` | 장착 — 가진 캐릭터·옷만. 보낸 칸만 바뀜 (`null`이면 기본 캐릭터 / 옷 벗기) |
| `PUT /users/{id}/decor` | 집 꾸미기 배치 `{slot, item_id}` — 가진 소품을 맞는 자리에, `null`이면 비우기 |
| `GET /users/{id}/room` | 방 모습 (내 방·이웃 방 공통): 닉네임·레벨·캐릭터·옷·놓은 소품 |
| `GET /users/{id}/level` | 레벨·경험치 |
| `POST /users/{id}/visits` | 친구 방 놀러 가기 (`{id}` = 방 주인, body에 `visitor_id`). 방문한 사람의 방문 미션 자동 완료 |
| `GET /users/{id}/visits` | 오늘 내 방에 놀러 온 친구 |
| `GET /users/{id}/rooms/recommended` | 놀러 갈 만한 친구 방 — 최근 7일 안에 앱을 쓴 사람 중 **내 레벨과 가까운 순** (각 방에 `level`, `level_diff`, `similar`) |
| `GET /users/{id}/guestbook?viewer_id=` | 방명록 목록 (`{id}` = 방 주인). 신고 2명 이상·차단 관계인 사람의 글은 빠짐 |
| `DELETE /users/{id}/guestbook/{entry_id}?by=` | 방명록 글 지우기 (방 주인 또는 쓴 사람) |
| `POST /users/{id}/guestbook/{entry_id}/like` `{user_id}` · `DELETE …/like?by=` | 방명록 좋아요·취소 (한 사람이 한 번). 목록의 각 글에 `likes`, `liked` |
| `POST /users/{id}/guestbook` | 방명록 남기기. `author_id`(쓴 사람)를 넣으면 쓴 사람의 방명록 미션 자동 완료. 욕설 필터, 차단 관계면 403 |
| `POST /users/{id}/friends` `{nickname}` | 친구 추가 — 닉네임으로 요청 (상대가 먼저 요청했으면 바로 친구) |
| `GET /users/{id}/friends` | 친구 목록 + 받은 요청 + 보낸 요청 (닉네임·레벨·마지막 접속일·오늘 놀러 갔는지·**친밀도**) |
| `POST /users/{id}/friends/{friend_id}/accept` · `DELETE /users/{id}/friends/{friend_id}` | 요청 수락 / 친구 끊기·요청 취소·거절 |
| `POST /users/{id}/blocks` · `DELETE /users/{id}/blocks/{target}` · `GET /users/{id}/blocks` | 차단하기·풀기·목록 (차단하면 친구도 끊김) |
| `POST /reports` | 신고하기 (방명록 글·사람). 신고한 사람에게는 바로 숨김, `block: true`면 차단도 함께 |
| `POST·GET·DELETE /users/{id}/rest` | 쉬어 가기 시작(`{days}` 1~30)·상태·끝내기. 쉬는 기간은 오래 쉰 날로 치지 않음 |

날짜를 받는 API는 `?date=YYYY-MM-DD`로 날짜를 바꿀 수 있습니다 (발표 데모에서 날짜 넘기기). 안 넣으면 **서울 기준 오늘** (프론트와 같이 서울 자정에 하루가 바뀜).

### 사용자
- 닉네임 2~12자, 앞뒤·연속 공백 정리. 대소문자·띄어쓰기만 다른 닉네임은 같은 것으로 보고 중복 불가 (409)
- 방문자·추천 방 목록과 방명록 작성자에 닉네임이 붙음. 방명록은 `author`를 비우면 `author_id`의 닉네임 사용
- 지금은 로그인(비밀번호·토큰) 없이 `id`만으로 동작. 출시 전에 토큰 확인을 붙여야 함
- 나중에 iPhone 앱으로 낼 때 Game Center id를 `game_center_id`에 연결할 수 있게 칸만 만들어 둠
- 프론트의 "모찌 이름"(캐릭터 이름)과 사용자 닉네임은 별개

## 미션 규칙

**주간 미션** (월~일, 매일 미션과 별도 · `app/missions.py` `WEEKLY_QUESTS`)
- 이번 주 자연 속 산책 2번: 공원·산책로·하천 사진을 **서로 다른 날 2번** → 100코인 · 200XP (한 주에 한 번)
- 하루에 한 번만 셈(같은 날 두 번째는 409), 오늘 찍은 내 사진만 인정, 사진첩에 "이번 주 자연 속 산책 2번"으로 표시
- 근거: 자연에서 주 120분, 짧게 여러 번이어도 효과 (White 2019)

**처음 설문** (`app/survey.py` `QUESTIONS`) — 10/12 면담 "처음에 현재 상태 묻기"
- 직업(학생·취업 준비·직장인·아르바이트·쉬는 중·기타), 함께 사는 사람, 반려동물, 외출 빈도, 관심 취미(5개까지), 평소 하는 일(6개까지)
- 쓰는 곳: ① **걸음 기록이 없는 날**(처음 며칠) 외출 빈도가 "거의 매일·주 2~3번"이면 나간 날로 봄 (걸음 기록이 있으면 걸음이 우선) ② 조건 있는 미션(`requires`)은 답이 맞을 때만 나옴 — 예: 강아지가 있을 때만 "강아지 산책 5분 더", 가족과 살 때만 "가족과 한 끼"
- 관심 취미·평소 하는 일로 미션 고르기는 남음
- 답은 미션 고르기에만 쓰고 다른 사람에게 보이지 않음. 계정 삭제 시 함께 삭제

**매일 고정 6개** (`category: daily`)
- 출석하기: 앱을 열 때 `POST /attendance`
- 오늘 걸음 채우기: 8,000보 이상 (서버에 올라온 오늘 걸음으로 판정)
- 지난주보다 1,000보 더 걷기: 최근 7일 하루 평균 + 1,000보 (100보 단위 올림). 최근 7일 중 걸음 기록이 4일 이상일 때만 나오고, **어제 8,000보 이상 걸었으면 나오지 않음**
- 오늘의 일기 쓰기: 설명에 오늘의 추천 주제가 들어감. 주제와 상관없는 일기도 인정. 기록 탭에서 쓰면 자동 완료
- 친구 방 놀러 가기: 다른 사람 방을 방문하면 자동 완료
- 방명록 남기기: **다른 사람 방**에 쓰면 자동 완료 (내 방에 쓴 건 제외)

**매일 바뀌는 3개** = 움직이기(`outdoor`) + 집에서(`home`) + 이어지기(`connect`)
- 움직이기·이어지기는 **단계 사다리** (QUEST_DESIGN ④, 4단계 지역은 뺌): 1 혼자 → 2 한 명 → 3 여럿
  - 지금 단계 미션을 **3번** 하면 다음 단계가 열림 (`STAGE_UP_COUNT`). 내려가는 일은 없음. 완료 기록으로 계산
  - 어제 걸음이 1,000보 미만이거나 평소(최근 28일 중앙값)의 절반 미만이면 "안 나간 날" → **움직이기만 한 단계 낮게** (이어지기는 그대로)
  - 단계가 오를 때마다 코인 +10 (`STAGE_BONUS_COINS`). 예: 밖 1단계 50 · 2단계 60 · 3단계 70
  - 이어지기 미션에는 `tip` ("이렇게 해 보세요" 사회 기술 팁)
  - `outdoor` 중 `stage: 0`(안 가 본 길, 벽화, 노을 등 새 활동)과 `explore`·`record`는 매일 미션에 안 나옴 (10/12 면담: 새로운 것보다 하던 것 늘리기)
- 같은 사람·같은 날은 항상 같은 미션, 최근 이틀 동안 준 미션은 가능하면 피함
- **새로고침**: 마음에 안 들면 같은 칸·같은 단계의 다른 미션으로 바꿈. 하루 3번(`REROLLS_PER_DAY`), 무료. 끝낸 미션은 못 바꿈

  - **쉬어 가기**(최대 30일)로 미리 쉬겠다고 하면 그 기간은 쉰 날로 치지 않음 → 초기화 안 됨. 돌아오면 "푹 쉬었어? 다시 와 줘서 반가워!"
  - 참고: Habitica도 며칠을 빠지든 하루치만 불이익을 주고, "여관에서 쉬기"로 불이익을 멈출 수 있음

### 상점
- 상품·가격·레벨 조건은 프론트와 같음. 꼬질 감자 모찌는 처음부터, 복숭아 토끼 모찌는 LV.3에 무료, 하루 펭귄 모찌는 하루 미션 3개 완료 시 무료
- 코인 사용은 보상 장부에 마이너스로 기록 (잔액 = 장부 합계, 경험치는 그대로)
- 사도 자동 장착하지 않음. 잠긴 캐릭터는 이름을 내려주지 않음 (프론트의 `???` 표시와 같게)
- 프론트 목업의 시작 코인 540은 서버에 넣지 않음 (서버는 0에서 시작)
- 집 꾸미기: 전등·카페트·액자·인형·창밖 풍경 다섯 자리에 하나씩. 구매는 캐릭터·옷과 같은 `POST /shop/buy` (`type: "decor"`), 사도 자동 배치 안 함, 빼도 보유는 그대로. 잠긴 소품은 이름·레벨을 숨김

**일기 주제**: 사용자마다 순서를 섞어 하루 하나. 50일 동안 같은 주제가 다시 나오지 않음

### 친밀도 (`app/friendship.py`)

친구에게 방명록·방문을 할수록 관계 레벨이 오르고, **오를 때 두 사람 모두 코인**을 받는다.

| 레벨 | 이름 | 누적 점수 | 오를 때 코인 (두 사람 각각) |
|---|---|---:|---:|
| 1 | 새 친구 | 0 | — |
| 2 | 아는 사이 | 4 | 20 |
| 3 | 친한 친구 | 12 | 40 |
| 4 | 단짝 | 24 | 60 |
| 5 | 베스트 프렌드 | 40 | 100 |

- 점수: 방명록 +2, 방문 +1. **같은 사람이 같은 친구에게 하루에 종류마다 한 번만** (반복으로 코인 모으기 방지)
- 두 사람이 서로 한 활동이 한 점수로 합쳐짐 → 서로 오가면 빨리 오름 (하루 최대 6점)
- 친구(수락된 사이)일 때만 쌓임. 레벨 보상은 관계마다 한 번 (끊었다 다시 맺어도 다시 안 줌, 점수는 남음)
- 방명록·방문 응답의 `friendship` `{level, name, points, points_to_next, gained, leveled_up, earned_coins}`

### 신고·차단·필터 (App Store 심사 1.2)

- **필터:** 방명록 글·보이는 이름·닉네임에 욕설·비하·성적 표현이 있으면 저장 안 함 (422 "다른 말로 바꿔 써 줄래요?"). 띄어쓰기·숫자로 피해 가는 것("시 1 발")도 잡음. 목록 `app/data/profanity.json` (팀 정리, 계속 보완)
- **차단:** 어느 쪽이 차단했든 서로의 방 추천·방문·방명록·방문자 목록에서 사라짐. 방 주인이 차단하면 그 사람이 예전에 쓴 글도 숨김
- **혐오 표현:** 비하·혐오 표현(`slurs`)을 방명록에 쓰면 글을 막고 **방명록 쓰기 7일 정지** (`guestbook_bans`). 일반 욕설은 글만 막음
- **신고:** 신고한 사람에게는 바로 숨기고, 서로 다른 **2명**이 신고한 방명록 글은 모두에게 숨김. 신고 내용은 `reports` 표 (운영자가 확인 → `status`)
  - **가입 3일 미만 계정(또는 가입 기록 없는 id)의 신고는 기록만 하고 숨김 횟수에 안 셈** — 새 계정을 여러 개 만들어 멀쩡한 글을 숨기는 것 방지
- 참고: Habitica(`HabitRPG/habitica`)의 신고 2건 숨김·새 계정 신고 미반영·혐오 표현 시 채팅 정지 방식 (코드는 가져오지 않고 방식만 참고)
- 남은 일: 운영자 확인 화면, 운영자 신고는 바로 숨김, 문제 사용자 글을 처음부터 숨김으로 저장(shadow mute), 신고 처리 기한(24시간 안) 운영 방식, 앱 안 문의 연락처

### 위기 표현 확인

일기와 글·목록 미션에 쓴 글을 확인한다. **진단이 아니라 도움을 건네기 위한 장치**이고, 사용자에게는 어떤 단어가 걸렸는지 알리지 않는다. 글 내용은 저장하지 않고 위험도·분류만 기록한다.

| 위험도 | 예 | 사용자에게 | 응답 `care` |
|---|---|---|---|
| high | 직접적인 죽음·자해 언급 ("죽고 싶어", "사라지고 싶어") | 상담 안내 109 · 1577-0199 | `{"type": "support", "message", "contacts"}` |
| medium | 절망·무가치감·자기비하·강한 고립 ("쓸모없는 사람 같아") | 캐릭터 안부, 그날 홈 말풍선도 안부로 | `{"type": "check_in", "message"}` |
| low | 절대주의 단어 2개 이상, 수면·식욕 호소, 외로움 | 아무것도 안 보임 (기록만) | `null` |

- 띄어쓰기·문장부호는 무시하고 비교. "배고파 죽겠다", "끝내준다", "자살예방" 같은 표현은 제외 목록으로 거름
- 목록 출처: 자살 경고신호 언어적 신호(보건복지부·한국생명존중희망재단), 절대주의 단어(Al-Mosaiwi & Johnstone 2018), 외로움 표현 연구(Guntuku 외 2019) — 문구는 분류를 참고해 직접 작성
- 점검: `python scripts/import_kote.py`(KOTE 한국어 감정 댓글 5만 개, MIT → DB `kote_comments`) → `python scripts/check_crisis_lexicon.py`
  - 2026-10-06 결과: high가 행복·기쁨 댓글 0.02%, 절망·자기혐오 댓글 0.28%에서 걸림
