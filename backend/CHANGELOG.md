## 2026-10-06 — 사진첩

**브랜치** `backend-album`

- 사진첩 API: 내가 올린 사진을 날짜 최신순으로, 어떤 미션(예: "오늘 하늘 찍기")이나 일기에 올렸는지와 함께 보여 줌
  - 기간 필터(`from`·`to`), 페이지, 월별 개수(`/album/months`)
  - 사진 지우기: 일기에 붙어 있던 것도 떼고 파일도 지움. 이미 받은 미션 보상은 그대로
- 사진을 미션·일기에 쓰면 그 미션 id와 날짜를 사진에 기록 (예전 DB는 서버를 켤 때 칸이 자동 추가)
- 왜: 밖에 나가서 찍은 사진이 쌓이는 걸 다시 볼 수 있으면, 나간 기억이 남고 다음 외출 동기가 됨
- FRONTEND_GUIDE·README에 사진첩 API 추가
- **촬영 일시 확인**: 업로드할 때 사진 파일의 촬영 일시(EXIF)를 읽어 저장 (`taken_at`, iPhone HEIC 포함)
  - 사진 미션은 촬영 일시가 있으면 **오늘 찍은 사진만** 인정 → 안 되면 "오늘 찍은 사진으로 다시 올려 주세요."
  - **검증은 서버 안에서만**: 촬영 일시는 응답·사진첩에 내보내지 않고, 거절할 때도 날짜나 확인 방법을 알리지 않음 (사용자가 알 필요 없음)
  - 촬영 일시가 없는 사진(스크린샷·메신저 사진 등)은 일단 인정. 정상 사용자가 막히지 않게 하려는 것 (`ALLOW_PHOTO_WITHOUT_TAKEN_AT`로 바꿀 수 있음)
  - 일기 사진은 날짜 제한 없음
  - 한계: 촬영 일시는 조작할 수 있어서 완벽한 부정 방지는 아님
  - 라이브러리 추가: pillow, pillow-heif

## 2026-10-04 — 서버 기준으로 맞추기로 결정, 프론트 연결 가이드

**브랜치** `backend-demo-data` (커밋 전)

- **결정: 프론트와 다른 점은 백엔드(서버) 기준으로 맞춘다.** 코인·경험치·레벨·퀘스트·출석·상점은 서버가 계산하고, 프론트는 응답을 보여 주기만 함
  - 확인해 보니 프론트는 아직 서버를 전혀 호출하지 않음 (모두 localStorage·화면 안 데이터)
- `FRONTEND_GUIDE.md`: 프론트가 바꿀 것(퀘스트 목록·출석 보상·하루 펭귄 조건·시작 코인 등), 앱 시작 흐름, 화면별 API, 미션 `kind`별 표시 방법, 보상 응답, 상점 `status` 값
- 기본 캐릭터(꼬질 감자)는 처음 지급될 때 `new_items`에 넣지 않음 → "새 캐릭터!" 알림이 잘못 뜨지 않게

**남은 문제** 경험치 수치가 높은 문제(하루 810 XP)는 이제 서버 기준으로 정할 수 있음 → 결정 필요

## 2026-10-03 — 사용자 등록, 상점 서버 저장, 서울 날짜 · PR #11

**브랜치** `backend-users` · PR #11 (열림)

- 사용자: 가입(닉네임) · 닉네임 확인·변경 · **계정 삭제**(걸음·미션·코인·사진 파일·일기·방문·방명록·상점까지)
  - 닉네임 2~12자, 대소문자·띄어쓰기만 다른 이름은 중복 불가
  - 방문자·추천 방 목록에 닉네임 표시 (응답 모양이 `[id]` → `[{id, nickname}]`로 바뀜)
  - 왜: App Store는 계정을 만들면 앱 안에서 지울 수 있어야 함. Game Center는 iPhone 전용이라 우리 닉네임을 기본으로 하고 Game Center는 나중에 연결할 칸만 둠
- 상점: 캐릭터 6 · 의상 4를 프론트(`game.js`, `Shop.jsx`)와 같은 값으로 서버에 저장, 구매 시 레벨·코인·중복 확인, 장착 API
  - 무료 지급: 꼬질 감자(처음), 복숭아 토끼(LV.3), 하루 펭귄(하루 미션 완료) → 응답 `new_items`
  - 코인 사용은 장부에 마이너스 기록, 경험치는 그대로
  - 서버 시작 코인 0 (프론트 목업 540은 넣지 않음)
- 날짜를 안 주면 **서울 기준 오늘** (프론트가 서울 자정에 하루를 바꾸게 바뀜)
- 프론트가 캐릭터 이름을 바꿔서 맞춤 (복숭아 토끼·달빛 양·새잎 거북·하루 펭귄 모찌)
- 테스트 111개 통과

**남은 문제**
- 로그인 토큰 없음: `id`만 알면 누구나 그 사용자로 동작 → 출시 전 필수
- 프론트와 맞출 것: 출석 보상(프론트는 무작위), 하루 퀘스트 목록, 하루 펭귄 지급 조건 → 논의 중

## 2026-10-01 — 매일 고정 미션, 출석·레벨, 방문·방명록 미션 · PR #9

**브랜치** `backend-level` · PR #9 (머지됨)

- 오늘의 미션 = **매일 고정 6개** + 매일 바뀌는 3개
  - 고정: 출석 · 걸음 8,000보 · 지난주(최근 7일 평균)보다 많이 걷기 · 일기 · 친구 방 놀러 가기 · 방명록 남기기
  - 왜: 일기·방명록·걸음은 매일 하게 하고 싶다는 결정. "어제보다 많이 걷기"는 매일 바뀌는 쪽에 둠
- 레벨·XP·코인을 프론트 `game.js`에 맞춤: `LV = 1 + XP // 100`, 미션 100 XP · 30 코인, 일기 40 코인, 3개 완료 코인 보너스 없음
- 일기·방명록·방문은 그 화면에서 하면 미션 자동 완료. 방명록·방문은 **다른 사람 방**만 인정
- 방문 API(방문 기록·내 방 방문자·추천 방), 방명록에 작성자 id·날짜 저장
- 일기 미션은 추천 주제를 보여 주지만 다른 이야기도 인정 (매일 쓰게 하는 게 목적)
- README를 현재 구조 위주로 정리, 쓰지 않는 처음 계획은 "보류"로
- `AGENTS.md` 삭제 (팀원 에이전트용 작업 규칙 파일)

**문제** 하루에 다 하면 810 XP = 레벨 8개 → 수치 조정 필요

## 2026-10-01 — 미션·코인·FastAPI 서버·사진·일기 · PR #5 → #7

**브랜치** `backend-missions` · PR #5(→ `backend`), PR #7(`backend` → `main`) 머지됨

- **방향 전환**: 위험 점수로 단계를 판정하는 규칙 엔진 대신, **미션으로 행동을 유도**하는 단순한 구조
  - 예: 동네 맛집을 직접 찾아보게 하면 → 가 보고 싶은 곳이 생기고 → 나갈 계기가 됨
- 미션 목록을 `app/data/missions.json`으로 분리 (팀원도 파일만 고치면 됨)
  - 사진 올리기 · 찾아서 적기 · 걸음으로 **확인할 수 있는 미션만** 남김 (샤워·스트레칭처럼 확인 못 하는 것은 뺌)
- 어제 걸음이 1,000보 미만(또는 평소의 절반 미만)이면 "안 나간 날" → 밖으로 한 발 미션 위주
- 걸음 목표 8,000보, 어제보다·지난주보다 많이 걷기(기록이 있을 때만)
- FastAPI + SQLite 서버, 사진 업로드(본인이 올린 사진만 미션 인정)
- 일기 주제 50개(사용자마다 순서를 섞어 하루 하나), 일기 API

**참고** PR #5는 `backend` 브랜치로 머지돼서 `main`에 반영하려고 PR #7을 따로 올림
