## 2026-10-08 — Habitica 참고: 신고 기준 2건, 새 계정 신고 미반영, 혐오 표현 정지, 쉬어 가기

**브랜치** `backend-neighbor-level` · 참고: [HabitRPG/habitica](https://github.com/HabitRPG/habitica) (코드는 가져오지 않고 방식만)

- 신고 숨김 기준 3명 → **2명** (Habitica `CHAT_FLAG_LIMIT_FOR_HIDING = 2`)
- **가입 3일 미만 계정·가입 기록 없는 id의 신고는 숨김 횟수에 안 셈** (`reports.counted`). 신고한 본인에게는 그대로 숨김 (Habitica `USER_AGE_FOR_FLAGGING = 3`)
- 욕설과 **혐오 표현(slurs) 목록 분리**: 혐오 표현을 방명록에 쓰면 글을 막고 **방명록 쓰기 7일 정지** (`guestbook_bans`). 일반 욕설은 글만 막음 (Habitica: 혐오 표현 시 채팅 정지)
- **쉬어 가기** `POST·GET·DELETE /users/{id}/rest` (최대 30일): 그 기간은 오래 쉰 날로 치지 않아 14일 경험치 초기화가 안 됨. 돌아오면 "푹 쉬었어? 다시 와 줘서 반가워!" (Habitica "여관에서 쉬기")
- 14일 이상 쉬다 온 날 문구를 "오랜만이야! 다시 와 줘서 정말 반가워."로 줄임
- `POST /reports`에 `?date=` (시연용) 추가, 응답에 `counted`
- 테스트 4개 추가·신고 테스트 갱신 (전체 182개 통과)

## 2026-10-08 — 신고·차단·필터, 오래 쉬다 돌아온 사용자, 일기 내보내기, 외출 미션 코인 ↑

**브랜치** `backend-neighbor-level`

**신고·차단·필터** (App Store 심사 1.2 — 사용자끼리 글을 남기는 앱은 필수)
- 필터 `app/moderation.py` + `app/data/profanity.json`: 방명록 글·보이는 이름·닉네임의 욕설·비하·성적 표현을 막음. 띄어쓰기·숫자 끼워 넣기도 잡고, 일상 표현과 겹치는 말(꺼져·졸라·뒤져, 시발점)은 뺌
- 차단 `POST/DELETE/GET /users/{id}/blocks`: 서로의 추천·방문·방명록·방문자 목록에서 사라짐 (방문·방명록 403)
- 신고 `POST /reports` (방명록 글·사람): 신고한 사람에게 바로 숨김, 서로 다른 3명이면 모두에게 숨김, `block: true`로 차단도 함께
- 방명록 글 지우기 `DELETE /users/{id}/guestbook/{entry_id}?by=` (방 주인·쓴 사람)
- DB: `blocks`, `reports` 표 (계정 삭제 시 함께 삭제)

**오래 쉬었다 돌아온 사용자** (2023 실태조사: 벗어나려 한 청년의 45.6%가 다시 고립)
- 3일 이상 쉬면 홈 `welcome_back` + 말풍선 "다시 와 줘서 반가워!"
- 14일 이상 쉬면 **지금 레벨의 처음부터** (레벨 안 경험치만 0, 레벨·코인·아이템 유지). 장부 `comeback_reset`, 하루 한 번

**일기 내보내기** `GET /users/{id}/diary/export?from=&to=` → .txt (날짜·기분·주제·글·사진 장수). 기관 연동 없이 사용자가 직접 보관·공유

**밖에 나가는 미션 코인 30 → 50** (`outdoor: true`, 걸음 미션 포함). 경험치는 그대로 100

- 테스트 `tests/test_moderation.py` 11개 추가 (전체 178개 통과)

## 2026-10-08 — 주간 미션: 이번 주 자연 속 산책 2번

**브랜치** `backend-neighbor-level`

## 2026-10-08 — '지난주보다 많이 걷기'를 +1,000보로, 어제 8,000보 이상이면 빼기

**브랜치** `backend-neighbor-level`

- 목표: 지난 7일 하루 평균을 넘는 다음 100보 → **평균 + 1,000보** (100보 단위 올림). 예: 평균 2,500보 → 3,500보
- **어제 8,000보 이상 걸었으면 이 미션은 그날 나오지 않음** (권장 걸음을 이미 채우는 사람에게 목표를 계속 올리지 않게). 그날 매일 고정 미션은 5개
- 미션 이름 "지난주보다 1,000보 더 걷기", 설명에 +1,000보 표시
- 근거: 하루 1,000보 늘 때마다 우울 위험 9%↓ (Bizzozero-Peroni 2024, APP_INTRO 근거 섹션)
- 테스트: 목표 계산, 어제 7,999보/8,000보 경계, 기존 테스트 숫자 갱신

## 2026-10-08 — 이웃 추천: 나와 비슷한 레벨부터

**브랜치** `backend-neighbor-level`

- `GET /rooms/recommended`가 최근 7일 안에 앱을 쓴 사람 중 **내 레벨과 차이가 작은 순**으로 추천 (같은 차이면 최근에 활동한 사람 먼저)
- 응답에 `my_level`, 각 방의 `level`·`level_diff`(이웃 − 나)·`similar`(차이 2 이내) 추가 → 화면에서 "나와 비슷한 레벨" 표시 가능
- 비슷한 레벨이 부족하면 그다음으로 가까운 레벨로 채움 (목록이 비지 않게)
- 왜: 비슷한 단계의 사람끼리 만나면 부담이 적고, 레벨 차이가 크면 비교·위축될 수 있음
- 응답 모양이 `{rooms: [{id, nickname}]}` → `{my_level, rooms: [{id, nickname, level, level_diff, similar}]}`로 바뀜 (기존 칸은 그대로라 호환)

## 2026-10-06 — 레벨 곡선: 처음엔 빨리, 갈수록 천천히

- 다음 레벨까지 필요한 XP = 100 + 150 × (지금 레벨 − 1) → 100, 250, 400, 550 … (전에는 프론트처럼 레벨마다 100 고정)
- 누적: LV.3 350 · LV.5 1,300 · LV.8 3,850 · LV.12 9,350. 하루 400 XP(미션 4개 정도)면 LV.12까지 약 24일, 전부 하면(810 XP) 약 12일
- 왜: 처음 며칠은 금방 올라 성취감을 주고, 이후엔 한 레벨에 며칠씩 걸려 오래 이어 가게. 전에는 시연 데이터 21일에 LV.98이 나오던 문제도 해결
- 상품 해금 레벨(LV.3·5·8·12)은 그대로. 프론트는 서버 `level` 값을 그대로 표시하면 됨 (FRONTEND_GUIDE 반영)
- 시연 데이터(21일치) 다시 생성: 주인공 LV.98 → **LV.12** (코인 3,270은 여전히 많음 → 미션 코인 수치는 따로 검토)

**회의 제안 (10/6)**
- 퀘스트 난이도를 점점 높이기 (예: 방명록 → 감사 답하기 → 관심사 대화 → 취미 모임 정기 참여) → 분야별 단계 사다리로 설계 검토 중
- 처음 설문(연령대·생활·사회적 상황) → **보류**

## 2026-10-06 — 위기 표현 확인, 관련 데이터 조사·DB 반영

**브랜치** `backend-decor` (집 꾸미기와 같은 브랜치, 커밋 전)

- **데이터 조사**: 고립·우울·자살 관련 언어 연구와 공개 데이터를 찾아 DB에 넣을 수 있는지 확인
  - 바로 사용: 자살 경고신호 언어적 신호(보건복지부·한국생명존중희망재단), KOTE(MIT), 절대주의 단어(Al-Mosaiwi & Johnstone 2018), 109 상담전화
  - 신청 필요: AI Hub 웰니스 대화 스크립트(상담 기록 기반, 내국인·IRB·안심존 — 앱 DB에 그대로 넣기 어려움), AI Hub 감성 대화 말뭉치
  - 확인 필요: KNU 감성사전(라이선스 표기 없음), KCI 자살위험 탐지 연구 데이터(비공개로 보임)
- `app/data/crisis_lexicon.json`: 위기 표현 103개 (high 45 · medium 27 · low 31), 분류·출처 포함. 경고신호 분류를 참고해 문구는 직접 작성 → 서버 시작 때 DB `crisis_terms` 표로
- `app/crisis.py`: 일기·글·목록 미션의 글을 확인
  - high → 상담 안내(109·1577-0199), medium → 캐릭터 안부(그날 홈 말풍선도), low → 기록만
  - 사용자에게 걸린 단어를 알리지 않고, 글 내용은 저장하지 않음 (위험도·분류만 `crisis_signals`)
  - 관리자 확인 API (`ADMIN_TOKEN` 없으면 꺼짐)
- KOTE 5만 개를 DB `kote_comments`에 넣고 점검 스크립트로 잘못 걸리는 표현을 찾아 고침
  - "살 이유가 없다"(사다), "끝내준다"(최고다), "하나만 없으면", "~하지 않으면" 같은 표현 제외
  - 결과: high가 행복·기쁨 댓글 0.02%, 절망·자기혐오 댓글 0.28%
- 왜: 고립·우울 대상 앱이라 위험한 글에 반응하지 않으면 안 됨. 다만 진단처럼 보이지 않게, 꼭 필요할 때만 도움을 건넴

**결정** 위기 탐지는 당분간 **목록 일치 방식**으로 한다. AI로 문맥을 판단하는 방식은 더 생각해 보기로 함

**한계** 단어 목록 방식이라 문맥(남 이야기, 소설, 반어)을 모름. KOTE는 뉴스 댓글이라 일기 글과 다름

**기타** 루트에 앱 소개 문서 `APP_INTRO.md` 추가 (목적, 기능성 앱 설명, 주요 기능, 사용자 경험·안전 원칙)

## 2026-10-06 — 사진첩

**브랜치** `backend-album`

- 사진첩 API: 내가 올린 사진을 날짜 최신순으로, 어떤 미션(예: "오늘 하늘 찍기")이나 일기에 올렸는지와 함께 보여 줌
  - 기간 필터(`from`·`to`), 페이지, 월별 개수(`/album/months`)
  - 사진 지우기: 일기에 붙어 있던 것도 떼고 파일도 지움. 이미 받은 미션 보상은 그대로
- 사진을 미션·일기에 쓰면 그 미션 id와 날짜를 사진에 기록 (예전 DB는 서버를 켤 때 칸이 자동 추가)
- 왜: 밖에 나가서 찍은 사진이 쌓이는 걸 다시 볼 수 있으면, 나간 기억이 남고 다음 외출 동기가 됨
- FRONTEND_GUIDE·README에 사진첩 API 추가
- **촬영 일시 확인**: 업로드할 때 사진 파일의 촬영 일시(EXIF)를 읽어 저장 (`taken_at`, iPhone HEIC 포함)
  - 사진 미션은 촬영 일시가 있으면 **오늘 찍은 사진만** 인정 → 안 되면 "오늘 찍은 사진으로 다시 올려 주세요."
  - **검증은 서버 안에서만**: 촬영 일시는 응답·사진첩에 내보내지 않고, 거절할 때도 날짜나 확인 방법을 알리지 않음 (사용자가 알 필요 없음)
