README 23.2 "지역 단위 분석 아이디어"를 실제 데이터로 구현한 1차 결과. 재현: `analysis/01 → (05 카드 있으면) → 04 → 03 → 06` 순서로 실행. (`02`는 v0.1 단순 버전, 참고용)

| 항목 | 확인 결과 |

| 지표 | 계산 | README 연결 |

| `flatness` | 24h 프로파일의 평탄도 (0 뾰족 ~ 1 평탄) | 23.2 "낮 피크가 없는 블록" |

## 3. 주요 발견

1. **지역 차이**: 춘천은 강남보다 야간 비율 높음(6.0% vs 4.7%), RA 낮음(0.76 vs 0.82), 주말/주중 비 >1(1.14 vs 0.78), 60+ 비중 높음(24% vs 18%). 강남은 출퇴근 유입형, 춘천은 거주·관광형.
2. **고령 비중 ↔ 유동 밀도 음의 상관 (r=−0.37)**, 고령 비중 ↔ 평탄도 양의 상관 (r=+0.47). 고령 블록일수록 낮에 피크가 없고 사람이 적다 — 논문의 "낮·밤 대비 낮음 ↔ 외로움" 논리가 지역 집계 수준에서도 방향이 같게 나옴.
3. **월별 추세는 평탄**: 6개월간 ±5% 이내. 12월 소폭 감소. 지역 전체로는 "급락"이 없으므로 급락 축은 블록 단위에서만 의미 있음.
4. **취약지수 상위 블록**: 강남은 남동부(개포·일원·수서 방향) 대단지 주거지에 집중. 춘천은 외곽 면 지역(셀 1,000개+, 60+ 비중 40~58%)이 상위 — 이는 농촌 고령화 지역이라 도심 취약지와 성격이 다름 → **도심/외곽 분리 평가 필요**.

## 4. 생활활동 취약지수 v0.2 (`output/block_vulnerability.csv`, `04_residential_stratify.py`)

1. **권역 분리**: 셀 50개 초과 블록 = 외곽 (춘천 면 지역 122, 강남 산지 37). 외곽은 셀당 유동이 도심의 1/10 이하라 도심과 같은 척도로 비교 불가 → 층(region×zone) 안에서만 순위.
2. **거주형 필터**: 층 내 야간/주간 유동 비율 상위 50% = 거주형. 업무·상업형은 "낮에 안 나감" 해석이 성립하지 않으므로 지수 산정에서 제외(`제외(업무상업형)`).
3. 층 내 백분위 가중합: flatness 0.30 + share_60GU 0.20 + (낮은) wkdy_per_cell 0.20 + 주중·주말 무차이 0.15 + (음의) trend 0.15 (+ 카드 결합 시 생활업종 소비 0.15, 합 1로 재정규화).
4. 등급: 층 내 상위 5% 우선 / 5~10% 주의 / 10~20% 관찰. 우선: 강남 도심 50·외곽 1, 춘천 도심 16·외곽 4.

## 4-1. 카드 결합 (`05_card_join.py`, 카드 파일 대기 중)

카드는 시군구×업종×연령×성별×일 집계라 블록과 직접 조인 불가. (지역, 연령대)별 생활업종(식당·카페 등) 결제 비중·추세를 만들고, 블록의 연령 구성으로 가중 평균해 `life_consumption_idx`로 내림. 더미 파일로 파이프라인 동작만 검증했고 실제 산출물은 없음.
**실행 전 할 일**: `MCT_RY_CD` 코드표 확인 → `LIFE_MCT_CODES`에 생활업종 코드 채우기, `SGG_TO_REGION`에 실제 시군구 코드 확인.

## 4-2. 행정향 주간 리포트 (`06_weekly_report.py`)

README 23.3의 3개 섹션(취약 블록 / 앱 사용자 개입단계 분포 / 복지 자원) 구조로 `output/report/주간리포트_<날짜>.md` 생성. 좌표는 UTM-K(EPSG:5179)→위경도 변환. 앱 사용자 단계는 `output/app_user_stage.csv`(BLOCK_CD, stage), 복지 자원은 `analysis/welfare_resources.csv`를 채우면 자동 반영.

> 가중치는 프로토타입 초기값. README 12.8과 같은 수준의 근거 등급이며 검증 대상.

## 5. 프로젝트에 활용하는 방법

- **행정향 에이전트 입력** (README 23.3): `block_vulnerability.csv`의 우선/주의 블록 목록 + 좌표 → 담당자 주간 리포트의 "생활활동 취약 블록" 섹션.
- **개인 데이터와 연결** (README 12.9): 앱 사용자 거주 블록의 `vuln_grade`를 **지역 맥락 변수**로만 사용. 개인 점수에 더하지 않고, 에이전트가 "이 지역엔 복지관이 가까움" 같은 자원 연결 선택에 활용.
- **카드 데이터 결합**: 같은 블록·연령대의 식당·카페 결제(`MCT_RY_CD`)가 낮으면 취약지수 보강 (아직 카드 데이터 없음).

## 6. 한계

- 블록 단위 집계라 개인 판단 불가 (README 12.9). 유동인구는 거주자+방문자 합산이라 거주형 필터를 넣어도 "거주자가 안 나감"과 "방문자가 없음"이 완전히 분리되지 않음.
- 월 단위라 주 단위 변화(개인 규칙의 2주 지속 등)는 볼 수 없음.
- 외곽 블록은 v0.2에서 층을 분리했지만 여전히 도심 순위와 직접 비교하면 안 됨.
